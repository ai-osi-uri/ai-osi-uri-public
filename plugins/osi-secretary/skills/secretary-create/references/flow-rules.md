# 業務定義の書き方（資料から案を作るとき）

秘書の管理画面の「資料から案を作る」と同じ決まり。秘書（LINE の AI 秘書）がその通りに動けるよう、業務の流れを1行ずつの決まりにする。

## 1行の形
- **no**：英字1〜2文字＋数字（業務ごとに頭文字を変える。例 依頼=T、営業=S、契約=C、請求=B、支払=P、採用=H、会議=M）。
  **R1・R2 は使わない**（ひな形が最初から入れる「議事録から ToDo」の行で使う）。
- **process**：業務の名前（短く。例「請求」「採用」）
- **trigger**：きっかけ（何が起きたら。例「毎月の締め日」「請求書を受け取った」）
- **task**：やること（誰が何をするか。1〜2文。人の名前は呼び名で）
- **owner**：担当（呼び名。複数なら「、」でつなぐ。秘書がやるなら「秘書」）
- **record_to**：記録先（台帳・書類の名前。フォルダの場所は書かない）
- **done_when**：終わりの条件（何ができたら終わりか）

## 守ること
- 資料に書いてあること・はっきり読み取れることだけを書く。分からない担当は「（担当を決める）」とし、推測で人を当てない。
- 1つの業務は3〜8行。全体で多くて60行。
- 社内の依頼（頼む→担当に届く→進んだら報告→頼んだ人に届く）は必ず入れる（T1〜T3。`standard-flows.md` の 5）。
- 社外に送るもの・お金・承認は、必ず人の確認を入れる行にする。
- 最後に、資料から分かったこと・分からなかったこと（担当が決まっていない業務、資料どうしの食い違いなど）を3〜6行でまとめる。

## 読み方のこつ
- 運用ルール・マニュアルの「列の持ち主」「誰が何をする」「いつ」の表は、そのまま行になることが多い。
- メールは宛先・件名・日付だけで、「毎月末に◯◯さんがお客さまに請求書を送る」「◯◯さんが定例の招待を出す」のような定期の流れが分かる。本文は読まない。
- 資料に書いていない仕事は出てこない。足りない業務は本人に聞くか、標準の形（`standard-flows.md`）を「標準の形」と明記して出す。
