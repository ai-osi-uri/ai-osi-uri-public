# secretary-create（秘書をつくる）

会社ごとに AI 秘書を1つ作る。**秘書はすべて使う人自身のアカウントに置く**：LINE 公式アカウント（窓口）、Supabase（秘書の置き場）、
Vercel（管理画面）、Claude の API キー（秘書が考えるのに使う）。提供元（このスキルを配った会社）の側には置かない・中を見ない・管理しない。
道具は **AI OSI URI Deploy 拡張**（1.37.0 以降。自分の Supabase と Vercel の鍵を入れたもの）を使う。秘書の中身（関数・データの形・管理画面）は、
Deploy 拡張に入っている「ひな形」から入る。

## 守ること

- **鍵は本人が入れる。Claude は値を見ない。**
  - Supabase・Vercel の鍵は Deploy 拡張の設定に本人が入れる（初回セットアップのスキル `osi-deploy:setup-deploy-environment`）。
  - LINE のチャネルシークレット／チャネルアクセストークン（長期）と Claude（Anthropic）の API キーは、管理画面の **設定用リンク（setup_url）** に本人が貼る。
  - チャットに貼られたら使わず、「チャットに鍵が残ったので、発行元で作り直してから、設定用リンクに貼ってください」と伝える。
- **外に見える操作・費用が出る操作の前は、完成形を見せて OK をもらう。** LINE 公式アカウントの作成、置き場の作成、管理画面の公開、業務定義の書き込み。
  費用は各サービス（LINE・Supabase・Vercel・Anthropic）から本人の会社に請求されることだけ伝え、金額は言わない（プランによるため）。
- **アカウントの作成・ログイン・利用規約への同意は本人が行う。** Claude は画面を開いて場所を案内するだけ。
- **資料は読むだけ。** 業務定義の表だけを秘書に書く。資料の本文を秘書の置き場や他の場所に保存・送信しない。
  メールは **宛先・差出人・件名・日付だけ** を見る（本文・抜粋は読まない・使わない）。
- 会社名・代表者名・住所は **公式サイトで一字ずつ確認** し、ウェブの表記を正とする。確認できない肩書は書かない。
- 普通の言葉で話す。カタカナ語・略語を避ける。1回の質問は多くて3つ。
- 報告は「何を頼まれたか → どう進めたか → 結果 → 決めてほしいこと」の順。

## 道具（AI OSI URI Deploy 拡張）

| 段階 | 道具 |
|---|---|
| 鍵の確認 | `health_check`（Supabase と Vercel が使えるか）。足りなければ `osi-deploy:setup-deploy-environment` に渡して、終わったらここへ戻る。URL で繋いだコネクタ（`health_check` がテキストで返る）なら、`uses` の `[secretary]` 行を見て、`✕` なら `osi-deploy:own-keys-setup`（やりたいこと `secretary`）に渡す。お試し（マネージド）では秘書は作れない |
| 置き場の作成 | `supabase_list_organizations` → `supabase_create_project` → `supabase_list_projects`（ACTIVE_HEALTHY を待つ） |
| 秘書を入れる | `secretary_install`（データの形・初期設定・関数・定時処理） |
| 管理画面を出す | `secretary_admin_deploy`（使う人の Vercel に管理画面を出し、秘書のリンクをそこへ向ける。`admin_url`・`setup_url` を返す） |
| 業務定義を書く | `secretary_write_flow`（版・変更の記録つき。同じ No は上書き） |
| 様子を見る | `secretary_status`（メンバー数・LINE の鍵・業務定義の版・ひな形の版・足りない関数） |
| 資料を読む | 繋がっているコネクタ（Google ドライブ・Gmail・Microsoft 365・Slack・Notion）と、会話に添付されたファイル |
| 画面の案内 | Claude in Chrome（LINE の画面を開いて場所を示す。操作は本人） |

## 流れ（6段階＋試運転）

最初にこの全体と「用意するもの」を1回だけ見せる（完成形の文面で）：

```
会社の AI 秘書を作ります。全部で6段階、1時間ほどです。途中でやめても続きから再開できます。
秘書は御社のアカウントの中に作ります（提供元の側には置きません）。

用意するもの（途中で一緒に作れます）
・LINE 公式アカウント（秘書の窓口）
・Supabase のアカウント（秘書の置き場）と Vercel のアカウント（管理画面）… AI OSI URI Deploy 拡張に鍵を入れておく
・Claude の API キー（Anthropic Console で作る。秘書が考えるのに使う）

【1/6 会社のこと】【2/6 LINE 公式アカウント】【3/6 秘書の置き場】【4/6 管理画面】【5/6 LINE と鍵をつなぐ】【6/6 業務定義（資料から）】→ 人を入れる・試運転
```

### 0. 鍵の確認（最初に1回）
- `health_check` で Supabase と Vercel が使えるかを見る。足りなければ「先に Deploy の初回セットアップをします」と伝え、
  `osi-deploy:setup-deploy-environment`（Supabase と Vercel の段だけでよい。GitHub は秘書には要らない）を進めてから、ここへ戻る。
- URL で繋いだコネクタ（`health_check` がテキストで返る）を使っている人は、`uses` の `[secretary]` 行を見る。`✕` なら
  `osi-deploy:own-keys-setup`（やりたいこと `secretary`）で鍵を登録して「自分の鍵を使う」に切り替えてから、ここへ戻る。お試し（マネージド）では秘書は作れない。
- Deploy 拡張が 1.37.0 より古ければ、ツールポータルから入れ直してもらう（1.36.0 より前には `secretary_admin_deploy` が無く、1.37.0 より前の管理画面には会社のドライブ・Gmail・OneDrive を「つなぐ」口が無い）。

### 1/6 会社のこと
- 会社の正式名称（公式サイトで確認して、住所・代表者も拾う）、秘書を運営する人（管理者）の呼び名と会社メール、
  秘書を使うメンバーの呼び名（分かる範囲で。後から増やせる）、秘書の呼び名（既定「秘書」）。
- `company_profile` は「社名／代表者の肩書と氏名／住所」の形にする（例：`〇〇株式会社／代表取締役 山田 太郎／〒…`）。
- 会社の短い名前（英小文字。例 `acme`）を決める。置き場と管理画面の名前に使う（`acme-secretary`）。

### 2/6 LINE 公式アカウント
1. 聞く：`秘書の窓口になる LINE 公式アカウントを作ります。▶ 作る（画面を開いて一緒に進めます） ▶ もうある（秘書専用のもの）`
   既にある会社の公式アカウントをそのまま使うと、お客さま向けの配信と秘書が混ざるので、秘書専用に1つ作るのをすすめる。
2. Claude in Chrome で開き、本人に操作してもらう：
   - LINE 公式アカウントの作成：`https://entry.line.biz/start/jp/`（アカウント名は「<会社名> 秘書」など）
   - LINE Official Account Manager → 設定 → Messaging API → 「Messaging API を利用する」（プロバイダーは会社名で作る）
   - 同じ「設定」の「応答設定」で、応答メッセージを OFF、Webhook を ON
3. 鍵（チャネルシークレット・アクセストークン）はまだ取り出さない。5/6 で設定用リンクに直接貼る。

### 3/6 秘書の置き場（Supabase）
1. 完成形を見せて OK をもらう：
   `御社の Supabase（組織「<組織名>」）に「<短い名前>-secretary」という置き場を東京リージョンで作ります。Supabase の利用料は御社に請求されます。▶ 作る ／ ▶ あとで`
2. `supabase_create_project`（db_pass は強い乱数を作って渡す。本人にも見せない）→ 数分待ち、`supabase_list_projects` で `ACTIVE_HEALTHY` を確認する。
3. `secretary_install`（members に 1/6 の呼び名）。失敗したら `done`（済んだ手順）を見て、同じ道具をもう一度呼ぶ（既にあるものは作り直さない）。
4. **関数を入れるのに1〜2分かかり、道具の返事が先に切れることがある。** そのときは数分待って `secretary_status` を見る。
   `template_version` が入っていて `functions_missing: []` なら入れ終わっている。
5. `project_ref` を控えて本人にも伝える（再開に使う）。

### 4/6 管理画面（Vercel）
1. 完成形を見せて OK をもらう：`御社の Vercel に「<短い名前>-secretary」という管理画面を出します。▶ 出す ／ ▶ あとで`
2. `secretary_admin_deploy`（project_name は `<短い名前>-secretary`）。返ってきた `admin_url`（管理画面）と `setup_url`（設定用リンク・24時間・一回限り）を控える。
   以後、秘書から届くログイン用リンクも、この管理画面を指す。

### 5/6 LINE と鍵をつなぐ
1. `setup_url` を本人に開いてもらう。LINE Developers（`https://developers.line.biz/console/`）で、2/6 のチャネルの
   **チャネルシークレット**（チャネル基本設定）と **チャネルアクセストークン（長期）**（Messaging API 設定の一番下で「発行」）をコピーして貼ってもらう。
2. 同じ画面で **Claude の API キー** を求められる。Anthropic Console（`https://console.anthropic.com/`）の「API Keys」で作った鍵（`sk-ant-` で始まる）を貼ってもらう。
   まだ無ければ、Anthropic Console でアカウントを作り、支払い方法を登録してから鍵を作る（本人が行う）。
3. 「つなぐ」を押すと、Webhook の設定と疎通の確認まで自動で行い、「友だち追加」のボタンが出る。管理者に友だち追加して「残ってる？」と送ってもらい、返事が来ればつながっている。
4. 設定用リンクが切れたら `secretary_admin_deploy` をもう一度呼ぶか、`secretary_install` をもう一度呼ぶ（リンクだけ作り直る）。

### 6/6 業務定義（資料から作る）
1. 聞く：`業務定義（誰が・何をきっかけに・何をするか）を、御社の資料から作ります。どこを読みますか？（いくつでも）`
   `▶ Google ドライブ ▶ Gmail（宛先・件名だけ） ▶ OneDrive・SharePoint ▶ Slack ▶ Notion ▶ ファイルを添付する ▶ 資料なしで、話して決める`
   - 選ばれたもののコネクタが繋がっていなければ、Claude の「コネクタ」でつなぐよう案内する（繋がっているものだけで進めてもよい）。
   - **管理画面からつなぐ道もある**（Claude のコネクタが使えない・あとで管理画面だけで作り直したいとき）：管理画面（`admin_url`）の「業務定義」→「資料から業務定義をつくる」→「① 会社の道具をつなぐ」。
     枠の中の「鍵の取り方」に沿って、御社の Google Cloud（ドライブ・Gmail）／Microsoft Entra（OneDrive）で OAuth のクライアントを作り（リダイレクト URI は画面に出る）、
     クライアント ID・シークレット（OneDrive はテナント ID も）を**本人が画面に貼って**「鍵を保存」→「つなぐ」で許可する。鍵はチャットに貼らせない。
     つないだら「資料を選ぶ」で、ファイルを選ぶ／このフォルダの全部（50件まで）／AI におまかせで選ぶ、Gmail は「宛先・件名を入れる」（本文は読まない）。
     そのあと「③ 業務定義の案を作る」で、チェックした資料（または全部）から案ができ、「この案を業務定義に入れる」で入る（この場合 5. の `secretary_write_flow` は要らない）。
2. 読む（多くても 10〜15 本。足りなければ本人に聞く）：
   - ドライブ・OneDrive・Notion：「業務マニュアル」「運用ルール」「手順」「規程」「担当」「フロー」「台帳」などで探し、題名の一覧を見せて読むものを選んでもらう。
   - Gmail・Outlook：直近 1〜2 か月の送受信の **宛先・差出人・件名・日付だけ** から、「誰が誰に何を定期的に送っているか」（請求書・日程調整・契約書の送付・議事録など）を拾う。宣伝・お知らせは除く。
   - Slack：業務の依頼・承認・報告が流れているチャンネルを、本人に選んでもらってから読む。
3. 案を作る（`references/flow-rules.md` の書き方）。表（No・業務・きっかけ・やること・担当・記録先・終わりの条件）と、
   **分かったこと／分からなかったこと**（3〜6行。担当が決まっていない業務、資料どうしの食い違いなど）を見せる。
   - 資料に書いてあること・はっきり読み取れることだけを書く。分からない担当は「（担当を決める）」とし、推測で人を当てない。
   - 資料が少ない業務は `references/standard-flows.md` の標準の流れを「標準の形」と明記して足してよい。
   - 社内の依頼（T1〜T3）は必ず入れる。行番号に R1・R2 は使わない（ひな形の議事録の行）。
4. 会話で直す：「B3 の担当は佐藤さんに」「請求書を送る前に部長の確認を入れて」のような直しを受けて、表を出し直す。「（担当を決める）」が残っていたら、まとめて聞く。
5. 「これで書き込みます」と完成形を見せて OK をもらい、`secretary_write_flow`（version `v1.0`、note に「資料から作成（読んだ資料の題名）」）で書く。
6. 書いたあとは、LINE（直せる人が「B3 の担当を佐藤さんに直して」と送る）か、管理画面（`admin_url`）の「業務定義」でも直せることを伝える。

### 人を入れる
- 管理者：管理画面の「人と権限」で、呼び名とメールを入れて招待する。メール送信の鍵が無い秘書ではメールは届かないので、
  招待した人に友だち追加してもらい、呼び名を付ける → 管理画面のログインで呼び名を入れると LINE にリンクが届く、と伝える。
- メンバー：管理画面の「LINE」に出る友だち追加の QR コードか URL を社内に配る。友だち追加した人は「人と権限」に「呼び名なし」で出るので、呼び名を付ける。
- 業務定義を直せるのは「業務の決まりを直す」ができる人（はじめは管理者）。直せない人の頼みは変更案になって承認に回る。

### 試運転
1. `secretary_status` で、`line_key: true`・メンバーが1人以上・`functions_missing: []`・業務定義の行数を確認する。
2. 本人に LINE で「残ってる？」と送ってもらい、返事が来たら完成。来なければ `secretary_status` の `last_event` を見る（Webhook が届いているか）。応答設定（応答メッセージ OFF・Webhook ON）も確かめる。
3. 最後に報告：置き場（ref）、管理画面の URL、LINE アカウント名、業務定義の版と行数（と読んだ資料）、「（担当を決める）」が残っている行、これから2週間はずれを業務定義に直していくこと。

## 再開するとき
`project_ref` が分かれば `secretary_status` で今どこまで済んでいるかを見て、続きの段階から始める
（ref が分からなければ `supabase_list_projects` で `-secretary` の付く置き場を探す）。
- 関数がそろっていない → 3/6 の `secretary_install` から
- 管理画面がまだ（秘書の ADMIN_URL が共通の置き場のまま）→ 4/6
- `line_key: false` → 5/6（設定用リンクは `secretary_admin_deploy` をもう一度呼べば作り直る）
- 業務定義が `v1.0` 未満・行が少ない → 6/6
