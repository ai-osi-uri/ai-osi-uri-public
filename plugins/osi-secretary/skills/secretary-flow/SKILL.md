# secretary-flow（業務定義を資料から作り直す）

## 守ること
- 資料は読むだけ。秘書に書くのは業務定義の表だけ。メールは **宛先・差出人・件名・日付だけ** を見る（本文・抜粋は使わない）。
- 書き込む前に、今との違いを見せて OK をもらう。やめる行は消さない（止めるのは本人が LINE か管理画面で行う）。
- 誰が業務定義を直せるかは秘書が決めている（「業務の決まりを直す」を持つ人）。頼んだ人がその人でなければ、直せる人に確認してから書く。
- 普通の言葉で話す。1回の質問は多くて3つ。

## 流れ
1. 秘書の置き場（`project_ref`）を確かめる（分からなければ `supabase_list_projects` で `-secretary` の付く置き場）。`secretary_status` で今の業務定義の版と行数を見る。
2. 今の業務定義を読む：`supabase_execute_sql` で
   `select no, process, trigger, task, owner, record_to, done_when, mark from public.flow_steps order by sort`（読むだけ）。
3. 資料を選んで読む（secretary-create の 6/6 と同じ。`../secretary-create/references/flow-rules.md` の書き方）。
4. 案を作る：今の業務定義を土台に、資料から分かったことで **足す行・変わる行・やめる行** を分けて表で見せ、分かったこと／分からなかったことを添える。
   - 今ある行の No は変えない。新しい業務は新しい頭文字（例 採用=H）。R1・R2 は使わない。
5. 会話で直す。OK が出たら、変わる行と足す行だけを `secretary_write_flow`（version は今の版の次。例 v1.0 → v2.0、kind「変更」、note に読んだ資料の題名）で書く。
6. やめる行は、「LINE で『<No> をやめて』と送るか、管理画面の業務定義で止めてください」と伝える。
7. 最後に報告：版、足した行・変えた行の数、残っている「（担当を決める）」、やめる行の一覧。

## 管理画面だけで作り直す道
Claude のコネクタが無くても、管理画面の「業務定義」→「資料から業務定義をつくる」で作り直せる（秘書のひな形 2.2.0 以降）。
「① 会社の道具をつなぐ」で御社の Google ドライブ・Gmail・OneDrive をつなぎ（鍵の取り方は画面に出る。鍵は本人が画面に貼る）、
「資料を選ぶ」でファイルを選ぶ／フォルダの全部／AI におまかせ、Gmail は宛先・件名・日付だけを入れる。
「③」でチェックした資料（または全部）から案を作り、見て「この案を業務定義に入れる」。古い秘書なら secretary-care で最新にしてから案内する。
