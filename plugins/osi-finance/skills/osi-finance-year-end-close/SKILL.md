# 決算整理と決算書一式（osi-finance-year-end-close）

> **組織固有値はプロファイルから読む。** 会計期間・資本金・株主構成・青色申告の有無・消費税の計算方法
> （原則／簡易／2割特例）・中間納付の有無は `osi-profile.md` と `{{paths.finance}}/osi-finance-settings.md` を正とする。
> 手順と判断の正本は `references/close-rules.md`。

## なぜ順番が大事か

決算整理は、前の仕訳の結果を次の仕訳が使う。たとえば消費税の精算は全部の取引の税区分が確定してから、
法人税等は消費税の精算後の利益から計算する。順番を崩すと、あとから直すたびに税金の計算をやり直すことになる。
このスキルは順番を固定し、各段で残高の説明表（`osi-finance-balance-schedule`）が合ってから次へ進む。

## 前提（どれかが欠けたら止まる）

1. 期末月の月次の締め（`osi-finance-monthly`）が終わっている。
2. 期ズレの期末組替え（`osi-finance-accrual` §6）と固定資産の期末3点（`osi-finance-fixed-assets`）が済んでいる。
3. 消費税区分のチェック（`osi-finance-tax-class-check`）で、要確認が残っていない。
4. 残高の説明表で差額が0。

## 手順

```
0. 前提の4点を確かめる。欠けていれば、何が欠けているかを出して止まる
1. 仮勘定の整理        … close-rules §1（仮払金・仮受金・諸口・新株式申込証拠金を0にする）
2. 利息の見越し        … close-rules §2（貸付金の未収利息・借入金の未払利息）
3. 税務調整の候補を出す … osi-finance-tax-adjust を呼び、税理士に渡す論点を一覧にする（仕訳はしない）
4. 消費税の精算        … close-rules §3（税額は申告ソフト／税理士の計算結果を受け取る）
5. 法人税等の計上      … close-rules §4（税額は申告ソフト／税理士の計算結果を受け取る）
6. 残高の説明表を期末の形で出す（osi-finance-balance-schedule §10）
7. 決算書一式を出す    … close-rules §5（BS・PL・株主資本等変動計算書はMF、個別注記表は本スキルで作る）
8. 受け渡し            … close-rules §6 の一覧と期限をまとめて、税理士・代表者に渡す
```

各段の仕訳は「案 → 人の承認 → 登録 → 残高の説明表で確認」で進める。AUTO_POST_ROUTINE が on でも、
本スキルの仕訳は自動登録しない（どれも判断が要る）。

## 出力

`{{paths.ledger}}/決算/{期末年月}/` に次を置く（期ごとに1フォルダ。月次では何も作らない）。

- 決算書（BS・PL・株主資本等変動計算書）の PDF（MFから出力）
- 個別注記表（docx）
- 残高の説明表（勘定科目内訳明細書の元）xlsx
- 決算整理の仕訳一覧と、各仕訳の根拠（どの資料のどの数字か）
- 税務調整の候補一覧（`osi-finance-tax-adjust` の出力）
- 受け渡しの一覧（何を・誰に・いつまでに）

## 摘要キー

| 区分 | キー |
|---|---|
| 仮勘定の整理 | `YEC-仮 {科目} {期末}` |
| 資本金への振替 | `YEC-資本 {払込日}` |
| 利息の見越し | `YEC-利息 {相手} {期末}` |
| 消費税の精算 | `YEC-消費税 {期末}` |
| 法人税等 | `YEC-法人税等 {期末}` |

登録前に同じキーの仕訳が無いかを `getJournals` で確かめる（二重計上を防ぐ）。

## 他スキルとの分担

- 税額の計算・申告書（別表・消費税申告書）の作成・電子申告は対象外。税理士か申告ソフトが行い、本スキルは結果の数字で仕訳を作る。
- 株主総会での決算の承認、増資の変更登記は会社の手続き。本スキルは期限と必要書類を知らせるだけ。

## 注意

- 法人税の申告は、株主総会で承認された決算にもとづいて行う（確定した決算）。承認前の決算書で申告しない。
- 決算日を過ぎてからの仕訳は、日付を期末日にする。翌期の日付で入れない。
- 税額を推測で入れない。受け取った計算結果の出どころ（ファイル名・作成者・日付）を摘要に書く。
