# 固定資産の判定と償却（osi-finance-fixed-assets）

> **組織固有値はプロファイルから読む。** 会計期間・青色申告の承認の有無・資本金の額・従業員数・
> 資産の所在地（償却資産申告の提出先）は `osi-profile.md` と `{{paths.finance}}/osi-finance-settings.md` を正とする。
> 判断ルールの正本は `references/asset-rules.md`。金額基準と期限は税制改正で変わるので、同ファイルの
> 「最終確認日」から1年以上たっていたら国税庁のページで確かめ直してから使う。

## なぜ毎月やるのか

資産か経費かは、買った月に判断するのが一番楽で正確（請求書・用途・台数がまだ手元にある）。
期末にまとめると「これは何だったか」を探す作業になり、少額特例の年300万円枠や償却資産申告の対象の
集計もやり直しになる。毎月拾っておけば、期末は一覧を確かめるだけで済む。

## 入力（新しい台帳は作らない）

| 見るもの | どこ | 使い方 |
|---|---|---|
| 当月の仕訳（費用科目・資産科目） | MF（`getJournals` を科目IDで） | 1件10万円以上の支出を拾う |
| 固定資産・繰延資産の科目の仕訳 | MF | 資産タグ（下記）と残高 |
| 発注契約 | 請求管理台帳の契約マスタ（方向=発注） | 外注開発が自社用システムかどうかの手がかり |
| 会社の前提 | プロファイル・settings | 青色申告か、資本金1億円以下か、従業員数 |

固定資産台帳は **資産を計上した仕訳の摘要に付ける資産タグ**で持つ（別の一覧を作らない）:

```
[資産 工具器具備品 取得2026-06-19 供用2026-06-19 税抜113236×6 耐用4 少額特例 所在=本社]
```

タグの無い既存の資産は、摘要と証憑から中身を読み取って案を出し、人が確認したら `putJournals` で
摘要の末尾に追記する（1回だけ）。

## 確定する範囲と確認する範囲

判断は人が1回だけ確認し、決まったことの繰り返しはAIが確定する。設定 `AUTO_POST_ROUTINE`
（`{{paths.finance}}/osi-finance-settings.md`）が `on` のときだけ、下の「定型」を人の承認なしに登録する（`off` なら全部を確認に回す）。

| 区分 | 中身 | 扱い |
|---|---|---|
| 定型 | 資産タグのある資産の毎月の償却（通常の減価償却・一括償却資産） | 登録して事後に報告 |
| 判断 | 新しく拾った10万円以上の支出の判定（経費か資産か・どの特例か）、資産タグの新規作成・変更、ソフトウェア・繰延資産の判定、期末の3点 | 案を出して人が承認してから登録 |

定型でも、摘要キーの既存仕訳がある・登録後の残高が資産タグと合わない・償却が終わっている、のどれかなら登録せず確認に回す。

## 手順

```
0. 対象事業者・対象月・会計期間を確認。期末月かも判定する
1. 前提の確認：青色申告の承認・資本金1億円以下・従業員数を settings から読む（無ければ要確認で止める）
2. 拾う：当月の費用科目と資産科目の仕訳から、1件（1台・1組）10万円以上のものを抜き出す
   - 金額は会社の経理方式で見る（税抜経理なら税抜）。付随費用（送料・設置費）は本体に足す
   - まとめ買いは1台ごとに判定する（6台で60万円でも1台10万円なら1台で見る）
3. 判定：references/asset-rules.md §1〜§4 を当てて「経費のまま」「資産にする（どの処理か）」「要確認」に振り分ける
4. 償却：資産タグのある資産について当月分の償却案を出す（§5）
5. 仕訳案を一覧で出す（日付・借方・貸方・金額・根拠・資産タグ）。要確認は「何が決まれば判定できるか」を1行で
6. 登録：定型は登録して事後報告、判断は人の承認後に登録（上の「確定する範囲」）。登録直後に getJournals と残高試算表で検算
7. 期末月だけ：§6 の3点（少額特例の枠、別表16の元、償却資産申告の一覧）をまとめる
```

## 摘要キー（重複防止）

| 区分 | キー |
|---|---|
| 資産への振替 | `FA-計上 {元仕訳No}` |
| 月次の償却 | `FA-償却 {元仕訳No} {対象月}` |
| 少額特例・一括償却の処理 | `FA-少額 {元仕訳No}` ／ `FA-一括 {元仕訳No} {対象月}` |

## 他スキルとの分担

- 前払費用・長期前払費用（礼金など）の取崩しは `osi-finance-accrual`。本スキルは「繰延資産になるか」の判定まで出し、
  繰延資産にしたものの月割償却は accrual の按分タグに渡す。
- 税額の計算・別表16そのものの作成・償却資産申告の提出は対象外（税理士・人）。本スキルはその元になる一覧まで。

## 注意

- 資産か経費か、どの特例を使うかは会社の選択なので、案と理由を出して人が決める（自動で登録するのは資産タグどおりの毎月の償却だけ）。
- 少額特例・一括償却は「申告書に明細を付ける」ことが条件。使ったものは必ず資産タグを付けて期末に拾えるようにする。
- 特例の適用条件（青色申告・中小企業者）は **取得した日と使い始めた日の状態**で判定する。増資で資本金が1億円を
  超える予定があるときは、その前後で判定が変わるので必ず要確認に出す。
- 事業者の取り違えは事故。対象事業者を毎回確認する。

## エラー処理

詳細は [`docs/エラー処理ガイド.md`](../../docs/エラー処理ガイド.md) を正本とする。

- 前提（青色申告・資本金・従業員数）が settings に無い → 判定を出さずに止め、何を確認すればよいかを報告する。
- 資産タグと残高が合わない → 償却を出さずに差額と候補原因を報告する。
- MFの登録結果が返らない → 同じ仕訳を再送しない。先に `getJournals` で登録有無を確かめる。
