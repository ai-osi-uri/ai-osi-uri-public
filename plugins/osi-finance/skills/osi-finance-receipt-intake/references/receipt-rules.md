# レシート取込 判断辞書（osi-finance-receipt-intake）

紙・写真・PDFのレシートを「証憑化 → 突合 → 仕分け（補助/仕訳）」する際の判断辞書。
※会計・税務・電帳法の最終判断は人（必要なら税理士）。本辞書は初期値・運用の目安。

> 判断ロジックは汎用。自社固有の実値（メンバー・人↔カード・加盟店→科目・少額特例の適用可否・
> 事務処理規程の有無）は `config/osi-finance-settings.md`「8. 経費（レシート）設定」を正本にする。

## 0. 大前提（必読）

- **カード（UPSIDER）払いレシートは仕訳しない。** カード連携が自動仕訳する。二重計上になる。本スキルは**証憑保存＋突合**のみ。
- **カード会社の利用明細だけでは仕入税額控除を受けられない。** 店舗レシート（適格請求書）の保存が必須（3万円未満でも必要）。
- **証憑の正本は Google Drive。** 電帳法スキャナ保存の要件を、ファイル名規則＋索引台帳＋事務処理規程で満たす（下記§4）。
- **確定（MF計上・振込・台帳確定）は人。** 本スキルは案・リストを出す。

## 1. 支払手段による2ストリーム振り分け

突合（`getJournals` のカード明細 × その人のカード）で対応明細の有無を見て振り分ける。

| 状況 | ストリーム | 動作 |
|---|---|---|
| 対応するカード利用明細あり | **A（カード）** | 証憑保存＋明細に紐付け。**仕訳しない** |
| 対応明細なし・現金払いの印字 | **B（現金）** | 証憑保存＋仕訳案 (借)経費/(貸)現金 |
| 対応明細なし・個人が立替 | **B（立替）** | 証憑保存＋精算案 (借)経費/(貸)未払金〔立替者〕。精算振込時 (借)未払金/(貸)普通預金 |
| 支払手段が読めない/曖昧 | 要確認 | 本人に支払手段を確認してから振り分け |

## 2. レシート頻出の勘定科目・税区分（目安）

> **科目名はローカル名で書いている。** 会計SaaSへ送る／突合するときは、勘定科目マスタの
> `MF科目名`（freee は `freee科目名`）列で変換する。とくに 消耗品費→備品・消耗品費、
> 交際費→接待交際費、業務委託費→業務委託料、支払報酬料→支払報酬 は名前が変わる。

| レシートの例 | 勘定科目 | 税区分 | 備考 |
|---|---|---|---|
| タクシー・電車・バス | 旅費交通費 | 課税仕入10% | |
| 飲食（少人数の打合せ） | 会議費 | 課税仕入10% | 食料品持ち帰りは軽減8%に注意 |
| 接待・会食 | 接待交際費 | 課税仕入10% | 参加者・目的をメモ |
| 文具・備品・消耗品 | 消耗品費（MF科目名: 備品・消耗品費） | 課税仕入10% | 10万円以上は資産計上の可能性→要確認 |
| 書籍・新聞・雑誌 | 新聞図書費 | **課税仕入8%（軽減）** | 定期購読の新聞は軽減 |
| 飲食料品（差入れ・手土産の食品） | 会議費/接待交際費 | **課税仕入8%（軽減）** | 酒類は10% |
| 切手・はがき | 通信費 | 非課税（購入時） | |
| 収入印紙 | 租税公課 | 非課税 | |
| 駐車場（時間貸し） | 旅費交通費 | 課税仕入10% | 月極は地代家賃 |
| 宅配・送料 | 荷造運賃/通信費 | 課税仕入10% | |

- 迷う科目は推測で確定せず「要確認」。自社の確定マッピングは `osi-finance-settings` を優先。

## 3. 軽減税率（8%）の扱い

- 飲食料品（酒類・外食を除く）と定期購読の新聞は **8%**。
- **1枚に 8%/10% 混在**（例：コンビニで食品＋日用品）→ 税区分ごとに**明細を分けて**記録する。
- レシートの税率別合計（「8%対象 ¥○○」「10%対象 ¥○○」）を読み取って転記する。

## 4. 電子帳簿保存法（スキャナ保存）を Drive で満たす

正本を Drive に置く運用で満たすべき要件と担保方法：

| 要件 | 担保方法（本スキル） |
|---|---|
| 解像度200dpi以上・カラー | 取込時に画質チェック。不足は「要再撮影」 |
| 検索要件（取引年月日・取引金額・取引先） | ファイル名 `YYYYMMDD_取引先_税込金額`＋経費レシート台帳の3列で検索可能に |
| 真実性の確保（タイムスタンプ相当） | **「訂正・削除の防止に関する事務処理規程」で代替**（国税庁サンプル様式）。原本フォルダは上書き・削除を禁じ、編集権限を制限。**要税理士確認** |
| 保存期間7年 | `レシート証憑/{YYYY年度}/{氏名}/` の年度別保存 |
| 帳簿との相互関連性（重要書類） | 台帳の「UPSIDER明細ID」「レシートID」で仕訳・明細と相互参照 |

- **規程が未整備の間は紙原本も併存保管**（スキャナ保存の適合が確定するまでの安全策）。

## 5. 少額特例（税込1万円未満）

- 一定規模以下の課税事業者（基準期間の課税売上高1億円以下 等）は、**税込1万円未満**の課税仕入れなら
  インボイスの保存が無くても**帳簿のみで仕入税額控除**が可能。
- 本スキルは `SMALL_AMOUNT_SPECIAL=あり` のとき、税込1万円未満を「少額特例フラグ」で立て、証憑添付漏れの優先度を下げる。
- **自社が特例の対象事業者か**は基準期間の課税売上高等で決まる。**要確認・税理士判断**。1万円以上は常に証憑必須。

## 6. インボイス区分

- 適格請求書（登録番号 T+13桁 の記載あり）→ 全額控除。
- 登録番号なし → 経過措置（当面80%控除）。台帳に「登録番号なし」を明記。
- 非課税・不課税の品目（切手・印紙等）は控除対象外なので登録番号の有無は影響しない。

## 7. 人単位フォルダ運用（申請者の特定）

- 入口 `レシート未処理/{氏名}/`・正本 `レシート証憑/{YYYY年度}/{氏名}/`。**パス＝申請者**。
- 突合は `PERSON_CARD_MAP`（人↔UPSIDERカード下4桁）でその人のカード明細に限定 → 他人との誤マッチ防止。
- 同じ人のフォルダにも「カード（保存のみ）」と「立替（要精算）」が混在する → 区別は§1の突合で判定。
- 立替分は台帳「申請者」「精算状態」で人ごとに集計し、精算（振込）案を作る。**振込実行は人**。

## 8. 重複防止・登録の作法

- 証憑命名 `YYYYMMDD_取引先_税込金額`。既出キー＝**取引先＋取引日＋税込金額**。一致はスキップ。
- ストリームB で MF に post する場合、摘要に `レシートID / 申請者 / 取引先 / 取引日` を入れ、`getJournals` で同キー重複を事前確認。
- **大量を一気に post しない。** 少数ずつ → 直後に getJournals／残高試算表で検算。
- 当会計年度外（前期）の取引日は post 不可 → 前期分は人に返す。

## 9. エッジケース

- カード計上日と店舗日のズレ → 突合は日付±2〜3日許容。
- レシートとカード明細で金額が違う（チップ・端数・分割）→「要確認」。
- 私的利用が混在 → 該当行を「対象外/事業主貸」候補にして人確認。
- 同店同日の複数レシート → 金額込みキーで別物判定。
- 感熱紙の退色 → 早期撮影を促す（運用メモ）。読めない退色分は「要再撮影/紙原本保管」。
