# osi-finance-bank-recon（銀行明細CSV ⇔ 台帳 突合）

> **組織固有値は `config/osi-finance-settings.md` を参照。** 発動条件: `INTEGRATIONS.BANK_RECON = ON`。
> OFF なら案内して止まる。MF の口座連携で消込する運用（AR_BANK_LINK_HANDLING）とは併用に注意
> （二重消込を防ぐため、どちらを正とするかを settings で確認する）。

## 役割と非役割

- やる：`04.連携データ/銀行/`（DRIVE_SYNC_BANK）の入出金明細CSVを読込 → 台帳と照合 →
  入金候補・支払実績・不明入出金を報告 → 突合結果・突合日時の書き戻し。
- やらない：**送金・振込**、**入金済/支払済への自動遷移**（候補提示まで。確定は人のボタン）、
  仕訳の投入（会計側は mf-sync / ar-sync / freee-sync の領分）。

## 機微値の扱い（厳守）

明細CSVには**口座番号・取引先の実名**が含まれる。CSVは Drive の `04.連携データ/銀行/` から動かさず、
チャット出力・レポートでは**口座番号を必ずマスク**する。コミット・スキル・設定例に実値を書かない。

## 手順

### 1. 前提確認とCSV読込
- フォルダに対象期間のCSVがあるか確認（無ければネットバンキングからのダウンロード手順を案内して止まる）。
- 銀行別の形式差（文字コード・列順・日付形式）は自動判別し、判別できなければヘッダを提示して人に確認。
- 明細の期間を突合対象期間として明示する。

### 2. 入金側（AR）の照合
- 月次請求スケジュールの `請求ステータス=請求済` の行と、明細の**入金**を照合する。
  一致条件：金額一致（±0円）＋入金日が支払期限の前後、振込名義と取引先名の類似。
- 一致した行は「**入金候補**」として `行（INV・取引先・金額）× 明細（日付・名義）` の対で提示する。
  **入金済への遷移・入金日/入金額の記入は人がコンソールのボタン等で行う**（本スキルは提示まで）。
- 合算入金（複数INVが1明細）・手数料差引（金額不一致）は自動で紐付けず「要確認」に分類する。

### 3. 出金側（AP）の照合
- 月次支払スケジュール・月次支払管理の未払系の行と、明細の**出金**を金額・支払先名で照合する。
- 一致した行は「支払実績あり」として提示する（支払済への遷移は人。mf-sync の Step 9 相当の反映を
  依頼された場合のみ、人の確認後に更新する）。

### 4. 台帳外の入出金
- どの台帳行とも一致しない入出金は「不明入出金」として一覧化する（非AR大型入金＝出資/借入等の
  可能性があるため、分類は人・会計側の feed-recon 系の判断に委ねる）。

### 5. 書き戻し（人レビュー後）
- 照合できた行の 突合結果（一致/未計上）・突合日時 を書き戻す。**列はヘッダ名で解決**する。
- **操作者トラッキング（v3）**：書き戻した各行の**更新者・更新日時（JST）**を記録する
  （正本: `assets/schema/data-layout.yaml` の `operator_tracking`）。
  **値はコネクタが自動で押すので `actor` を渡さないこと**（拡張の設定「操作者【必須】」→ env `OPERATOR`）。
  ログインユーザーのメールを自分で入れない——経路ごとに違う文字列が入り、操作者が割れる。

## 留意

- 送金しない。台帳の自動確定をしない（入金済/支払済は人のボタンのみ。差し戻しも人のみ）。
- 明細は一次情報だが、**紐付けの確定は人**（同額別取引の誤消込が最も危険）。
- 明細が古い場合は「再ダウンロードが必要」と明示する。

## エラー処理

詳細は **[`docs/エラー処理ガイド.md`](../../docs/エラー処理ガイド.md)** を正本とする。
- フォルダ未作成・CSVなし → 配置手順を案内して止まる。
- 形式判別不能 → 推測せずヘッダ提示のうえ人に確認。
- 金額不一致・合算・手数料差引 → 自動紐付けせず「要確認」。
