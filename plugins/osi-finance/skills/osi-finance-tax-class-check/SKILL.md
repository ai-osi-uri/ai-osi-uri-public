# 消費税区分のチェック（osi-finance-tax-class-check）

> **組織固有値はプロファイルから読む。** 消費税の計算方法（原則課税／簡易課税／2割特例）、
> インボイス発行事業者の登録の有無、少額特例（1万円未満）を使えるかは `osi-profile.md` と
> `{{paths.finance}}/osi-finance-settings.md`（SMALL_AMOUNT_SPECIAL など）を正とする。
> 判断ルールの正本は `references/tax-class-rules.md`。制度は改正が多いので、同ファイルの最終確認日から
> 半年以上たっていたら国税庁のページで確かめ直してから使う。

## なぜ毎月やるのか

税区分の誤りは、期末にまとめて見ると件数が多すぎて見落とす。しかも1件の誤りが消費税額にそのまま響く。
毎月、その月の仕訳だけを見れば件数が少なく、請求書もまだ手元にあるので、インボイスの有無もすぐ確かめられる。

## 手順

```
0. 対象事業者・対象月を確認（currentOffice）。プロファイルで計算方法と登録の有無を確かめる
1. 当月の仕訳を読む（getJournals）。税区分マスタ（getTaxes）と勘定科目（getAccounts）も読む
2. 判定：references/tax-class-rules.md の §1〜§5 を順に当てる
   §1 科目と税区分の組み合わせ（不課税・非課税になるはずの科目、課税になるはずの科目）
   §2 税率（軽減税率8%の対象か）
   §3 インボイス（相手の登録、登録番号の記載、経過措置の割合、少額特例）
   §4 国外の相手（国外事業者の登録、リバースチャージ）
   §5 売上側（課税売上・免税売上・非課税売上、立替金の混入）
3. 候補を出す：仕訳No・日付・相手・科目・今の税区分・正しいと思う税区分・理由・確かめる資料
4. 人の承認後に直す：putJournals で税区分を直し、摘要の末尾に [税区分修正 {理由} {確認日}] を足す
5. 報告：当月の件数（チェックした件数・候補の件数・直した件数）と、残った要確認
```

## 確定する範囲と確認する範囲

| 区分 | 中身 | 扱い |
|---|---|---|
| 判断 | すべての税区分の修正 | 候補を出して人が承認してから直す |

税区分は消費税額に直接響くので、AUTO_POST_ROUTINE が on でも自動では直さない。
一度決めた「相手→税区分」は settings §7 の支払先マッピングに足してもらい、翌月からは入口（mf-sync・payment-intake）で正しく入るようにする。

## 他スキルとの分担

- 税区分を最初に付けるのは入口のスキル（`osi-finance-mf-sync`・`osi-finance-payment-intake`・`osi-finance-journal`）。
  本スキルは後から確かめる役。同じ誤りが続くときは、入口のマッピングを直す提案をする。
- 消費税の精算仕訳は `osi-finance-year-end-close`。税額の計算・申告は対象外。

## 注意

- 相手が登録事業者かどうかは、国税庁の適格請求書発行事業者公表サイトで登録番号を確かめる。推測で「登録あり」にしない。
- 請求書が手元に無いものは、税区分を決めずに要確認にする。
