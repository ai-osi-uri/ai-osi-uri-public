# 月次経理 判断辞書

毎月の仕訳化で、科目・税区分・インボイス・源泉をブレなく判断するためのルール集。
※会計・税務の最終判断は人（必要なら税理士）。本辞書は初期値・運用の目安。

> **判断ロジック・税区分ルールは汎用**だが、**自社固有の「支払先→勘定科目」対応表は組織ごとに異なる。**
> 自組織の実値は `config/osi-finance-settings.md`（テンプレ：`config/osi-finance-settings.example.md`）の
> 「7. 判断辞書（科目マッピング）」に定義し、本辞書の下表は**雛形（`例:`）**として扱う。

下表は**書き方の例**。自組織の確定値は `osi-finance-settings` の「7-1. 支払先別 勘定科目マッピング」に置く。

## 3. 税区分ルール

- 国内の課税仕入 → **課税仕入10%**。
- **国外SaaS（電気通信利用役務）→ 暫定「対象外」**（控除しない安全側）。リバースチャージ／登録国外事業者
  の扱いで変わるため、**税理士の方針に従って確定**。確定後にMFで一括変更。
- 貸付金・借入返済・グループ内振替・カードの引き落とし → **対象外**（資金/財務取引）。

## 4. インボイス区分

- 法人の取引先 → **適格（全額控除）を初期値**（MF既定）。
- 個人事業主・小規模先 → 請求書の**登録番号（T＋13桁）を確認**。無ければ **80%控除（経過措置）**。
- **法人でも非適格はある。** 登録番号が請求書に書かれていても、**国税庁の適格請求書発行事業者公表サイトで
  未登録**なら非適格。「法人だから適格」で流さない。
- **同一取引先のインボイス区分は全期間で統一する。** 途中で判明した場合は**過去分もさかのぼって直す**。
  - 実例：ある外注先を5月分だけ「適格」、6月分から「非適格80%控除」で計上していて整合が取れていなかった。
    非適格と判明した時点で、5月分も 80%控除へ訂正した（`putJournals` で修正可）。
- 80%控除の計上：MFは `invoice_kind = INVOICE_KIND_UNQUALIFIED_80` を指定すると
  **控除可能な消費税額（本来税額×80%）を自動計算**し、**控除できない20%は費用本体に算入**される。
  費用行の `value` には税込総額をそのまま入れる（自分で按分計算しない）。

## 5. 源泉徴収

**判定軸は「外注か雇用か」ではない。** 業務委託・外注であっても源泉対象になる支払はある。見るのは次の2点だけ。

1. **支払先が個人か法人か** … 法人への支払いは原則**源泉なし**（例外は馬主である法人への競馬の賞金のみ）。
2. **支払内容が所得税法204条の列挙報酬か** … 個人への支払いでも、列挙されたものだけが対象。

対象になる主なもの（個人宛）：原稿料・講演料、**弁護士/司法書士/税理士/公認会計士/社会保険労務士等の士業報酬**、
プロスポーツ選手・モデル・芸能関係、ホステス等の報酬、契約金、広告宣伝の賞金。

- **システム開発・プログラミング・デザイン制作の外注は列挙報酬に該当しない → 源泉なし。**
- 税率は原則 **10.21%**（同一支払で100万円超の部分は20.42%）。
  **司法書士・土地家屋調査士・海事代理士のみ「(支払額 − 10,000円) × 10.21%」** と計算式が違う。
- 消費税が請求書で明確に区分されていれば、**税抜額に対して**源泉を計算してよい。
- 納付期限は**支払月の翌月10日**（納期特例の届出がある場合を除く）。
- **判定を誤って未徴収のまま満額を振り込んでも、納付義務は会社に残る。** 会社が立て替えて納付し、
  相手に精算してもらう流れになり、遅れると不納付加算税がつく。**個人宛の士業報酬は支払前に必ず判定する。**
- 迷う場合は**振込前に**請求書の発行元（法人か個人事業か）と源泉徴収税額の記載有無を確認する。最終判断は税理士。

> 実例：登記を依頼した司法書士（個人名義の口座へ振込）に、源泉徴収せず満額130,000円を振り込んでいた。
> 対象なら (130,000 − 10,000) × 10.21% = 12,252円 を天引きし翌月10日までに納付すべきだった。

## 6. カードの未払金構造（法人カード／例: UPSIDER）

- 利用時：(借) 各経費 /(貸) 未払金（カード負債）。
- 引き落とし時：(借) 未払金 /(貸) 普通預金（対象外）。
- 未払金がブリッジ。利用で積み上がり、引き落としで消える。月末の未払金＝未精算残。
- **銀行明細のカード引き落としは必ず未払金へ**。経費にすると二重計上。
  （カード会社の自動仕訳連携を使う場合、利用明細はカード連携側で経費化される前提。）

### 6-1. カード会社への出金は2種類ある（取り違え注意）

同じカード会社宛でも、**摘要の種別で意味がまったく違う**。金額だけで判断しない。

| 銀行明細の見え方 | 実体 | 仕訳 |
|---|---|---|
| **振込**（例:「振替 W21 カ)◯◯カード」）で、毎回同額のキリのいい金額 | **与信のための保証金・デポジット差入** | (借) **差入保証金** /(貸) 普通預金〔対象外〕 |
| **口座振替**（例:「コウザフリカエ DF.カ)◯◯カード」）で、端数のある変動額 | 当月のカード利用代金の決済 | (借) **未払金**〔カード〕/(貸) 普通預金〔対象外〕 |

- 実例：保証金の振込（300,000円×複数回）を「未払金の取崩」で計上していたため、
  **差入保証金という資産が1,000,000円分オンバランスされていなかった**。摘要に「保証金差入」と書いてあるのに
  科目が未払金、という状態は要注意サイン。過去分も見直す。
- 保証金は**返還される資産**。費用にも未払金取崩にもしない。

## 7. 重複防止・登録の作法（重要な教訓）

- 仕訳の摘要に必ずキー（請求書ID＝支払先ID＋対象月＋請求書番号、無ければ代替キー／カードは加盟店＋月）を入れる。
- 登録前に `getJournals` で同キーの仕訳が無いか確認（二重連携防止）。
- **大量を並列で一気にpostしない。** 結果が返らず二重登録が起きやすい。少数ずつ→**直後に
  getJournals／残高試算表で件数・金額を検算**してから次へ。
- **MCPに仕訳削除は無い。** 重複したらMF画面で該当番号を削除する。
- **当会計年度外（前期）の取引日はpostできない**（期間外エラー）。前期分は前会計年度で処理。

### 7-1. 支払の仕訳を切る前に「発生計上済みか」を必ず確認する（最頻出の二重計上）

受領請求書を受け取った時点で `(借)費用 /(貸)未払金` と**発生計上している場合**、
その後の支払は **`(借)未払金 /(貸)普通預金`（対象外）** でなければならない。
ここで費用をもう一度立てると、**費用が二重、未払金が消えずに残る**。

**手順（必須）**：支払明細を仕訳化する前に、`getJournals` を **未払金の勘定科目IDで絞って**取得し、
その支払先・対象月の**発生計上が存在するか**を確認する。

- 発生計上が**ある** → (借) 未払金〔補助科目=支払先〕/(貸) 普通預金。費用科目は使わない。
- 発生計上が**ない** → 支払時に費用計上（(借) 費用〔税区分〕/(貸) 普通預金）。

同じ会社の中でも運用が揃っていないことがある（発生計上する取引先と、支払時計上の取引先が混在する）。
**取引先ごとに毎回確認する。** 「先月こうだったから」で決めない。

> 実例：通信費と諸会費の2件を「費用/普通預金」で仕訳した直後、どちらも月末に
> 「費用/未払金」で発生計上済みだったことが判明し、二重計上になりかけた（`putJournals` で未払金取崩に訂正）。

## 8. 連携対象外（自動連携・突合の除外）

- 法人カード決済（例: UPSIDER）→ カード明細連携で経費化。台帳行は資金管理のみ。
- 貸付金／借入返済／グループ内振替 → 財務取引（対象外）。経費連携の対象にしない。

## 9. 連携明細（未仕訳）の棚卸し・MCP/画面の境界（重要な教訓）

連携明細（未仕訳）の整理そのものは **`osi-finance-feed-recon` スキル**＋`recon-rules.md` を正本にする。要点：

- **MFのAI自動推定科目は誤りが多い。** 特に**入金は何でも「売上高/売掛金」に寄せる**。**「一括登録」ボタンは押さない。**
- **連携明細の「対象外／登録」はMF画面専用（MCP不可）。仕訳の削除もMCP不可**（MF画面で番号指定）。
  - 画面：科目を直して「登録」（明細も同時にクリア）／重複は「一括対象外」／取消は「明細一覧」でステータス=対象外を絞り「対象外を解除」。
  - MCP：明細に紐づけない計上（借入・貸付・保証金・差額補正・売上計上・入金消込）は postJournals で振替伝票化。
- **MF画面の自動操作（ブラウザ自動化）は不安定**（クリックがフリーズ／拡張切断で未反映）。書込は**人の画面操作**か
  **MCP（明細非依存の仕訳）**を優先し、自動クリックは安定時のみ1操作ずつ検証。反映確認できないまま連打しない。
- **二重計上防止**：連携明細をMCPで振替伝票計上したら、**必ずその明細を画面で対象外**にする（しないと後で登録され二重）。
  既存の手入力バックフィル × 連携未仕訳の重複は、種別ごとに正本を決める（重複する未仕訳は対象外）。

## 10. 財務的入金の作法（売上にしない）

詳細は `osi-finance-feed-recon/references/recon-rules.md`。代表のみ：

- **顧客入金（AR）** → (借)普通預金/(貸)売掛金（売掛金が無ければ先に売上計上）。
- **借入金（融資実行）** → (借)普通預金/(貸)長期借入金（短/長は契約）。**入金額が額面と違う**ときは
  (借)普通預金＋(借)支払手数料 等 ＝差額 /(貸)長期借入金＝**額面**。既に入金額で計上済みなら差額の調整仕訳1本で額面に補正。
- **貸付金の回収** → (借)普通預金/(貸)短期貸付金。
- **保証金の差入** → (借)差入保証金/(貸)普通預金（対象外）。
- **出資（増資）** → 登記前は(貸)新株式申込証拠金、登記後に資本金/資本準備金へ振替。**司法書士/税理士確認**。売上高に絶対入れない。
- **借入金の返済（出金）** → (借)長期借入金（元金）＋(借)支払利息（利息）/(貸)普通預金〔対象外〕。
  - **元金と利息の内訳は償還予定表（返済予定明細）でしか分からない。** 明細の金額だけでは按分できない。
  - 予定表が手元に無いときの**暫定処理**：いったん**全額を借入金の返済**として計上し、予定表を入手後に
    各月分の利息を **`(借)支払利息 /(貸)長期借入金`** の振替伝票で1本ずつ入れて戻す。
    月次PLを正しくしたいので**年次まとめではなく毎月1本**を推奨。摘要に「暫定・予定表受領後に利息振替」と残す。
  - **返済額が途中で大きく変わったら要確認**（元金据置期間の終了、2本目の融資実行など）。
- **助成金・補助金の入金** → (貸)雑収入（不課税）。売上高にしない。
- **キャッシュバック・ポイント還元** → (貸)雑収入〔対象外〕。
- いずれも**非ARの大型入金は人（経営/出資者）確認**を挟む（MF推定「売上高/売掛金」は誤り）。

## 11. 不動産・社宅・賃貸まわりの科目（受領請求書で頻出）

社宅・オフィス賃貸の請求書は**1枚に複数科目が混在し、多くが非課税**。明細ごとに行を分けて起票する。
資産/費用の別・償却年数は税理士確認。

| 明細 | 勘定科目 | 税区分 | 備考 |
|---|---|---|---|
| 居住用賃料（社宅・住宅）／日割賃料 | 地代家賃（社宅は福利厚生費とする会社も） | **非課税仕入** | 居住用賃貸は消費税非課税。本人からの家賃徴収は別途（預り/雑収入等） |
| 事業用（オフィス・店舗）賃料 | 地代家賃 | 課税仕入10% | 事業用は課税 |
| 敷金・保証金（返還される分） | **差入保証金**（資産） | 対象外 | 返還前提は資産。敷引（返還されない部分）は費用化 |
| 礼金・更新料 | **20万円未満＝地代家賃（支払時損金）／20万円以上＝長期前払費用**（繰延資産・契約期間で償却、最長5年） | 居住用は非課税／事業用は課税仕入10% | 礼金258,750等は20万超→長期前払費用 |
| 保証会社保証料 | 保証期間1年以内＝支払手数料／1年超＝長期前払費用（期間按分） | 非課税（保証料は非課税） | |
| 仲介手数料 | 支払手数料 | 課税仕入10% | 宅建業者の仲介は課税 |
| 火災保険料 | 保険料（長期は長期前払費用で按分） | 非課税 | 保険料は非課税 |
| 前払い賃料（翌月以降分を先払い） | 地代家賃 | 上記に準ずる | 短期前払費用の特例で支払時損金可（継続適用前提） |

- **インボイス**：非課税取引は仕入税額控除の対象外なので、登録番号の有無は控除に影響しない（非課税にインボイス不要）。
  課税分（事業用賃料・仲介手数料等）は登録番号を確認。
- **源泉**：不動産賃料の支払いに源泉なし（個人への原稿・講演・士業報酬等とは別）。

## 12. 支払漏れを防ぐ運用（事故から得た教訓）

支払漏れは「うっかり」ではなく、**台帳が信用できなくなった結果**として起きる。連鎖はいつも同じ形をとる。

```
口座連携が止まる → 突合が止まる → 台帳のステータスが実態とズレる
→ 払ったものが「未払い」のまま並ぶ → 台帳が信用されなくなる
→ 支払予定日を見ても行動につながらない → 本当の未払いが埋もれて支払漏れ
```

塞ぐべき箇所は4つ。**どれか1つでも欠けると同じ事故が再発する。**

| 防ぐもの | 仕組み | 担当スキル |
|---|---|---|
| 連携停止に気づかない | 毎朝、口座ごとの最終取込日をチェックし3営業日途絶で警告 | `osi-finance-mf-sync` Step 0 |
| 台帳のステータスが腐る | 銀行明細で確認できた支払を台帳へ自動反映（手更新をやめる） | `osi-finance-mf-sync` Step 9 |
| 請求書の取りこぼし | キーワードに加え**送信元アドレス**で検出＋定期支払の未着検知 | `osi-finance-payment-detect` |
| 期日を見落とす | 期日3営業日以内／期限超過の未払いを毎朝、週次、月末前に提示 | `osi-finance-payment-detect` ＋ スケジュールタスク |

### 12-1. 定期支払は「請求書を待たずに先に予定を置く」

毎月固定で発生する支払（顧問料・家賃・借入返済・固定額の業務委託）は、**請求書の到着に依存させない**。
`osi-finance-settings`「7-3. 定期支払先（毎月固定）」に登録し、当月分の支払予定を先に台帳へ置く。
これで請求書自体を取りこぼしても、支払予定日に必ず引っかかる。

### 12-2. 月末振込は当日にやらない

月末当日にまとめて処理すると、リストが不正確なときに取りこぼす。**月末の2〜3営業日前**に
「今月末までに払うもの」を確定させ、そこで定期支払の起票漏れも点検する。

### 12-3. 推奨スケジュール

| 頻度 | 内容 |
|---|---|
| 平日 毎朝 | 連携健全性 → 新着請求書の未起票検出 → 突合と台帳反映 → 期日3営業日以内の未払い |
| 毎週はじめ | 今週払うものを振込先つきで一覧（そのまま振込画面に入力できる形） |
| 毎月26日ごろ | 月末までに払うもの＋定期支払の起票漏れ点検＋必要残高 |

通知は**アクションが無いときは1行で終える**こと。毎日長文が届くと読まれなくなり、
結局また台帳が見られなくなる。

## 13. 頻出する細かい科目（迷ったらここ）

| 取引 | 勘定科目 | 税区分 | インボイス | 備考 |
|---|---|---|---|---|
| 銀行の振込手数料 | 支払手数料 | 課税仕入10% | 適格 | 件数が多いので機械的に処理してよい |
| 業界団体・商工会等の会費 | **諸会費**（科目が無ければ**雑費**） | **対象外（不課税）** | 対象外 | 入会金も同じ扱い。科目を新設するかは方針次第 |
| カード会社への保証金差入 | 差入保証金 | 対象外 | 対象外 | §6-1 参照。資産であり費用ではない |
| キャッシュバック・ポイント還元 | 雑収入 | 対象外 | — | 費用のマイナスにしてもよいが方針を統一する |
| 借入返済 | 長期借入金＋支払利息 | 対象外 | — | §10 参照。償還予定表が要る |

**この会計に実在しない科目は使わない。** 必ず `getAccounts` で実在科目に突き合わせる
（「外注費」→「業務委託料」など。対応表は `osi-finance-mf-sync/references/mf-journal-rules.md`）。
補助科目が無い取引先は、残高を追う必要があるもの（貸付金・未払金・売掛金）だけ**先に補助科目を作る**。
