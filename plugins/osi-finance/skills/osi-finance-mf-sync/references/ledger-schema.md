# 台帳スキーマ（連携で使う列の解説）

**全タブ・全列・フォルダ構成の正本は `assets/schema/data-layout.yaml`（データレイアウト仕様）**。
本ファイルはそのうち「連携で参照・更新する列」の意味と扱いを解説する補足。
台帳の実体＝台帳フォルダ（拡張設定「台帳フォルダ【必須】」）に置いたローカル xlsx。

## 操作者トラッキング列（v3・行を持つ全タブ共通）

全タブは末尾に **作成者／作成日時／更新者／更新日時** を持つ（雛形マスタのみ 登録者／更新者／更新日時）。
操作者＝**拡張の設定「操作者【必須】」に入れた値**。台帳を共有された人が「誰の仕事か」を列で読めるようにする。

**この値はコネクタが自動で押す。`actor` を渡さないこと。** サーバ（`xlsx-tools`）が env の `OPERATOR` を
更新者／作成者に書くので、スキル側は何もしなくてよい。**ログインユーザーのメールを自分で入れてはいけない**
——コンソール経由とスキル経由で違う文字列が入り、同じ人の操作が別人に見える。
実際に割れた: メール表記と `Claude(OSI Finance)` 77行。後者は人ではなく道具の名前で、
誰が操作したのか台帳から読めなかった（77行は 2026-08-16 に実操作者へ寄せ済み）。

- **行を新規に書くとき**（contract-intake / contract-draft / payment-intake の起票、invoice の単票起票、
  スケジュール展開の各行）：作成者・作成日時（JST `YYYY-MM-DD HH:mm`）を記録する。以後上書きしない。
- **既存行を更新するとき**（invoice のステータス更新、mf-sync / ar-sync / freee-sync / bank-recon の
  突合結果・突合日時・実績反映、コンソールのボタン操作、条件修正）：更新者・更新日時を毎回上書きする。
- 設定「操作者」が空なら、拡張の設定を入れてもらう（スキルが推測で埋めない。空で書くほうがまだ無害）。
- 正本は `assets/schema/data-layout.yaml`（v3 `operator_tracking`）。列はヘッダ名で解決する（列番号決め打ち禁止）。

## 共通キー

`請求書ID = 支払先ID + 対象月(YYYYMM) + 請求書番号`
請求書番号が無い証憑は `支払先ID + 対象月 + 金額 + 連番`。
このIDを仕訳の摘要に必ず含め、台帳・MFの突合キーにする。

## シート「月次支払スケジュール」（契約由来・AP予定）

AR 側「月次請求スケジュール」の対称版。**発注契約（方向=発注・状態=締結済）** を起点に、契約期間の各月へ支払予定を展開する。`osi-finance-payment-detect` は「受領請求書 × 本予定」を突合し、予定にあるのに請求書未着＝督促、予定に無い実請求＝新規、を検出する。

| 列 | 用途 | 連携での扱い |
|---|---|---|
| 予定ID | 主キー | `支払先ID + 対象月(YYYYMM)` |
| 契約ID | 契約紐付け | 契約マスタ（方向=発注）の `AP-C-###` |
| 取引先ID | 名寄せ | **共通マスタの「取引先マスタ」**（`P-001` 形式の文字列）。双方向先の相殺突合キー |
| 支払先ID | 取引先紐付け | 支払先マスタ（V-）。取引先IDと対応 |
| 支払先名 | 表示 | |
| 対象月 | 期間 | 重複展開防止（同 契約ID×対象月 は作らない） |
| 予定額(税込) | 金額 | 月額固定は各月、一括は該当月のみ |
| 支払予定日 | 期日 | 契約の支払サイトから算出 |
| 状態 | 進捗 | 未払予定／請求書受領済／支払済 |
| 受領請求書ID | 突合 | payment-detect が受領AP請求書と結び付け |

> **初月日割り**：契約開始が月途中なら初月は日割り（AR の請求スケジュールと同ルール）。

## 契約マスタ（請求管理台帳）の拡張列（AR/AP 共通）

契約マスタは AR/AP 双方を1表で持つ。既存列に加え次を持つ：
`取引先ID`（`P-001` 形式・**共通マスタの取引先マスタ**）／`方向`（受注/発注）／`状態`（ドラフト/締結済）。
**状態=締結済のみスケジュール展開**（AR=月次請求スケジュール／AP=月次支払スケジュール）。契約IDは方向接頭辞つき（`AR-C-###`／`AP-C-###`、既存 `C-###` は AR とみなし移行）。

> **契約マスタは宛先を持たない。**（2026-09-06）`請求先To` `Toアドレス` `CC` `CCアドレス` の4列は
> 削除した。会社の情報は `取引先ID` で共通マスタの**取引先マスタ**を引く。
> 同じ情報を2箇所に置いていたため片方だけ直され、「取引先マスタは正しいのに契約マスタが古い」
> 状態が実際に起きていた（セーフティ＆ベル）。契約ごとに窓口が違う相手は契約の備考に書く。

## 請求管理台帳（AR）で連携が使う列

タブ・全列の定義は `assets/schema/data-layout.yaml` を参照。連携で意味を持つのは次。

| タブ / 列 | 連携での扱い |
|---|---|
| 月次請求スケジュール / 請求書番号 | `INV-YYYY-MM-連番3桁`。**AR の突合キー**（ar-sync が MF 仕訳の摘要と照合） |
| 月次請求スケジュール / 請求ステータス | `未請求 → 下書き済`（invoice が更新）→ `請求済 → 入金済`（人のボタン/Gmail整合）。差し戻しは人のみ。ar-sync の抽出条件 |
| 月次請求スケジュール / 突合結果・突合日時 | mf-sync/ar-sync 等が書き戻す（一致/未計上）。コンソールは表示のみ（v2） |
| 月次請求スケジュール / 請求額(税込)・対象月 | 売上計上（(借)売掛金/(貸)売上高＋仮受消費税・対象月末計上）の金額・日付の源泉 |
| 月次請求スケジュール / 入金日・入金額 | 入金消込（(借)普通預金/(貸)売掛金）の源泉。銀行連携が消込する運用では「除外」 |
| 発行者設定 | 請求書PDFの発行元情報。osi-finance-settings と一致させる（不一致はヘルスチェックで報告） |

## 抽出条件（再掲）

AP：`状態 = 支払済` かつ `MF連携状態 = 未連携`（実質 MF仕訳ID が空）。
AR：`請求ステータス = 請求済`（売上計上）／`= 入金済`（消込）で、MF に対応仕訳が無いもの。
