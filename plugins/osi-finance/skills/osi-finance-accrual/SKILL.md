# 期ズレ計上（osi-finance-accrual）

> **組織固有値はプロファイルから読む。** 本文の `{{paths.*}}` `{{ledgers.*}}` `{{company.*}}` は、
> 連結フォルダ直下の `osi-profile.md` と `config/osi-finance-settings.md` の値に置き換えて解釈する。
> 判断ルールの正本は `references/accrual-rules.md`。毎回それに沿って判定し、ブレさせない。

## なぜ毎月やるのか

決算整理のうち「期ズレ」（前受・前払・未払・未収）は、期末に1年分まとめてやると、どの請求がどの月の
役務だったかを思い出す作業になる。毎月の締めで同じ判定をしておけば、期末は**残高が説明できるかの確認だけ**で済む。
月次の損益も「入金・支払の月」ではなく「仕事をした月」で見られるようになる。

## 入力（新しい台帳は作らない）

| 見るもの | どこ | 使い方 |
|---|---|---|
| 契約マスタ | 請求管理台帳 | 契約期間・金額区分・支払条件（着手金／完了時など）・方向（受注／発注） |
| 月次請求スケジュール | 請求管理台帳 | 対象月の役務行、着手金・残金の行、請求ステータス |
| 月次支払スケジュール | 支払管理台帳 | 対象月の支払予定、予定額（空＝都度）、状態（請求書受領済か） |
| 前払費用・長期前払費用・前受金・未払費用の仕訳 | MF（`getJournals` を科目IDで） | 按分タグ（下記）と残高 |
| 残高試算表 | MF（`getReportsTrialBalanceBalanceSheet`） | 取崩し後の残高が按分表と一致するかの検算 |

按分の予定は **MFの仕訳の摘要に書いた按分タグ**に持たせる（別の一覧を作らない）:

```
[按分 2026-06..2028-05 24回 月110000 通信費 課仕10%]
```

タグの無い既存の前払費用は、摘要から期間・回数を読み取って案を出し、人が確認したら `putJournals` で
摘要の末尾にタグを追記する（1回だけ）。

## 手順

```
0. 対象事業者・対象月・会計期間を確認（currentOffice）。対象月が期末月かも判定する
1. 読込：上の表の台帳とMFを読む（台帳は sheets_get_values、ヘッダー行は header_row を使う）
2. 判定：references/accrual-rules.md の §1〜§6 を順に当てて「仕訳案」「要確認」「対象外」に振り分ける
   §1 前受金      … 着手金・準備金・前金の計上科目、完了月の売上振替
   §2 前払費用    … 按分タグに従い当月分を費用へ取崩し
   §3 長期前払費用 … 礼金・保証料など税法上の繰延資産を月割償却
   §4 未払費用    … 当月役務で請求書未着の支払を見積計上（翌月1日に振戻し）
   §5 計上漏れ    … 契約期間内なのに対象月の行が無い受注・発注契約
   §6 期末組替え  … 期末月だけ。1年超の前払費用を長期前払費用へ
3. 仕訳案を一覧で出す（日付・借方・貸方・金額・税区分・摘要キー・根拠行）。要確認は「何が決まれば計上できるか」を1行で添える
4. 人の承認後に登録：postJournals を少数ずつ。登録直後に getJournals と残高試算表で件数・金額・科目残高を検算
5. 報告：科目別の月末残高と内訳（前受金・前払費用・長期前払費用・未払費用）が説明できる形で出す
```

## 摘要キー（重複防止の生命線）

同じ根拠から二度計上しないよう、摘要の先頭に必ずキーを入れる。登録前に同じキーの仕訳が無いかを `getJournals` で確かめる。

| 区分 | キー |
|---|---|
| 前受金の計上・振替 | `ACR-前受 {契約ID} {対象月}` |
| 前払費用の取崩し | `ACR-前払 {元仕訳No} {n}/{回数}` |
| 長期前払費用の償却 | `ACR-長前 {元仕訳No} {対象月}` |
| 未払費用の見積・振戻し | `ACR-見積 {予定ID}` ／ `ACR-振戻 {予定ID}` |
| 期末組替え | `ACR-組替 {元仕訳No} {期末}` |

## 他スキルとの分担

- **売上の月額分**は `osi-finance-ar-sync` が「対象月末日付」で計上する。本スキルは計上しない（二重計上になる）。
  月次の締めを請求書発行（翌月初）の後にすれば、請求前の見越し計上は要らない。本スキルは「行が無い」漏れだけを見る（§5）。
- **支払の実額**は `osi-finance-mf-sync` が計上する。§4で見積を入れた予定IDは、実額を**受領月の日付**で計上する
  （対象月末に入れると見積と二重になる）。
- **減価償却・固定資産**は対象外（資産か経費かの判断を含むため別工程）。
- **消費税・法人税等の計上、税務調整**は対象外（税理士の領分）。

## 注意

- 自動で確定しない。仕訳は必ず人の承認を経て登録する。
- 前受金の売上振替は「完了した」事実が要る。完了を台帳（残金行の請求ステータス）か人の確認で押さえてから出す。
  推測で売上に振り替えない。
- 見積の根拠（前月実績・契約額・算定式）は摘要に書く。根拠の無い見積は出さず、要確認にする。
- 事業者の取り違えは事故。対象事業者を毎回確認する。
- 当会計年度外の日付は post できない。前期分は別処理。

## エラー処理

詳細は [`docs/エラー処理ガイド.md`](../../docs/エラー処理ガイド.md) を正本とする。

- 台帳の列が data-layout と違う → そこで止めて報告（`osi-finance-monthly` Step 0 と同じ）。
- 按分タグと残高が合わない → 取崩しを出さずに差額と候補原因（取崩し漏れ・二重・期間の誤り）を報告。
- MFの登録結果が返らない → 同じ仕訳を再送しない。先に `getJournals` で登録有無を確かめる。
