# 残高の説明表（osi-finance-balance-schedule）

> **組織固有値はプロファイルから読む。** 会計期間・台帳の場所・支払サイト・資本金の登記内容は
> `osi-profile.md` と `config/osi-finance-settings.md` を正とする。
> 科目ごとの説明のしかたの正本は `references/balance-rules.md`。毎回それに沿って判定し、ブレさせない。

## なぜ毎月やるのか

決算書は仕訳を集計しただけのものなので、残高の中身が説明できなければ、決算書も説明できない。
期末に1年分の残高を遡って調べると、「この売掛金は入金済みなのに消し忘れたのか、本当に未回収なのか」を
探す作業になる。毎月の締めで残高を説明しておけば、期末はこの表を内訳明細書に写すだけで済み、
間違いも発生した月のうちに見つかる。

## 入力（新しい台帳は作らない）

| 見るもの | どこ | 使い方 |
|---|---|---|
| 科目別の月末残高 | MF（`getReportsTrialBalanceBalanceSheet`） | 説明する対象。内訳の合計がこれと1円単位で合うこと |
| 科目ごとの仕訳 | MF（`getJournals` を科目IDで） | 補助科目・取引先・摘要（按分タグ・資産タグ・摘要キー）で内訳に分ける |
| 補助科目・取引先 | MF（`getSubAccounts` `getTradePartners`） | 相手別に分ける単位 |
| 口座の残高 | MF（`getConnectedAccounts`）／銀行の明細 | 預金の残高を外の証拠と照らす |
| 請求・入金 | 請求管理台帳（月次請求スケジュール・契約マスタ） | 売掛金・前受金を請求書・契約単位で説明する |
| 支払 | 支払管理台帳（月次支払管理・月次支払スケジュール） | 買掛金・未払金を支払予定単位で説明する |
| 資本金・借入・貸付の取り決め | 登記事項・契約書（Drive） | 資本金・借入金・貸付金の残高の裏付け |

## 手順

```
0. 対象事業者・対象月・会計期間を確認（currentOffice）。期末月かどうかも判定する
1. 残高を読む：残高試算表（貸借対照表）の全科目を取得し、残高が0でない科目を一覧にする
2. 内訳に分ける：references/balance-rules.md の科目別ルールで、科目ごとに内訳（相手・契約・タグ単位）を作る
3. 合計を合わせる：内訳の合計＝残高試算表の残高 になるまで、差額の原因を探す（見つからない差額は差額のまま出す）
4. 外の証拠と照らす：預金は口座の残高、売掛金・未払金は台帳、資本金は登記、借入金は返済予定表と照らす
5. 要確認を挙げる：balance-rules.md §9 のどれかに当たったものを、何が決まれば消えるかを1行添えて挙げる
6. 報告：科目ごとに「残高・内訳の件数・合っているか・要確認」を1行で。要確認は上にまとめる
   期末月は §10 の形（内訳明細書の様式ごと）で xlsx にも出す
```

## 出力

- **毎月**：画面で報告する。合っている科目は1行、要確認がある科目だけ内訳を開いて見せる。
  ファイルは作らない（同じことを毎月の締めで繰り返すだけなので、残す必要がない）。
- **期末月（または頼まれたとき）**：`{{paths.ledger}}/決算/{期末年月}_残高の説明表.xlsx` に、
  内訳明細書の様式ごとにシートを分けて保存する。税理士への受け渡しと申告書への転記に使う。

## 他スキルとの分担

- 本スキルは**読むだけ**。仕訳は登録しない。直す仕訳は、原因ごとに担当スキルへ回す:
  前払・前受・未払の期ズレ → `osi-finance-accrual`／固定資産・償却 → `osi-finance-fixed-assets`／
  売上・入金の漏れ → `osi-finance-ar-sync`／支払の漏れ → `osi-finance-mf-sync`／
  連携明細の未仕訳・重複 → `osi-finance-feed-recon`。
- 期末の決算整理（法人税等・消費税の精算・資本金の振替など）は決算整理のスキルが行い、本スキルはその前後で残高を確かめる。
- 税額の計算・申告書（別表）の作成は対象外（税理士または申告ソフト）。

## 注意

- 差額を「その他」や「調整」にまとめて合わせない。合わない差額は合わないまま出す。
- 相手の名前は、台帳・取引先マスタの正式名称で書く。推測で書かない。
- 口座番号・カード番号は内訳に書かない（下4桁まで）。
- 事業者の取り違えは事故。対象事業者を毎回確認する。

## エラー処理

詳細は [`docs/エラー処理ガイド.md`](../../docs/エラー処理ガイド.md) を正本とする。

- 残高試算表が取れない → 推測で表を作らない。取れた科目だけで出し、取れなかった科目を明記する。
- 台帳の列が data-layout と違う → そこで止めて報告（`osi-finance-monthly` Step 0 と同じ）。
- 内訳の元になる仕訳が多すぎて一度に読めない → 期間を月ごとに分けて読み、合計を足し上げる。
