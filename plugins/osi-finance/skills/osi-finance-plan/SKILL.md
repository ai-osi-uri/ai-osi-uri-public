# 計画を読む

## 正本は Excel。ここでは書き換えない

計画は根拠から出る数字で、その計算は Excel の式の中にあります。**同じ計算を台帳側にも持つと、
2箇所に計算装置が立って必ず食い違います。** だから計画は Excel を唯一の正本とし、
Cowork とコンソールは**読んで出すだけ**にしています。

- 置き場: 台帳フォルダ（既定 `06.会計`）の **`事業計画.xlsx`**
- 主シート: `【計画】財務三表（月次）`（月が横、科目が縦、B〜G列のインデントが階層）
- 年次シート: `【計画】財務三表（年次）`
- コンソール: 財務三表タブ →「計画」サブタブ。年度を選んで表示し、
  リード数・単価・人数などの**前提行は既定で隠す**（チェックで出せる）

## 読み方

1. `sheets_get_values`（`spreadsheet_id: 事業計画`）でシートを取る。
2. **行や列の位置を決め打ちしない。** 月は「日付が並んでいる行」を探して見つけ、
   科目は B〜G 列のどこにラベルがあるかで階層を判断する。Excel 側で行が増減しても壊れないように。
3. 数字を引用するときは**どの行のどの月か**を必ず添える。計画には似た名前の行が並ぶ
   （例: 「アップセル売上」と「新規開発売上」は親子で同額）。

## 実績と混ぜない

実績は勘定科目、計画は計画自身の切り方（CAIO契約売上、コンサル外注、通信費の内訳…）で、
**行の対応は付きません。** 突き合わせるときは金額の意味が同じところ——売上高・売上原価・
販管費・営業利益——に絞り、それ以外を1対1で並べない。並べると、名前が似ているだけの行が
対応づいて差異が意味を失います。

コンソールでも予実対比の表は作っていません（実績と計画は別サブタブ）。
比較が必要なときは、この4つの数字だけを会話で並べて説明する。

## 直すのは計画だけ

**実績はチャットで直さない。** 実績の正本は仕訳で、会話で書き換えるものではありません。
数字がおかしいときは仕訳を直す（`osi-finance-journal`）。ここで扱うのは計画だけです。

計画は毎月ズレていくものなので、直せることが前提。コンソールの「財務三表 → 計画」に
2つのボタンがあり、どちらも Cowork を開いてこのスキルを呼びます。

- **📝 新規で事業計画を作る**（計画ファイルが無いとき）
- **💬 チャットで計画を直す**（あるとき）

## セルを突かない。作り直す

**式の入ったブックのセルを機械で書き換えないこと。** どの式が壊れたか誰も気づけないまま
数字だけが残ります。**直すときは前提（config）を変えて、`financial-model-3statement` で
作り直す。** これは「Excel の中に計算を置く」方針と矛盾しません——計算装置は1つのまま、
入力を変えて出し直すだけです。

そのために、生成した計画の隣に **`事業計画.config.json`**（前提一式）を必ず置きます。
これが無いと次回の修正で前提を引き継げず、また一から聞き直すことになります。

### 新規に作るとき

1. **実績を出発点にする。** 仕訳台帳の確定仕訳から直近数ヶ月の売上高・売上原価・販管費を出す。
   ゼロから想像で置かない。
2. 前提を対話で決める（売上ドライバ・単価・件数・採用計画・固定費）。一度に4問まで。
3. config に **開始年月（`YYYY-MM`）** を必ず入れる。**月番号だけでは暦月の実績と並べられない。**
4. 生成したら verify で **Balance Check と 連動Check が全月 0** であることを確認する。
   **0 でないまま渡さない。**
5. `事業計画.xlsx` と `事業計画.config.json` を台帳フォルダに保存する。

### 直すとき

1. 今の計画と config を読み、前提と数字を要約して見せる。
2. 実績と並べ、**売上高・売上原価・販管費・営業利益の4つ**でズレを示す。それ以外は1対1で並べない。
3. **どの前提を動かすかを相談する。金額の直接上書きはしない。**
4. 作り直す前に、**前の版を `事業計画_YYYY-MM.xlsx` として残す。**
   上書きだけだと「先月は何と言っていたか」が消え、達成の議論が揺れます。
5. Check=0 を確認して差し替え、**通期の売上高と営業利益がいくらからいくらに変わったか**を報告する。

## やらないこと

- 計画の数字を台帳（仕訳台帳）に写して持たない。かつて `計画PL` `計画ドライバ` タブで
  やって二重管理になり、2026-08-25 に廃止した（タブは中身を空にして「未使用」と印がある）。
- 実績が計画に届かないときに、帳尻合わせの計画引き下げを提案しない。
  数字を動かす判断は人がする。こちらは「動かすとこうなる」を示すだけ。
