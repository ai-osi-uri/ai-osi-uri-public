# osi-finance-journal（内部仕訳帳への仕訳生成・記帳）

> **組織固有値（台帳ID・科目マッピング・税率）は `config/osi-finance-settings.md` を参照。**
> データ構造の正本は `assets/schema/data-layout.yaml` v4（仕訳台帳: 仕訳帳／勘定科目マスタ／月次サマリ）。
> `OPERATION_MODE=参照専用` のときは生成案の提示までで記帳しない。

## 安全原則（厳守）

- **仕訳の自動確定はしない。** 生成は必ず「案」として全件提示 → 人が承認 → 状態=確定 で記帳。
- 同一 **参照ID×出所×対象月** の仕訳が既にあれば再生成しない（重複防止）。
  **キーに対象月を含めるのが肝**。合算請求は対象月をまたぐことがあり、2キーだと正常な月別計上を
  重複と誤検知する。それを避けようとして参照IDに枝番を付けると重複防止が効かなくなる（後述）。
- **記帳の前後で `assets/scripts/verify_ledger.py` を必ず走らせ、ERROR が1件でもあれば記帳しない。**
  ```
  python3 <plugin>/assets/scripts/verify_ledger.py "<台帳フォルダ>"
  ```
  借貸一致・仕訳ID重複・参照ID重複・枝番・マスタ外科目・請求書ID別の額面超過（売上/入金）・
  売掛金の自閉・税基準ズレの疑い（約1.1倍）を検査して exit 1 で止める。
  **これらは「静かに間違う」種類の事故で、人の目視では見つからない。** ルールを読んで気をつける
  のではなく、毎回この検査を通すこと。
- **書き込み開始行は件数から計算しない**（下「書き込み位置」）。
- 科目が判定できない行は推測せず「要確認」で止める。決算整理・税務判断は税理士の領分。
- 月次サマリは数式集計（手編集しない）。クローズ済みの月には記帳しない（人がオープンに戻してから）。
- **この仕訳帳は税込で持つ。** 仮受／仮払消費税を別行で分けない。会計SaaS の帳票（税抜で返るものがある）と
  比べるときは必ず税基準を揃える（`osi-finance-mf-sync` の「税基準」を参照）。

## 生成ルール（v1 標準・最終は各社の税理士確認前提）

| # | 出所 | 元データ（抽出条件） | 仕訳 |
|---|---|---|---|
| 1 | AR請求 | 月次請求スケジュール `請求ステータス=請求済/入金済`（対象月末で計上） | (借)売掛金＝税込 ／ (貸)売上高（税区分: 課税売上10%。仮受消費税の別行は作らない） |
| 2 | AR入金 | 同 `=入金済`（入金日で計上） | (借)普通預金＝入金額 ／ (貸)売掛金 |
| 3 | AP支払 | 月次支払管理 `状態=支払済`（支払日で計上） | (借)費用科目（支払先マスタの既定科目）＝税込 ／ (貸)普通預金。源泉ありは (貸)預り金 を併記 |
| 4 | 経費 | 経費一覧（発生月で計上） | (借)費用科目＝税込 ／ (貸)未払金 or 普通預金（支払状況で選択） |

- 摘要: `{取引先/支払先名} {内容} {参照ID}`。**参照ID（INV-…／請求書ID／経費ID）を必ず含める**。
- 銀行連携・カード連携が会計SaaS側で自動仕訳する運用（mf の入金bank連携等）では、該当出所を
  **除外**して二重計上を防ぐ（settings の AR_BANK_LINK_HANDLING 等に従う）。

### 売上計上しないもの（前受金に振り分ける）

出所1（AR請求）は「請求済＝一律売上計上」ではない。次の**両方**に当てはまる行は、売上ではなく
**(借)売掛金 ／ (貸)前受金** で計上し、検収・返金条項の消滅をもって **(借)前受金 ／ (貸)売上高** に振り替える。

1. 役務の提供が完了していない（検収前・納品前）
2. 全額返金条項・契約白紙条項が残っている

典型は**準備金・着手金・前受一括**。契約書に「期日までに未完成なら契約白紙・全額返金」がある準備金は、
入金があっても売上ではない。判定できない行は確定せず「要確認」に回す。
判断辞書は `osi-finance-monthly/references/monthly-rules.md` §10 を正本とする。

### 仕訳IDの採番（衝突する構造なので厳守）

`J-YYYYMM-連番4桁`。**出所グループごとに採番してはいけない。** 上の表は出所4種を別々に処理する構造なので、
グループごとに1から振ると AR支払 と AP発生 で同じIDが出る（実際に発生した事故）。

1. 記帳直前に仕訳帳の**全行**の 仕訳ID を読み、`J-YYYYMM-` の**最大連番**を取る。
2. その月のバッチ全体（出所をまたいで）を、最大連番+1 から**通しで**採番する。
3. 記帳直前にもう一度、当月 仕訳ID に重複が無いことを検査する。**1件でもあれば記帳せず止めて報告**。

`osi-finance-invoice` の請求書番号採番と同じ強さで守ること。

### 書き込み位置（データを潰さないため）

- **`ヘッダ行 + 件数 + 1` で開始行を計算してはいけない。** 台帳の途中に空行があるため、既存行を上書きする
  （実際に11行を潰して復旧した事故がある）。
- `sheets_append_row` を使い、行位置の解決を拡張側に任せる。自前で書く場合は
  **シートの実最終行（末尾から遡って最初の非空行）を取得し、その次行から**書く。
- 列は必ずヘッダ名で解決する。読み取り範囲はタブ名だけを渡す（`!A1:T600` のような範囲指定は
  列・行が増えたときに静かに欠ける）。

## 手順

1. **前提確認**: settings（ACCOUNTING_SYNC・科目マッピング）と
   仕訳台帳のタブ（仕訳帳／勘定科目マスタ／月次サマリ）を確認。列は**ヘッダ名で解決**（順序に依存しない）。
2. **対象月の読込**: 指定月（未指定なら前月）について、3台帳から抽出条件に合う行を取得。
3. **既存仕訳の照合**: 仕訳帳の同月分を読み、参照ID×出所×対象月 で突合。既にある行はスキップ、
   台帳にあるのに仕訳が無い行を「未仕訳」として列挙する。
   - **参照IDは請求書ID単位に正規化する。`INV-xxx/C-029` `INV-xxx/7月分` のような枝番を作らない。**
     枝番を付けると同じ請求書が別の参照IDに化けて重複防止をすり抜ける（NITOH で実際に 3,575,000 を
     売上・入金とも二重計上した）。合算請求の内訳を残したいときは参照IDではなく**摘要**に書く。
   - 同じ請求書を月をまたいで按分計上したい場合、**枝番ではなく対象月で区別する**（キーが3つ組なので
     それで一意になる）。`verify_ledger.py` の「参照IDの枝番」検査がこれを機械的に止める。
4. **仕訳案の生成**: 未仕訳分について生成ルールで仕訳案を作成。科目は 勘定科目マスタ＋settings の
   支払先→科目マッピングで解決（解決できない行は「要確認」）。借貸一致を検算。
   - **請求書ID単位の額面検算（必須）**: 同じ請求書IDについて「既存仕訳の売上計上額 ＋ 今回の計上案」が
     **請求書の額面を超えないこと**を検算する。超えたら計上せず報告する。これが二重計上の最後の砦。
5. **人レビュー（必須ゲート）**: 仕訳案の全件（日付・借貸・金額・摘要）と「要確認」を提示し、承認を得る。
   金額を書き換える提案（既存行の訂正）を含む場合は、訂正前後の値と借貸検算を並べて提示する。
6. **記帳**: 承認された行を仕訳帳へ追記（状態=確定・作成者=ログインユーザーのメール・作成日時）。
   採番と書き込み位置は上のルールに従う。**記帳前に台帳ファイルのバックアップを取る**。
   記帳後に件数・合計・仕訳ID重複・参照ID×出所重複を読み戻して検算。月次サマリの 未仕訳件数 を更新する。
7. **エクスポート（SYNC設定時のみ・任意）**:
   - `mf`: 既存の mf-sync/ar-sync のレビューフローで postJournals（登録後 エクスポート済み=mf）。
     **科目名はローカル名のまま送らない。** 勘定科目マスタの `MF科目名` 列で変換してから送る。
   - `freee`: freee インポート形式のCSVを生成して `04.連携データ/freee/` に置く（投入は人。出力後 エクスポート済み=freee）。
     同様に `freee科目名` 列で変換する。
   - `none`: 何もしない（仕訳帳が正本）。

## 期首残高（`ACCOUNTING_SYNC=none` では必須）

仕訳帳が会計の正本になる運用では、期首残高が無いと BS が成立しない（売掛金が期首未回収分だけ
マイナスに沈む、普通預金が実残と合わない）。

- 出所 `期首残高`・日付＝会計年度開始日・参照ID `OB-YYYY-MM-DD-n` で計上する。
- 会計SaaSがある組織はその期首残高（MFなら `getReportsTrialBalanceBalanceSheet` の `opening_balance`）を正本に写す。
- 仕訳帳は1行1借方1貸方の形式なので、期首残高は**科目ごとの合計が一致するように**balanced pair に割り付ける
  （割り付け方は任意。摘要に「期首残高」と内訳を書く）。
- 資金取引（出資・借入・貸付の入出金）を台帳が持たない運用では、**普通預金は合わない**。
  合わせるなら資金取引の入出金仕訳も入れる必要がある。合わせない方針なら settings に明記する。

## 未仕訳の検出（単体でも呼べる）

「未仕訳を検出して」では記帳せず、Step 2-3 のみ実行して未仕訳一覧（出所別・件数・金額）を報告し、
月次サマリの 未仕訳件数 を更新する。コンソールの仕訳タブが表示に使う。

## エラー処理

詳細は **[`docs/エラー処理ガイド.md`](../../docs/エラー処理ガイド.md)** を正本とする。
- 仕訳台帳・タブが見つからない → data-layout v4 の定義を提示し、作成（setup）を案内して止まる。
- 科目未解決・源泉計算不明 → 「要確認」に分類し確定しない。
- クローズ済み月への記帳依頼 → 拒否し、人によるオープン戻しを案内。
