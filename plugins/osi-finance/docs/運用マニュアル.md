# OSI Finance 運用マニュアル

**毎日この経理を回す人のための本。**困ったときに引く場所。
導入・初期設定は [`導入マニュアル.md`](./導入マニュアル.md) を見てください。ここは動き出したあとの話です。

---

## 0. 最初に覚える3つ

**① 台帳が正本。画面もチャットも、台帳を見せている窓にすぎない。**
だから**台帳に無いものは、どの画面にも出ません。**
2026-08-17 に、契約書もメールもあるのに台帳に無い支払（3,190,000円・期限48日超過）が
見つかりました。健康診断にも遅延にも一切出ていませんでした。
**「画面に出ていない＝無い」ではありません。**

**② お金を動かすのは人。システムは送金しません。**
振込は自分で実行して、そのあと画面で「支払済」にします。
請求書メールも、下書きまで作って止まります。送信ボタンは人が押します。

**③ 迷ったら「要確認事項」タブを開く。**
放っておくと事故になるものだけを、台帳から自動で拾っています。
ここが0件なら、少なくとも機械で分かる範囲では問題がありません。

## 1. 1日の流れ

### 朝（5分）

1. コンソールを開く（デスクトップの「コンソールを開く」／`http://127.0.0.1:7789/`）
2. **左サイドバーの「要確認事項」に数字が出ていたら開く**
3. ダッシュボードの **「支払の遅延」** を見る

朝のうちに、届いた受領請求書の検出が自動で回っています（起票案の提示まで。自動では書きません）。

### 請求書が届いたら（その場で30秒）

**Cowork のチャットに PDF をドロップして「この請求書を支払予定に起票して」。**
フォルダに置きに行かなくて構いません。読み取り → 格納 → 起票案まで出ます。
**内容を確認してから**確定してください。

> カード払い（自動課金SaaS）の請求書は**起票しません。**
> 会計のカード連携が既に仕訳しているので、二重になります。証憑の保存だけします。

### 振り込んだら（10秒）

支払一覧 →「実績」→ 該当行の状態を **「支払済」** に。支払日が自動で入ります。

## 2. 1ヶ月の流れ

| 時期 | やること | 誰が |
|---|---|---|
| **1日 9:30** | 当月の請求書を自動で下書き | 自動 |
| 1日〜3日 | **Gmail の下書きを確認して送信** → 画面で「請求済」に | 人 |
| 随時 | 受領請求書を起票、振込、支払済に | 人 |
| 月末 | 入金を確認して「入金済」に | 人 |
| 翌月上旬 | 仕訳を作る（「先月の仕訳を生成して」） | 人＋Cowork |
| 翌月上旬 | 会計と突合して計上漏れを見る | 人＋Cowork |

### 月初の請求は「止まる」ことがある

宛先が入っていない契約があると、**そこで止まります。**これは正しい動きです。
番号だけ採番されて中身が無い請求書ができると、連番に穴が空くからです。

止まらないように、**月末までに要確認事項の「請求先メールが未設定・要確認」を0件にしておく。**

## 3. 画面の使い方

### ダッシュボード

月に依存しません。常に全期間を見ます。

- **月別の売上・費用・利益** … **ローカルの確定仕訳が正本**です。会計SaaS（MF）は
  「外で突き合わせる相手」であって、データの出どころではありません
- **支払の遅延** … 支払予定日と今日の差で、その場で計算しています。
  「支払予定日なし N件」が出ていたら、**その行は遅延を判定できていません**。予定日を入れてください
- **消費税の見込み（1行）** … 台帳の税額列からの概算で、**仕訳とは別の計算**です
  （ローカル仕訳は税込のまま税額を分けていません）。**必ず幅で見てください。**
  貸付金など不課税の支出が混ざると控除しすぎになり、未請求ぶんを入れると増えます。
  簡易課税・2割特例を選ぶと計算方法ごと変わります。**確定は税理士の判断です。**
  詳しく見るときはチャットで「税理士に渡す消費税の材料を作って」

> **資金繰り（口座残高から「払えるか」を見る）機能は、意図的に持っていません。**
> 口座残高には対応する業務イベントが無く、誰かが思い出して入れるしかないため、
> 忘れた瞬間に「残高」という信じられる名前で古い数字が残ります。
> この台帳が信じられるのは、すべての行が業務イベントから生まれているからです。
> 資金繰りが要るときは、会計SaaS のレポートか銀行アプリを使ってください。

### 要確認事項

13項目を自動で見ています。**読むだけで、何も書き換えません。**

期限が走るものが2つ入っています。

- **源泉徴収の対象なのに徴収していない** … 納期限は原則**支払った月の翌月10日**
  （納期の特例なら年2回）。遅れると不納付加算税・延滞税がつきます。
  対象かどうかの判断が止まっている行もここに出ます
- **決算・申告の期限が近い** … 申告と納付は原則**決算日の2ヶ月後**。
  `請求管理台帳 → 発行者設定` に **項目=決算月／値=1〜12** の行を足すと期限を追えます。
  未設定のうちは「決算月が未設定です」と出ます

直し方が機械的に決まっているものには **🛠️ 直す** が出ます。押すと「台帳の保守」に移り、
**何をどう変えるかを一覧で見てから**実行できます。押した瞬間には書きません。

### 請求一覧・支払一覧

- **状態はプルダウンで直接変えられます。**その場で台帳に書き込み、更新者と日時を記録します
- **対象月**と**取引先／支払先**の2つで絞れます
- **「下書き済」は、送ったという意味ではありません。**Gmail の下書きを作っただけです。
  送ったかどうかは Gmail が正本です

### 契約一覧

各行の **🔗 紐づく請求 / 紐づく支払 N件** を押すと、請求一覧・支払一覧に移動して、
**その契約の行だけ**に絞られます。押す前に件数が出るので、**0件＝台帳が繋がっていない**と分かります。

> 発注契約で 0件 かつ赤字で「取引先IDが未採番」と出たら、それは**繋ぎ方が無い**状態です。
> 契約マスタと支払先マスタの両方に同じ取引先IDを入れると繋がります。

### 台帳の保守

やり直せる処理だけを置いています。**必ず「確認する」→ 中身を見る →「実行する」**の順で。
実行前に台帳のバックアップを自動で取ります（直近10世代）。

## 4. チャットに何と言うか

画面のボタンで足りないことは、Cowork のチャットに話しかけます。

| やりたいこと | 言い方 |
|---|---|
| 請求書を発行する | 「今月の請求書を作って」「INV-2026-08-011 の下書きを作って」 |
| 受領請求書を起票する | PDFを添付して「この請求書を支払予定に起票して」 |
| レシートを出す | 写真を添付して「このレシートを取り込んで」 |
| 仕訳を作る | 「2026-07 の仕訳を生成して」 |
| 会計と突合する | 「台帳と MF を突合して」 |
| 契約を取り込む | 契約書PDFを添付して「この契約を台帳に起票して」 |
| 月次を締める | 「今月の経理を締めて」 |

**すべて、書き込む前に一覧で提示されます。**確認してから承認してください。

## 5. 困ったとき

### 画面が「台帳未接続」になる

拡張の設定「台帳フォルダ」が空か、パスが違います。
設定 → 拡張機能 → AI OSI URI Finance → 台帳フォルダ を確認し、
**Claude を完全に終了して開き直します**（設定はプロセス起動時にしか読まれません）。

### 「台帳が使用中で書き込めません」

**誰かが Excel で台帳を開いています。**閉じてもらってください。
これは事故防止のための正しい動作です。中途半端に書くよりずっと安全です。

### 画面の数字がおかしい

1. **まず「🔄 再読込」を押す**（開きっぱなしだと古い可能性があります）
2. それでも合わないときは、**台帳を直接見て、どちらが正しいかを確かめる**
3. 台帳が正しくて画面が違うなら不具合です。**そのとき見ていた画面と数字を控えて**報告してください

> 数字を疑うときは、**期待値を台帳から先に出してから**画面と比べてください。
> 画面を見てから「合ってそう」と判断すると、ずれに気づけません。

### 数字が急に減った／増えた

**絞り込みが残っていないか**を先に見てください。
**絞り込みは「絞り込み」欄に入っている文字がすべて**です。`C-001` のように契約IDが入っていたら、
その契約の行だけが出ています。**×ボタン**で消せます。

> 検索は部分一致で、複数の列（取引先・請求書番号・契約ID・件名など）を横断します。
> 空白で区切ると AND です。受注側「ドキュメントフォース」と支払側「ドキュメントフォース株式会社」は
> 表記が違いますが、「ドキュメント」と打てば両方に当たります。

### 台帳を壊したかもしれない

`_backup/` に世代バックアップがあります（保守の実行前に自動取得）。
**あわてて上書きせず、まず今の台帳をコピーして退避**してから戻してください。

## 6. やってはいけないこと

- **台帳を Excel で開いたままにする** … 書き込みが全部止まります
- **台帳のコピーを人ごとに持つ** … xlsx には統合手段がありません。どちらが正か機械には分かりません
- **バックアップを台帳フォルダの中に置く** … 台帳として読まれることがあります
- **導出できるものを列に持つ** … 契約の有効/終了を手管理していたとき、43件中8件がずれていました
- **IDが空の行を寄せる** … 空をキーにすると別人が合算されます（偽の合計が出た実例あり）

## 7. 月次の締めで見るところ

1. **要確認事項が0件か**（0でないなら、残す理由を説明できるか）
2. **ダッシュボードの損益**が、会計SaaS の数字と説明できる差に収まっているか
3. **仕訳の借方と貸方が一致しているか**（仕訳タブの合計に出ます）
4. **未払い・未回収の一覧**に、実態と違うものが残っていないか

差が出たときは「どちらが正しいか」を決めてから直します。
**画面を数字に合わせにいかない。**台帳と現実を合わせます。
