# OSI Finance 導入マニュアル

**本番運用を始めるまでの本。**動き出したあとは `運用マニュアル.md` を見てください。

クリック単位の操作は `導入手順書.md`、顧客・伴走先への説明は `導入ガイド.md` にあります。
この本はそれらの上位に立ち、**誰が何を判断し、どこで「導入できた」と言え、失敗したらどう戻すか**を扱います。

---

## 0. 導入で本当に難しいのは、設定ではありません

設定は2時間で終わります。難しいのは次の3つです。

1. **既存データをどう載せるか。** 会社は既に動いていて、請求も支払も途中です
2. **いつ切り替えるか。** 従来のやり方と併走する期間をどう設計するか
3. **何をもって「導入できた」と言うか。** ここを決めずに始めると、いつまでも終わりません

この本の中心はここです。

> **導入の失敗は、たいてい「台帳に載っていないものがある」という形で出ます。**
> 2026-08-17 に、契約書もメールもあるのに台帳に無い支払（3,190,000円・期限48日超過）が
> 見つかりました。健康診断にも遅延にも一切出ていませんでした。
> **台帳に無いものは、どの画面にも出ません。**導入で一番手を掛けるべきは、この「載せ切る」作業です。

## 1. 役割分担

| 誰 | 何を | いつ |
|---|---|---|
| **管理者** | Claude Team 契約・プラグイン配布・運用モードの決定 | 第1部（30分） |
| **経理担当** | 拡張のインストール・接続・初期設定・**データ移行** | 第2〜3部＋移行（数日〜数週） |
| **経営** | 運用モードの承認・並行稼働の終了判断・**未回収/未払の扱いの決定** | 判定時 |
| **顧問税理士** | 会計方式・税区分・課税方式の選択 | 移行前に1回 |
| **提供元（AI OSI URI）** | キットの提供・詰まったときの支援 | 随時 |

**書き込む人は1人に決めてください。**台帳は xlsx で、同時編集の統合手段がありません。
見るだけの人には運用モード「参照専用」を設定します。

## 2. 準備するもの

| サービス | 必須/任意 | 用途 |
|---|---|---|
| Claude（**Team プラン**） | 必須 | 組織へのプラグイン配布に Team/Enterprise が要る |
| Google Workspace（**共有ドライブ**）＋ デスクトップアプリ | 必須 | 台帳・契約書・証憑の保管 |
| マネーフォワード クラウド請求書 | 請求書を発行するなら必須 | 採番・適格請求書・PDF |
| マネーフォワード クラウド会計 | 任意 | 突合の相手。**損益の正本はローカル仕訳帳**なので、無くても動く |
| Superhuman | 条件付き | **メール添付の請求書を自動取込する場合のみ**。標準 Gmail では添付を取得できない |
| DocuSign | 契約を電子署名で送るなら | Integration Key と RSA キーペアが要る（`contract-docusign-send/references/setup.md`） |

**手元に用意しておくもの**（設定の対話で聞かれます）

- 会社名・インボイス登録番号（T＋13桁）・本店住所
- 入金用の銀行口座
- **決算月**（1〜12）— 申告期限のアラートに使います
- 台帳を置くフォルダの**絶対パス**（これが唯一の必須設定）

## 3. 導入の手順

クリック単位は `導入手順書.md` に譲ります。ここでは**順序と、つまずく場所**だけ。

1. **管理者**：Team 契約 → プラグイン ZIP を組織にアップロード →「既定でインストール」
2. **担当者**：`.mcpb` をダブルクリックして拡張を入れる
3. **担当者**：コネクタを接続（Drive / Gmail または Superhuman / MF）
4. **担当者**：Cowork に「**OSI Finance の MF 連携をして**」→ 画面操作つきで OAuth を通す
5. **担当者**：Cowork に「**OSI Finance を導入して**」→ 設定ファイル・フォルダ・台帳を作る
6. **担当者**：スケジュールを登録し、**一度「今すぐ実行」を押す**（接続の許可を先に済ませる）

> **設定を保存したら、Claude Desktop を完全に終了して開き直してください。**
> 設定はプロセス起動時にしか読まれません。閉じ直さないと、コンソールは開くのに
> 全タブが読込エラーになります（Mac は ⌘Q、Windows はタスクトレイからも終了）。

### 自動実行の目安

| いつ | 何を |
|---|---|
| 毎朝 | 契約取込／払い忘れチェック |
| 毎月1日 | 請求書ドラフト |
| 毎月3日 | 月次クローズ |
| 毎月25日 | 支払予定の確認 |

**どれも「検出・下書き・報告まで」**です。送金も台帳の確定もしません。

## 4. 既存データの移行 — ここが本番

**新しく始める会社でない限り、ここが導入の大半です。**

### 4-1. どこまで遡るか決める

全部遡る必要はありません。**「いま生きているもの」と「今期の実績」**が入っていれば動きます。

| 対象 | 遡る範囲の目安 | 理由 |
|---|---|---|
| 契約 | **いま有効なもの全部**（終了済みも直近1年） | 請求予定の展開元になる |
| 請求 | **未回収は全部**＋今期の入金済 | 未回収が漏れると督促できない |
| 支払 | **未払いは全部**＋今期の支払済 | **未払いの漏れが一番痛い**（期限が過ぎる） |
| 経費 | 今期分 | 消費税と決算に効く |
| 仕訳 | 今期分 | 損益の正本になる |

### 4-2. 契約から入れる（順序が大事）

**契約 → 請求予定 → 請求実績 → 支払 → 仕訳**の順です。逆から入れると紐付けができません。

契約を入れるとき、**取引先IDを必ず採番してください。**ここを空にすると、あとで契約と支払が
繋がりません。実際、取引先IDを空のまま登録した契約は、支払実績と自動で紐付きませんでした。
名前で寄せるのは不可です（「株式会社ジャビックス」と「ジャビックス」のように必ず揺れます）。

### 4-3. 契約書ファイルのパスを台帳に書く

契約書PDFを Drive に置くだけでは足りません。**台帳の `契約書ファイル` 列にパスを書いてください。**
書いていないと、コンソールから開けず、「契約書があるのかないのか」が台帳から読めません。

同じことが受領請求書（`受領請求書ファイル`）にも言えます。**起票の瞬間に書くのが唯一確実**です。
あとから遡って突き合わせると、ファイル名から相手を特定できないものが大量に残ります
（45行を遡って7行しか埋まらなかった実績があります）。

### 4-4. 載せ切れたかを確認する

移行が終わったら、**要確認事項タブを開いて0件に近づける**のが実質的なゴールです。
0にならない項目は、「なぜ残すのか」を説明できる状態にしてください。

## 5. 受け入れ判定 — これが揃ったら「導入できた」

`受け入れ試験シナリオ.md` の試験を通したうえで、**業務として**次を確認します。

### 必須（これが欠けたら本番に出さない）

- [ ] **未回収の合計が、経理担当の認識と一致する**
- [ ] **未払いの合計が一致し、支払期限を過ぎたものが正しく赤く出る**
- [ ] 有効な契約の件数が実態と一致する
- [ ] 月初の請求ドラフトが**宛先未設定で止まらない**（要確認事項の「請求先メールが未設定」が0件）
- [ ] 台帳を Excel で開いたまま書き込むと**拒否される**ことを1回試した
- [ ] `_backup/` に世代バックアップができている
- [ ] 書き込む人が1人に決まっている

### 望ましい（無くても運用は始められる）

- [ ] 契約と支払が取引先IDで繋がっている（契約一覧の「🔗 紐づく支払」が0件でない）
- [ ] 契約書・請求書のファイルパスが台帳に入っている
- [ ] 決算月を設定し、申告期限のアラートが出る状態
- [ ] 消費税の見込みが出て、税理士と幅を共有できている

**「要確認事項が0件」は判定基準に入れていません。**実務では常に何かが残ります。
大事なのは0にすることではなく、**残っているものを説明できること**です。

## 6. 立ち上がりの最初の1ヶ月

**必ず起きること**を先に知っておくと、事故に見えません。

| いつ | 起きること | どうするか |
|---|---|---|
| 初月の1日 | 月初の請求ドラフトが**途中で止まる** | 宛先未設定の契約があるため。前月末に要確認事項を潰しておく |
| 初月の随時 | 「下書き済」のまま滞留する | Gmail で送ったら**画面で「請求済」に進める**。ここを飛ばすと送ったか分からなくなる |
| 初月の月末 | 支払の期限超過が出る | 移行で載せ切れなかった請求書が見つかる。**これが移行の答え合わせ**です |
| 翌月上旬 | 仕訳と会計SaaS が合わない | 科目名の違い・ポイント値引の扱いなど。**差の理由を1つずつ記録**する。同じ調査を二度やらないため |

**並行稼働は1ヶ月**を目安に。1回の月次クローズを通せば、抜けは大体出ます。
従来のやり方を止める判断は、**未回収と未払いが両方一致した時点**が目安です。

## 7. 切り戻し

**戻せる状態を作ってから始めてください。**

### 戻し方（軽い順）

1. **台帳を1世代戻す** — `_backup/` に世代バックアップがあります。**現在の台帳を先に別名でコピー**してから戻す
2. **運用モードを「参照専用」にする** — 書き込みを全部止める。原因を調べる間の応急処置として有効
3. **拡張を無効化する** — Claude の設定 → 拡張機能。台帳ファイルはそのまま残ります
4. **導入前に戻す** — 台帳フォルダごと退避し、従来のやり方に戻る

### 戻す前に必ず

- **いま何が起きているかを控える**（画面・数字・操作ログ）。戻すと消えます
- **台帳に書き込みが進んでいないか確認する。**戻すとその分の作業が消えます

### 戻せなくなるもの

- **送信済みのメール**（請求書の送付）
- **DocuSign で送った封筒**（無効化はできますが、相手には届いています）
- **実行した振込**

だから**この3つは必ず人が実行する**設計になっています。AI が勝手に送ることはありません。

## 8. 困ったとき

| 症状 | 原因と対処 |
|---|---|
| 台帳が見つからない | 設定のパスを確認。前後に引用符が入っていると読めない。xlsx のまま置く（スプレッドシートに変換しない） |
| 全タブが読込エラー | 設定後に Claude を**完全終了していない** |
| 台帳が使用中で書けない | 誰かが Excel で開いている。**正しい動作**です |
| メール添付の請求書が取り込めない | Superhuman の接続が必要（標準 Gmail では不可） |
| 会計データが見えない | MF の「データ連携 ＞ 登録済一覧」で銀行・カードの連携状況を確認 |
| 設定をやり直したい | Cowork に「OSI Finance の設定をやり直したい」 |
| 画面が古い版のまま | **拡張は自動更新されません。**ポータルから新しい `.mcpb` を取り直して入れ直す |
