# OSI Finance 運用ルール

台帳をローカルの Excel で持ち、複数人で使うための決めごと。導入が済んだら、経理に関わる全員がこれだけ読めばよい。

## 1. 台帳はどこにあるか

拡張の設定で指定したフォルダ（例 `06.会計`）に、Excel が3つ置いてある。

```
請求管理台帳.xlsx   契約・請求（AR）
支払管理台帳.xlsx   支払先・支払（AP）・経費・源泉
仕訳台帳.xlsx       仕訳・勘定科目・月次サマリ
コンソールを開く.html  ← 画面を開くとき、これをダブルクリック
```

Google Drive などの同期フォルダに置いてあれば、他のメンバーにも同じファイルが見える。

## 2. 書き手は1人

**これが一番大事なルール。**

同期フォルダは同時編集を解決しない。2人が同時に書くと「競合コピー」が生まれ、どちらかの更新が消える。ファイル名に相手の名前が付いた複製が増えていたら、それが起きたサイン。

なので、**台帳に書き込むのは常に1人**に決める。他のメンバーは見るだけにする。

見る専門の人には、拡張の設定で **運用モード＝`参照専用`** を入れてもらう。コンソールから更新ボタンが消え、チャット側から書き込もうとしても拒否される。うっかり書いてしまう事故が起きなくなる。

## 3. Excel で台帳を開いたままにしない

誰かが Excel で台帳を開いていると、拡張は書き込みを拒否する（ロックファイルを見ている）。

```
台帳が Excel で開かれています（請求管理台帳.xlsx）。閉じてから再実行してください
```

このメッセージが出たら、開いている人に閉じてもらう。同期フォルダの場合、**他の人が開いていても自分の環境からロックが見える**ので、自分は開いていないのに出ることがある。

Excel で直接編集するのは避けて、コンソールかチャットから触るほうが安全。

## 4. 画面（コンソール）の開き方

台帳フォルダの **「コンソールを開く.html」をダブルクリック**するのが一番早い。ブラウザで開いたら、ブックマークしておくとよい。

見失ったら、Cowork で「コンソールを開きたい」と言えば URL が返る。

**Claude Desktop を起動している間しか開けない。** ブックマークが繋がらないときは、まずそこを疑う。

### 起動用ファイルは「最後に起動したPC」のものになる

台帳フォルダを複数人で共有している場合、`コンソールを開く.html` は**起動したPCのURLで上書きされる**。
別のPCで開くと繋がらないので、そのときは Cowork で「**コンソールを開きたい**」と言えば自分のPC用のURLが返る。
（ファイル自体もポートを探しにいくので、ポートが変わっただけなら自動で繋がる。）

このファイルには**そのPC用のアクセストークンが入っている**。コンソールは `127.0.0.1` にしか
待ち受けていないので、他人のPCからは接続できない（トークンを知っていても届かない）。ただし
共有フォルダに置かれる以上、Drive の版履歴にも残る。**気になる場合はこのファイルを消してよい。**
消しても「コンソールを開きたい」で毎回URLを出せる。

なお、トークンそのものの保存先は各PCのホーム配下（`~/.config/ai-osi-uri/`）で、**同期フォルダには
置かれない**。

## 4-9. コンソールの開き方（複数人で使う場合）

台帳フォルダの **「コンソールを開く.html」** を開けば、**誰のPCからでも自分のコンソールが開きます**。
このファイルに個人の情報は入っていないので、共有フォルダに1枚あれば全員が使えます。

コンソールは **Claude Desktop が起動している間だけ** 開けます。繋がらないときは、まず
Claude Desktop が動いているかを確認してください。Cowork で「コンソールを開きたい」と言っても
URL が返ります。

> 2026-08-13 まで、このファイルには起動したPCのトークンが埋め込まれており、
> **後から Claude Desktop を起動した人が上書きして、他の人が開けなくなる**という問題がありました。
> トークンそのものを廃止したので、いまは起きません。

## 4-10. 台帳のバックアップは、台帳フォルダの中に置かない

**手動でコピーを取るなら、台帳フォルダの外（`99.資料/` など）に置いてください。**
`支払管理台帳_backup_20260814.xlsx` のようなファイルを台帳フォルダの直下に置くと、
同じタブ名を持つファイルが2つになり、コネクタが**どちらを触ればいいか決められなくなります**。

```
タブ「月次支払管理」が複数の台帳にあります:
  支払管理台帳.xlsx / 支払管理台帳_backup_20260814.xlsx
```

そもそも**手動バックアップはもう不要**です。台帳に書き込むたびに、コネクタが自動で
世代バックアップ（直近10世代）を `~/.local/share/ai-osi-uri/backup/` に取ります。
同期フォルダの外なので、Drive の版履歴を汚しません。

## 4-11. 「台帳が使用中で書き込めません」と出たとき

台帳への書き込みは、**Excel で開いていると止まります**（壊さないための仕様）。次の順で確認してください。

1. **Excel で台帳を開いていないか。** 開いていれば閉じる
2. 閉じているのに言われる場合、同じフォルダに **`~$請求管理台帳.xlsx`** のような
   ファイルが残っていないか。Excel が異常終了すると残ります。**消して構いません**
3. それでも出る場合は、**Google Drive の同期やウイルス対策ソフト**が一瞬掴んでいることがあります。
   コネクタ側で数回リトライしますが、駄目なときは少し待って再実行してください

**書き込みに失敗しても台帳は変更されません。** 書き込み前のバックアップは
`~/.local/share/ai-osi-uri/backup/` に直近10世代あります。

## 5. コンソールとチャットの使い分け

**コンソール**は、見ることと、ステータスを直すこと。契約・請求・支払・支払実績・経費・仕訳・各種マスタが一覧できる。請求を「請求済」にする、支払を「支払済」にする、といった状態の更新はここから。

**チャット**は、作ることと、外に出すこと。請求書 PDF が届いたら Cowork にドロップして起票、契約書から請求スケジュールを展開、仕訳の生成、MF との突合、DocuSign 送付。

コンソールの「DocuSignで送る」「MFと突合」のようなボタンは、押すと**プロンプトがクリップボードにコピーされる**。それを Cowork のチャットに貼ると、そこで実行される。コンソール自体は 127.0.0.1 のブラウザページなので、DocuSign にも MoneyForward にも届かない。実行される場所がチャットなのは、人の目が一度入るという意味でもある。とくに DocuSign の送付は取り消せないので、署名者を提示して確認を取るまで送らない。

## 5-1. 送付日は「送付日」列に記録する

請求書をメールで送ったら、**「送付日」列に送信日を入れます**（2026-08-14 に追加）。
`sheets_update_status` の `sent_date` がこの列に書きます。

> 以前は「送付日」列が無く、`sent_date` を指定すると**隣の「送付請求書ファイル」列**
> （PDFのファイル名）に日付が書き込まれ、ファイル名が消えていました。2026-08-14 に修正済みです。
> 列が無い台帳では、書かずに `skipped` として報告します。

## 5-2. 「下書き済」は、送ったという意味ではない

ステータスの `下書き済` が表すのは「**Gmail の下書きを作った**」ことだけで、送ったかどうかは分からない。
下書きのまま止まっていても、送信済みでもこのラベルになる。

**送ったかどうかの正本は Gmail の送信済み**（`in:sent` で検索できる）。台帳のステータスだけを見て
「まだ送っていない」と判断してはいけない。

逆に、送ったのにステータスが `下書き済` のまま残ると、月次の売上計上や督促の判断がずれる。送信したら
コンソールのボタンで `請求済` に進めること。溜まったときは Gmail の送信済みと突き合わせて一括で直せる。

2026-08 の棚卸しでは16行の `下書き済` のうち、**14行が送信済みで台帳が追いついていないだけ、2行が本当に
未送信**だった。未送信の1件は 3,300,000 円が期限19日前まで放置されていた。

## 5-3. 発行した請求書PDFは控えを残す

送付した請求書PDFは `{送付請求書}/YYYY-MM/` に必ず残す（`YYYY-MM` は請求月＝請求書番号と同じ月）。
メールに添付して送っただけだと、手元に控えが残らない。台帳の「送付請求書ファイル」列にファイル名を
書いたのに実体が無い、という状態になる（2026-08 時点で16件・884万円分がこれに該当した）。

## 6. バックアップ

台帳に書き込むたび、書く直前の状態が自動でバックアップされる。保存先は `~/.local/share/ai-osi-uri/backup/`（同期フォルダの外）。既定で10世代。

**同期フォルダの外に置いてあるのは意図的。** 台帳の隣に置くと、書き込みのたびに同期が走って鬱陶しいため。

間違えて上書きしたときは、ここから戻せる。

## 7. MoneyForward との関係

**請求書の発行**は MF クラウド請求書が担う（採番・適格請求書フォーマット・PDF）。台帳は番号と状態を持つ正本。

**会計への計上**は MF クラウド会計。台帳と突合して計上漏れを検出する。

どちらも任意。使わないなら台帳だけで完結する。

MF の接続が切れたら、Cowork で「MF を接続して」と言えばリンクが返る。開いて許可を押すだけ。権限に「書き込み」が含まれることを確認すること（「参照」だけだと請求書を発行できない）。

## 8. やらないこと

**送金しない。** 振込は必ず人がネットバンキングで行う。台帳は「いくら払う予定か」「払ったか」を記録するだけ。

**台帳の状態を勝手に確定しない。** 請求済・入金済・支払済への遷移は、人のボタン操作か、銀行明細で裏取りできた場合に限る。スキルが推測で進めることはない。

**ステータスを勝手に戻さない。** 差し戻し（入金済 → 未請求 など）は人の操作のみ。

## 9. 困ったときの見分け方

| 症状 | 見るところ |
| --- | --- |
| コンソールが開かない | Claude Desktop が起動しているか。「コンソールを開く.html」から開き直す |
| 台帳未接続と出る | 拡張の設定の台帳フォルダのパス。前後に引用符が入っていないか |
| 書き込みが拒否される | Excel で台帳を開いていないか。運用モードが参照専用になっていないか |
| 「読み取り後に台帳が変更されています」 | 誰かが同時に書いた。コンソールを再読込してやり直す |
| 請求書の発行が 403 | MF の権限が読み取りのみ。「MF を接続して」で write を含めて再認可する |
| 競合コピーが増えている | 書き手が複数になっている。§2 を決め直す |
