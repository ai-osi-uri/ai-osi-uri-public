# 型 2：契約 → 請求 → 月次

## いつ
契約書（PDF）が届いた／月初に当月分の請求書を出す／月末に経理を締める。3 つの入口があるが、同じ台帳の上を流れる。

## 入力
- 契約書 PDF（Gmail に届く、または手元）
- 請求管理台帳・支払管理台帳（`{{paths.finance}}/`。無ければ `osi-finance-setup` が作る）
- 会計 SaaS の口座連携（MoneyForward。無ければローカル仕訳帳で回す）

## 連鎖
| # | スキル | 渡すもの → 受け取るもの |
|---|---|---|
| 0 | `osi-finance:osi-finance-setup`（初回だけ） | 5〜7 問 → `osi-finance-settings.md`・台帳 3 本・規定フォルダ |
| 1 | `osi-finance:osi-finance-contract-intake` | 契約書 PDF → 契約書フォルダに格納、契約マスタに 1 行、契約期間分の「月次請求スケジュール」行を展開 |
| 2 | `osi-finance:osi-finance-invoice`（月初） | 当月の未請求行 → 請求書 PDF（`送付請求書/YYYY-MM/`）＋ Gmail 下書き（PDF 添付）。台帳「下書き済」 |
| 3 | 人が送信 → `osi-finance:osi-finance-payment-detect` / `payment-intake` | 送信済み・受領請求書 → 台帳の請求済／支払予定の起票 |
| 4 | `osi-finance:osi-finance-ar-sync`（月末） | 台帳の請求済・入金済 ↔ MF の仕訳・**口座連携の明細** → 計上漏れ・消込漏れの一覧 |
| 5 | `osi-finance:osi-finance-mf-sync`（月末） | 支払管理台帳の支払済 ↔ MF の仕訳 → 未計上の一覧（登録は人レビュー後） |
| 6 | `osi-finance:osi-finance-monthly` | ①明細取込確認 → ②仕訳化 → ③突合 → ④残高試算表で検算 → ⑤月次報告。MF を使わない組織は `osi-finance-journal` でローカル仕訳帳に記帳 |

## 止まる場所
- 契約の取込結果（金額・期間・請求先）の確認。`WRITE_CONFIRMATION` が事前確認なら台帳反映の前、事後確認なら反映後に見る
- 請求書の送信（**Gmail の下書きを送るのは人**。AUTO_SEND=ON でも送信ゲート 6 点を通ったものだけ）
- MF への未計上の登録（一覧を見てから）
- 振込（**送金は人。スキルは振込情報を整形するまで**）

## 出口
- 台帳 3 本（契約マスタ／月次請求スケジュール／支払管理）が当月分まで埋まり、MF と一致している
- `送付請求書/YYYY-MM/` に請求書 PDF、Gmail に送信済み
- 月次報告（売上・費用・未収・未払の 1 枚）

## 完了条件
- 送金と台帳の自動確定はしていない（人が押した記録がある）
- 請求書の登録番号・宛名の正式名称・税率ごとの対価と消費税額・合計が台帳と一致（1 つでも欠けたら添付しない）
- 入金は仕訳ではなく口座連携の明細で裏取りしている
- 突合の「未計上」に人のレビュー記録があり、重複登録がない
- 機微値（口座・登録番号）がチャットに残っていない（設定ファイルにだけある）

## よくある事故
- 請求日の規則を途中で変え、古い行を直さず当月分が一覧から消える
- MF の仕訳だけ見て「入金が無い」と誤報（明細を見れば入っている）
- フォールバック（ローカル生成）が黙って発動し、3 経路 4 レイアウトの請求書が混ざる → 落ちたら必ず報告する
