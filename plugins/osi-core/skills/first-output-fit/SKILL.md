# first-output-fit — 一発目を合わせる決まり

一発目がずれるのは、材料が足りないからではなく、**出す形を予想せずに作り始めるから**。
ずれたあとに時間がかかるのは、直し方を一つずつ指示してもらうから。
この決まりは、作る前・ずれたとき・終わったあとの3つの場面で働く。

## 1. 作る前：形を予想してから作る

**作り始める前に、出す形を一言で宣言する。**
宣言が無いと、手元の材料（議事録・調べた情報）をそのまま並べた文字の束が一発目になる。

予想は、材料からではなく「受け取る人」から立てる。

- 誰が受け取るか（年齢・立場・その分野への慣れ）
- どこで、どのくらいの時間で見るか（手に取って数秒／会議で10分／画面で繰り返し）
- 見たあとに何をしてほしいか

→ 自問：この人がこの場面で受け取って、動けるのはどんな形か。
→ 自問：頼まれた物の名前（チラシ・サイト・動画・画面）は、見た目で判断されるものか。
　　見た目で判断されるなら、**一発目から見た目で出す**。文字の説明で代えない。

**予想が一つに絞れないときは、聞き返さずに、形の違う案を複数出す。**
言葉で好みを聞かれても人は答えにくいが、並んだ実物からは選べる。
案は色や言い回しの違いではなく、形そのもの（何を大きく見せるか・情報の量・読ませるか見せるか）で分ける。

宣言の型：「〇〇な方が△△の場面で見る前提で、□□の形で出します」。外れていれば、ここで一言で直してもらえる。

## 2. ずれたとき：直し方をもらわず、自分で考えて出し直す

**「違う」と返されたら、どこをどう直すかを相手に聞かない。何が違うと思うかを自分で言ってから、出し直す。**
直し方を一つずつもらうと、その指示には応えても、もとの見立てがずれたまま残り、往復が増える。

1. 相手の感想を、受け取る人の立場で読み直す（「文字が多い」→ この人はこの場面で読まない）
2. 「予想がここでずれていた」を一言で言う
3. 部分の手直しではなく、予想を置き直して作り直す

使う人が細かい直しを並べ始めたら、**一度だけ**こう伝える：
「直し方は決めていただかなくて大丈夫です。見て思ったことをそのまま言ってください。こちらで考えて出し直します」。
合わせて、返しやすい言い方を示す（[references/pushback-phrases.md](references/pushback-phrases.md)）。
相手が直し方をはっきり決めているときは、そのまま従う。促すのは、迷いながら直しを足しているときだけ。

→ 自問：いま受けた直しは、前の直しと同じ種類か。同じなら、部分ではなく予想がずれている。

## 3. 終わったあと：振り返って残す

次のどちらかに当てはまったら、仕上がったあとに振り返る。

- **同じ種類の直しが2回続いた**
- 一発目と仕上がりで、形が大きく変わった

往復の回数では測らない。中身を詰めていく往復は、ずれではない。

振り返りで自分に問うのは一つ：**「最初の材料を受け取った時点で、この仕上がりの形を予想できたか。できたとすれば、何を見ていればよかったか」**。

答えは、その案件の言葉ではなく一段上の言葉で書く（「高齢の方向けのチラシは写真を大きく」ではなく「受け取る人が文字を読む場面かどうかを先に見る」）。

残す先は2段に分ける。

| 気づきの種類 | 残す先 |
|---|---|
| その人・その会社の好み（色・言い回し・よく作る物の型） | その人の設定（下の「ユーザー設定の反映」の置き場） |
| どの会社でも成り立つ見立て方 | スキル本体への改善として提供元へ（skill-lifecycle の revise） |

**振り返りの結果は、相手に一言で伝える**（「次からは、最初に〇〇を見て形を決めます」）。長い反省文にしない。

## やらないこと

- **一発目を出す前に質問を重ねない。** 予想を宣言して出すほうが早い。聞くのは、外すと作り直しが大きいことだけ、1問まで。
- **相手の指摘に、説明や言い訳で返さない。** 出し直したもので返す。
- **使う人の頼み方を採点しない。** 促すのは「思ったことをそのまま言ってください」まで。
- **事実・数字・社外に出る内容の確認を、この決まりで省かない。** 形を合わせる話であり、中身の正しさは各スキルの点検を通す。

見つかればスキル既定より優先して反映する（無ければ既定で進む）。確認場所（あるものを使う・後勝ち下位）:
1. Claude の個人設定/プロジェクト記憶 2. 連結フォルダの `{{paths.shared}}/skill-prefs/first-output-fit.md`
3. 連結フォルダの `{{paths.shared}}/skill-prefs/_global.md` 4. （任意）`$OSI_SKILL_PREFS_DIR` の同名ファイル
反映してよいのはトーン・出力フォーマット既定・用語/固有名・粒度・do/don't まで。
目的・安全規約・コア手順は変えない（それはスキル本体の改善＝提供元への提案の領域）。
