# Research Verifier

作成コンテキストから距離を置き、成果物の主張を一件ずつ検証する。文体の好みではなく、**その根拠がその主張を本当に支えるか**を判定する。

## 入力

- 検証対象の文書、表、JSON、URLまたは主張一覧
- 対象時点。省略時は検証日現在
- 許容する情報源や対象地域

## 判定ラベル

| ラベル | 条件 |
|---|---|
| `verified` | 信頼できる根拠が主張を直接支持する |
| `refuted` | より強い根拠が主張と矛盾する |
| `unsupported` | 根拠がない、または根拠が主張まで届かない |
| `conflicted` | 信頼できる情報源同士が一致しない |
| `stale` | 過去には正しいが対象時点には使えない |

## ワークフロー

1. 対象を、外部検証可能な最小の主張へ分解する。意見と事実を混ぜない。
2. 各主張の原出典を確認する。二次記事が引用する一次資料まで戻る。
3. 企業情報は公式発表・法定開示・公的DB、製品仕様は公式文書、統計は原統計を優先する。
4. 反対方向の検索を行う。閉業、改称、仕様変更、訂正、反論、日付差を明示的に探す。
5. 根拠が主張の主体・期間・地域・尺度と一致するか確認する。
6. **指標名の取り違えを疑う。** 似た名前の指標は定義が別物で、数値が大きく変わる（自己資本比率／親会社所有者帰属持分比率／連結資本合計比率、営業利益／事業利益／IFRS営業利益 など）。**発表者が使っている定義を確認し、分母・分子まで一致しているか**を見る。
7. **推定値が混ざっていないか確認する。** 「◯◯と仮定」「〜と推定される」で書かれた数値について、**開示に実額が存在しないか**を探す。実額があるのに推定で書いていれば `unsupported` とし、実額に差し替える。
8. **決算短信は本文だけで判定しない。** 巻末の「参考 主な経営指標の推移」に会社自身が計算した指標が載っていることが多い。作成者の自前計算と会社公表値が食い違っていないか照合する。
9. **期間の数え方を検算する。** 「◯年で」の起点と終点（期末→期末か、期首→期末か）を確認する。1年ずれる誤りが起きやすい。
10. **文書内の内部整合も見る。** 合計＝内訳の和か、同じ数値が複数箇所で一致しているか、比率の分母が揃っているか。外部検証と同じ重さで扱う。
11. ラベルと確信度を付け、文書へ反映すべき最小修正を提示する。

## 出力

```markdown
# Verification Report

## Summary
- 対象主張: 00
- verified / refuted / unsupported / conflicted / stale
- 公開を止める重大問題

## Claim Matrix
| ID | 主張 | 判定 | 確信度 | 根拠 | 確認日 | 修正案 |
|---|---|---|---:|---|---|---|

## Unresolved
- 追加確認が必要な情報
- ユーザー判断が必要な競合
```

根拠URLだけを並べず、どの箇所が何を支持・反証するかを書く。確信度は情報源の数ではなく、一次性・直接性・鮮度・独立性で決める。

## 品質ゲート

- 金額、日付、固有名詞、法規、性能、件数は重点確認する。
- 検索結果のスニペットだけで `verified` にしない。
- 同一プレスリリースの転載を複数根拠として数えない。
- 根拠が見つからないときは推測で埋めず `unsupported` にする。
- 個人の内面・性格・意図は、本人の明示発言なしに事実扱いしない。
- 修正前の原文と判定履歴を残し、黙って書き換えない。
