# 秘書への進み具合の報告（secretary-report）

## なぜ Claude の側から書くのか

秘書は Claude の会話を読みに行けない（外から読む公式の口が無い）。だから **Claude が作業の区切りで、要点だけを秘書に書き込む**。
会話をまるごと渡さないので、社外秘や取り下げた案は混ざらない。秘書はそれを件に結びつけ、LINE などで関係する人に知らせ、
「○○どうなってる？」と聞かれたときに答える材料にする。

## いつ報告するか

- 成果物ができた（資料・アプリ・文面・調査のまとめ・設定）／外に出した（送った・デプロイした・公開した）
- 途中で止まった（相手の返事待ち・本人の判断待ち・鍵が無い）— 止まった理由と、次に誰が動くかを書く
- 1つの作業につき1回。細かい手順ごとには報告しない
- 案件・業務に結びつかない作業（雑談、一般的な質問への答え）は報告しない

本人が「報告しないで」「これは秘書に入れないで」と言った作業は報告しない。

## 書き方（report）

3〜5行の普通の言葉で、この順に書く。

1. 何をやったか（成果物の名前）
2. どこまで済んだか（できた／送った／途中）
3. 次に誰が何をするか（本人が確認する、先方の返事待ち、など）

書かないもの：お金の数字・社外秘・相手の内情の分析・内部の言葉（card_id、関数名など）。
成果物に開けるリンクがあれば `links` に入れる（本文に貼らない）。相手先が分かれば `account` に入れる。

## 呼び方

| 引数 | 値 |
|---|---|
| project_ref | `{{secretary.project_ref}}` |
| member | `{{secretary.member}}`（空なら省いて `email` に本人の会社メール） |
| report | 上の書き方の本文 |
| account / links | 分かれば |

- `{{secretary.project_ref}}` が空、または道具 `secretary_report` が無いときは、報告せずに「秘書の置き場が未設定」と1行だけ伝えて終わる（作業そのものは止めない）。
- 返ってきた `secretary_said` は、本人に1行で伝える（例「秘書の『○○』の件に記録しました」）。秘書の返事をそのまま長く貼らない。

## 当てはまる件が無いと言われたら

秘書は件を勝手に増やさない。返ってきた候補を見て、

- 候補に当たる件があれば、その番号を `card_ids` に入れて呼び直す
- 無ければ本人に「秘書に『相手先｜やること』の件として作って記録しますか？」と1回だけ聞く。OK なら
  `open_if_missing: true` と `title` を付けて呼び直す。不要と言われたら報告しない

## 失敗したとき

道具のエラーは本人に1行で伝え、作業の結果そのものは普段どおり渡す。報告のために作業の返事を遅らせない。
