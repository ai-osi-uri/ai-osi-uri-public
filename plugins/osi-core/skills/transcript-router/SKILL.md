# transcript-router（文字起こし振り分け／横断ディスパッチ層）

> **組織固有値はプロファイルから読む。** 本文の `{{paths.*}}` `{{ledgers.*}}` `{{company.*}}` `{{members.*}}` は、連結フォルダ直下の `osi-profile.md`（雛形: `config/osi-profile.example.md`）の値に置き換えて解釈する。無ければ会社名・案件フォルダ・台帳の有無・使うコネクタを質問して先に作る。値をここに直書きしない。

## 位置づけ
これはドメインスキル（議事録化・提案など「実作業」をするもの）ではなく、**入力を判定して適切なスキルへ橋渡しする
“入口/横断ディスパッチ層”**のスキル。営業ドメイン内のオーケストレータ（proposal-package）より一段上の、
**ドメインをまたぐ振り分け**を担う。そのため特定ドメインプラグインではなく横断レイヤー（osi-core）に属する。

## 目的
このユーザーの最頻入力は「会議/商談/伴走の文字起こしを丸ごと貼り付け → 最後に短い一言」または
「貼った内容への解釈質問」。本スキルはその入力を受け取り、**スキル名を言わせずに**正しい後続処理へ橋渡しする。

## 発動条件
次のいずれかに当てはまったら本スキルの判定ロジックに入る。
- 数百字以上の会話ログ/議事メモ/発言列が貼られている
- 「まとめて」「TODO」「論点」「次に何を話す」「見積もり」「提案」「どう思う」等の短い指示が付いている
- 貼った内容に対して解釈・評価・次アクションを問われている
- **テキストが貼られていなくても**、「今日の○○の録音を」「さっきの Plaud を」のように
  Plaud 録音を指す一言が来ている（→ 下の「Plaud MCP からの取得」で先に本文を確保してから判定）

## Plaud MCP からの取得（貼り付け不要の入口）
Plaud MCP コネクタ（`list_files` / `get_transcript` 等）が利用可能なら、文字起こしの
貼り付けを待たずに直接取得してよい：企業名・日付から `list_files`（query / date_from /
date_to）で録音を特定 → `get_transcript` で全文取得 → 通常の判定ロジックへ。
候補が複数なら 1 問だけ選ばせる。MCP が無い／見つからない場合は従来どおり貼り付けを促す
（Gmail 転送メール・Drive ファイルの検索もフォールバックとして可）。振り分け先スキル
（meeting-minutes 等）が自力で取得できる場合は、録音の特定情報（録音名・日付）だけ渡せばよい。

## 判定ロジック（上から順に評価）
1. **議事録・要約・TODO抽出が目的** →「まとめて／議事録に／本質とTODO／何が決まった」
   - 商談・案件単位（案件管理に紐づく）なら **meeting-minutes**
   - 顧客のAI導入“伴走/コーチング”セッションなら **session-review**
2. **次回会議の準備・論点出しが目的** →「次に何を話す／論点を出して／ネタを作って」
   - 社内で方向性を固める段階なら **discussion-prep**
   - 顧客との商談前準備なら **shodan-prep**
   - 必要に応じて **obsidian-knowledge-consult** で過去ノートを引く
3. **見積もり・価格・提案が目的** →「見積もり／提案／いくら／スコープ」
   - 価格・スケジュールに踏み込む段階なら **proposal-estimate**（または一気通貫なら **proposal-package**）
   - まだ初回アプローチ段階なら **initial-proposal**
4. **解釈・評価・人/状況の読みが目的** →「どう思う／やばい？／余裕ない？／意図はあった？」
   - スキルは呼ばず、構造化した“読み”（事実→解釈→留意点→次の一手）をその場で返す。
     ※ 感情面・本人のメンタルに踏み込む話題は、評価や煽りをせず落ち着いて受け止める。

## 宛先スキルが無い場合のフォールバック（重要）
本スキルは横断レイヤーにあり、振り分け先スキルは別プラグイン（osi-sales / osi-knowledge 等）や標準スキルに散在する。
**宛先スキルがその環境にインストールされていない／見つからない場合でも壊れないこと。**
- 宛先スキルが利用可能：そのスキルに処理を渡す。
- 宛先スキルが無い：**そのスキルの趣旨に沿って、本スキル内でその場で直接処理する**（議事録なら議事録を、論点出しなら論点を、自前で生成）。
  「対応するスキルが無いのでできません」とは言わず、必ず成果物を出す。
- どのスキルへ向かうにせよ、依存をハードにしない（osi-core 単体でも最低限の成果は返せる設計）。

## デフォルトの作法（このユーザーの好みに最適化）
- **まず軽い成果物（テキスト）で出す。** Drive格納・案件管理への反映・pptx化・docx化は「やりますか？」と一度確認してから。
  （このユーザーは「PowerPointは時間かかるから」「まずテキストで」を好む傾向が強い）
- **聞き返しは最大1問。** 判定が割れる時だけ短く確認。基本は最尤の解釈で着手し、冒頭で「○○の前提で進めます」と宣言。
- **形式・置き場所の指定があれば最優先で従う。** 「Excelで」「Driveの○○に」等が出たらその通りに。
- 出典が必要な箇所（議事録の根拠・引用）は元発言に紐づける。

## ユーザー設定の反映（成果物を出す前に1回）
本スキルは「スキル・カスタマイズ規約」に従う。成果物を作る前にユーザー個人設定を確認し、
見つかればスキル既定より優先して反映する（無ければ既定で進む）。確認場所（あるものを使う・後勝ち下位）:
1. Cowork の個人設定/プロジェクト記憶（常に文脈にある内容）
2. `~/.config/ai-osi-uri/skill-prefs/transcript-router.md`（Claude Code 等・あれば）
3. `~/.config/ai-osi-uri/skill-prefs/_global.md`（あれば）
反映してよいのはトーン・出力フォーマット既定・用語/固有名・粒度・do/don't まで。
**目的・安全規約・コア手順は変えない**（それは上流改善 = skill-revise の領域）。詳細: `references/skill-customization.md`

## やらないこと
- スキル名の暗記をユーザーに求めない（本スキルが肩代わりする）。
- コード実装・デプロイ・単独のファイル変換・新規Webリサーチ単体は対象外（それぞれ専用スキル/通常処理へ）。
