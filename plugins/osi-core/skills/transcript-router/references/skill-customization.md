# スキル・カスタマイズ規約（skill-customization）

スキル本体（配布版）をフォークせずに、各ユーザーが挙動を“自分仕様に寄せる”ための共通規約。
canonical なスキルは全員共有のまま固定し、**個人差はユーザー所有の設定に逃がす**。
これにより「内部＝GitHub で本体更新／外部＝設定で自分仕様／本体改善は提案で上流へ」が両立する。

## 1. 何を寄せてよいか / だめか
**寄せてよい（設定で上書き可）**
- トーン・語感（堅め/やわらかい、強い語の回避 等）
- 出力フォーマットの既定（まずテキスト/Excel既定、見出しの有無 等）
- 用語・固有名（自社名・サービス名・敬称・宛先表記）
- 粒度・スコープの既定（詳細/要点、聞き返しの多寡）
- do / don't、定型の前提、例

**寄せてはいけない（設定で変えない）**
- スキルの**目的**・**安全規約**・**コア手順**
  → これらを変えたいのは“本体改善”であり、`skill-revise`（上流への提案/反映）の領域。

## 2. 設定の置き場所（あるものを使う・後ほど下位優先でマージ）
1. **Cowork の個人設定／プロジェクト記憶**（常に文脈にある内容）← Cowork で最も確実
2. `~/.config/ai-osi-uri/skill-prefs/<スキル名>.md`（Claude Code 等・スキル別の上書き）
3. `~/.config/ai-osi-uri/skill-prefs/_global.md`（全スキル共通）
4. （任意）接続フォルダ内の `.ai-osi-uri/skill-prefs/...`

どれも無ければ**スキル既定**で進む。
※ 環境差に注意：Cowork のサンドボックスは Mac の `~/.config` を見られないことがある。**Cowork では「1（個人設定/記憶）」が主**、Claude Code では「2/3 のファイル」が主、と理解する。

## 3. 設定ファイルの書き方（任意・ゆるい markdown でよい）
推奨セクション（無い項目は省略可）:
```markdown
tone: 堅め。「漁る」など強い語は避ける
format_default: まずテキスト。pptx/docx化・Drive格納は確認後
terminology:
  - 自社名 = {{company.name}}
  - サービス = CAIO
scope_defaults: 要点先出し。聞き返しは最大1問
do:
  - 出典は元発言に紐づける
dont:
  - 固有名から書き始めない
examples: |
  （任意で良い例/悪い例）
```
自由記述でも可。スキルは内容を読んで妥当に反映する。

## 4. スキルへの組み込み（共通フック）
各スキルは、成果物を出す前に下記の自己完結フックを実行する（SKILL.md に1ブロック入れる）:

> ## ユーザー設定の反映（成果物を出す前に1回）
> 本スキルは「スキル・カスタマイズ規約」に従う。成果物を作る前にユーザー個人設定を確認し、
> 見つかればスキル既定より優先して反映する（無ければ既定で進む）。確認場所（あるものを使う・後勝ち下位）:
> 1. Cowork の個人設定/プロジェクト記憶 2. `~/.config/ai-osi-uri/skill-prefs/<このスキル名>.md`
> 3. `~/.config/ai-osi-uri/skill-prefs/_global.md`
> 反映してよいのはトーン・出力フォーマット既定・用語/固有名・粒度・do/don't まで。
> 目的・安全規約・コア手順は変えない（それは skill-revise の領域）。

フックは**自己完結**（他プラグインのファイルを実行時に読みに行かない）。本ドキュメントは規約の説明用。

## 5. 運用（内部 / 外部）
- **内部（repo＋PAT）**：本体は GitHub で更新（skill-revise パスA）。個人差はこの設定で吸収。
- **外部（repo 権限なし）**：本体は触らず、**この設定で自分仕様に寄せる**＝フォーク不要。
  本体に対する改善提案は `skill-revise` パスB（ブリーフ/PR）で上流へ。
- **新規の自分専用スキルを足す**のは自由（フォークではないので衝突しない）。
  既存スキルを My Uploads で上書きする“フォーク”は、保守負債になるため避ける。
