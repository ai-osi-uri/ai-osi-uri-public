# 初回セットアップ（getting-started）

> 案内・手順書・画面で利用者に送らせる言葉は必ず「osi-core のセットアップをはじめる」。「はじめて」と書かない（Claude 自体の初期設定 setup-claude が先に動き、このスキルが起動しない。2026-09-21 に実際に起きた）。

## §0 定義と不変条件

**導入が済んだ** とは、次の 3 点が揃い、0 段目のスキルが 1 本、実物の成果物を出した状態を指す。

1. **プロファイル** — 連結フォルダ直下に `osi-profile.md` があり、社名・案件フォルダ・台帳の場所・使うコネクタが埋まっている
2. **プロジェクトキット** — 案件フォルダの雛形・営業管理表・アプリ台帳・フォルダ規約（CLAUDE.md）があり、ダミー案件が 1 件入っている
3. **コネクタの実測** — 繋がっているコネクタを**実際に叩いて**判定した「今使える／繋げば使える」の表がある

導出の型：**聞く（5 問まで）→ 作る（無いものだけ）→ 叩く（宣言でなく実測）→ 動かす（1 本）→ 表にして返す**。

不変条件（破ったら失敗）：

- 質問は **5 問まで**。答えられない項目は既定値で作り、「あとで `osi-profile.md` を直せばよい」と伝える。質問攻めにしない
- **機微値（インボイス登録番号・法人番号・口座）はチャットで聞かない。** 空欄で作り、本人がファイルに書く手順だけ示す
- **既にあるものは上書きしない。** `osi-profile.md` も台帳もフォルダも、無いものだけ作る（`init_kit.py` が保証する）
- コネクタは **宣言ではなく実測**。ツールが見えても叩いて失敗すれば「未接続」。叩けないものを「使える」と言わない
- 完了は **成果物が出たとき**。表を出して終わりにせず、0 段目のスキルを 1 本動かして「できた」まで持っていく
- **セットアップ中は鍵の話をしない**（2026-10-10）。お試し（マネージド）が有効なら、鍵が無くても最初のアプリの公開まで動く。
  表に「鍵が要る」の列や行を作らない、「本人がやる残り」に鍵の登録を入れない、`health_check` の `uses :` 行（✕・足りない鍵・ポータルの URL）をそのまま写さない。
  鍵は、利用者が鍵の要る機能（モバイルアプリ・AI 秘書・決済・LINE・お試しの枠を超えるアプリなど）を選んだときに初めて、`osi-deploy:own-keys-setup` で 1 つずつ案内する。
  ツールポータルは**任意**として、出力の最後に 1 行だけ触れる（下の「出力」5）

進め方の見せ方（毎回の返事で守る）：

- **最初の返事で全体の地図を 1 行で出す**：「① 5 つ質問 → ② フォルダと台帳を作る → ③ つながっている道具を確かめる → ④ 練習用の会社で 1 つ動かす → ⑤ できることの一覧」
- 以後の返事は頭に **いまの位置と、これからやること**を 1 行（例：「②／5 フォルダと台帳を作ります」）。細かい手順は書かない
- 返事の最後は **「次にやること：〜」1 行**。止まって待つときも同じ
- 選ばせるときは選択肢に **「選ぶと何が起きるか」** を添える（`AskUserQuestion` の説明欄に書く）
- 最後（⑤）は、表に加えて **「次にできること」を選択肢で 3〜4 個**出す（今使える段のスキルから、「提案書のたたきを作る」「議事録をまとめる」「アプリを作って公開する」のように）。選ばれたらそのスキルに進む

事故の型（過去に起きたこと・起きうること）：案内に「はじめて」と書いて Claude 自体の初期設定（職種ボタン）が起動し、このスキルが動かない（案内の言葉は「osi-core のセットアップをはじめる」に統一）／手順書が 30 ステップに膨らんで誰も最後まで行かない／会社固有の値をスキル本文に直書きして別会社で壊れる／`.mcpb` を入れたのに古いプロセスが残って「動かない」（新しいセッションで再試行）／Drive の同期フォルダが cloud-only で bash から見えず「無い」と誤報。

## Step 1. 現状を見る（質問の前に）

1. 連結フォルダを特定する（Claude の連結フォルダ。複数あれば会社の資料が入っている方）。**無ければ、質問より先にフォルダをつないでもらう。** 返事はこれだけにして、ほかの説明（この先やること・コネクタの状態など）は書かない：

   > 最初に、作業用のフォルダを 1 つつなぎます。
   > 1. この画面の下、入力欄のすぐ下にある「フォルダを追加」を押します
   > 2. 書類を置く場所（例：「書類」や Google ドライブ）に、新しいフォルダ「Claude 作業用」を作って選びます（すでに会社の資料フォルダがあれば、それを選んでも大丈夫です）
   > 3. つないだら、このチャットに「つないだ」と送ってください。続きを始めます

   フォルダを求めるツール（例：`request_folder_access` 系）が使える環境なら、文面の代わりにそれで 1 回だけ頼む
2. `python3 scripts/init_kit.py --root <連結フォルダ> --status` で、`osi-profile.md` の有無と直下のフォルダ一覧を取る
3. 見えているツール名から、繋がっているコネクタを列挙する（AI OSI URI（マネージドのカスタムコネクタ。`health_check` / `whoami` / `list_projects` / `usage_status` と Deploy の道具が見える）/ AI OSI URI Deploy / AI OSI URI Finance / AI OSI URI Creative / Gmail / Slack / Google Drive / Calendar / MoneyForward / DocuSign / Plaud / Obsidian）。**どれも必須ではない**。このスキル自体はコネクタ無しで動く

`osi-profile.md` が**既にある**場合は Step 2〜3 を飛ばし、Step 4（実測）と Step 5（最初の仕事）だけ行う。
**同じ会話で最初の仕事をもう済ませていたら（貼り付け文のセットアップで済んだ場合など）、Step 5 は飛ばす。**不足キー（雛形にあってプロファイルに無いキー）があれば追記を提案する。

## Step 2. 4 問だけ聞く

`AskUserQuestion` で、まとめて聞く（1 問ずつ往復しない）。

| # | 質問 | 使い先 |
|---|---|---|
| 1 | 会社名（登記名）と代表者。あれば読みやすい表記（英語名など） | `company.name` `company.name_display` `company.representative` |
| 2 | 案件フォルダは**これから作る**か、**既にある**か（あるなら、案件フォルダの親と営業管理表の場所） | `layout` / `paths.projects` / `ledgers.sales` |
| 3 | 台帳の担当者列に使う自分の表記（例: 山田） | `members.owner` |
| 4 | 使うコネクタ（Step 1 で見えたものを候補に、使う／使わないを選ぶ） | `connectors.*` |

住所・ドメイン・URL・事業内容は、会社名から Web 検索で補完できるなら**補完して確認だけ取る**（質問数に入れない）。
登記名の全角/半角・スペースは登記どおりに。分からなければ本人に登記簿の表記を確認してもらう。

次の項目は**質問数に入れず空欄で作ってよい**（空欄でもスキルは既定で動く）。分かれば `answers.json` に入れる：
- `brand.*`（主色・強調色・日本語フォント・ロゴ）— 自社資料の色。サイトやロゴから補完できるなら補完して確認だけ取る。空欄なら資料は中立色で作られる
- `sales.first_meeting_goal` / `sales.proposal_policy` — 初回提案で取りたいもの・提案の考え方。空欄なら「次の打ち合わせの約束を取る」既定で動く
- `paths.internal_docs` — 社内会議・稟議向け資料の置き場（既定「共通/社内資料」）

## Step 3. 作る（無いものだけ）

回答を `answers.json` にまとめ、`python3 scripts/init_kit.py --root <連結フォルダ> --answers answers.json` を実行する。
（`--dry` で先に「何が作られるか」を見せてから実行してもよい。）

作られるもの（既にあるものは飛ばす）：

| もの | 場所（規定。`layout=existing` なら回答の場所） |
|---|---|
| 会社プロファイル | `osi-profile.md`（雛形 `assets/osi-profile.example.md` の `{{ }}` を回答で埋めたもの。機微値は空欄） |
| 案件フォルダの親と雛形 | `案件/` `案件/000.フォルダ構造テンプレート/{01_提案・見積, 02_契約, 03_制作・成果物, 04_請求, 05_受領資料}` |
| 営業管理表 | `営業管理/営業管理表.xlsx`（ヘッダ 5 行目・27 列・「マスタ」タブにステータス値） |
| 運用ルール・アプリ台帳 | `営業管理/営業管理表_運用ルール.md` `案件/_アプリ台帳.md` |
| フォルダ規約 | `CLAUDE.md`（このフォルダの読み方。案件フォルダの命名・台帳の場所） |
| ダミー案件 | `案件/122.サンプル株式会社/`（ヒアリングメモ入り）＋ 台帳に 1 行。**初回の動作確認に使い、要らなくなったら消す** |
| 経理フォルダ | `経理/`（中身は `osi-finance-setup` が作る。ここでは空フォルダだけ） |

実行後、`created` / `skipped` を人が読める形で報告する。**登録番号・口座は「`osi-profile.md` の該当行に直接書いてください」と案内する**（チャットに貼らせない）。

## Step 4. 叩く（コネクタの実測）

`connectors.*` が true のものと、Step 1 で見えたものを、**実際に 1 回ずつ叩く**。

| コネクタ | 叩くもの | 判定 |
|---|---|---|
| AI OSI URI（マネージド・既定） | `health_check` | `managed : 有効` と `tools : Deploy N 道具` → 使える。`managed : 無効` → 運用者に会社の「マネージド」を有効にしてもらう。ツール自体が無ければ「導入案内の『道具をつなぐ』の手順でコネクタを繋ぐ」 |
| AI OSI URI Deploy（ダウンロード経路） | `health_check` | `github.valid` / `vercel.valid` が true → 使える。false → 鍵が要る（拡張の設定） |
| AI OSI URI Finance | `health_check` | 台帳フォルダが読めれば使える。MF は `mfi_connect_status` |
| AI OSI URI Creative | `list_models` | 返れば使える。無い・エラーなら「今は使えない」とだけ書く（鍵の話はしない。動画を選ばれたときに案内する） |
| Gmail / Calendar / Drive / Slack | 読み取り 1 回（ラベル一覧・カレンダー一覧・最近のファイル・チャンネル検索） | 返れば使える。ツール自体が無ければ「Connectors で接続」 |
| MoneyForward / DocuSign / Plaud / Obsidian | 軽い読み取り 1 回 | 同上 |

結果を `references/tiers.md` の段に重ねて、**この環境の表**を出す：

```
| 段 | 状態 | 使えるスキル（例） | 次の一手 |
| 0 段目 | 今使える | 提案書・事業計画・ファクトチェック・ペルソナ … 40 本 | — |
| 1 段目 | Gmail ○ / Calendar ○ / Slack ✕ | 議事録→台帳、空き時間取得 … | Slack を Connectors で接続 |
| 2 段目 | AI OSI URI（マネージド）✕ / Finance ○ / Creative ✕ | 請求書発行 … | 導入案内の「道具をつなぐ」でコネクタを繋ぐ |
```

「次の一手」は、`docs/onboarding.md` の該当節（§3 マネージド（URL）・§4 Connectors・§6 ダウンロード（`.mcpb`））を **1 行で**指す。手順を本文に写さない。マネージドが既定なので、自社 MCP が無い環境ではまず §3 を指す（ダウンロード経路は本人が自分の鍵で動かしたいと言ったときだけ）。

## Step 5. 最初の仕事を 1 つ進める

練習用のサンプルではなく、**本人の仕事を 1 つ片付けて**終わる。大きな目標は聞かない（答えにくく手が止まる）。

1. **1 回だけ聞く**：「今いちばん片付けたい仕事は何ですか。近いものを選ぶか、言葉で書いてください」。例を役割ごとに添える（マネージドの道具がつながっていれば `getting_started` の「最初の仕事の例」を使う。無ければ下の表の左の列）。
   会社の台帳（AI 秘書）があれば、先に `secretary_goal`（action=open_items）で本人の未済の件を最大 3 件（件名だけ）見せ、「これを進める」も選べるようにする。
   「あとで」「特にない」ならそこで終える。二度は聞かない。大きな目標が来たら、その中で今週動かせるものを 1 つだけ聴き返す。
2. **分けて見せる**：答えを **ゴール 1 件**（終わったら何かが届く・決まる一文＋何がそろったら終わりか）と **作業 2〜3 つ**に分ける。
   1 つ目は「この会話で Claude が進められるもの」。先方への連絡・決めること・お金・社外への送付は本人の作業にする。
   見せ方の例：「ゴール：○○への提案書を商談までに仕上げる（終わり：本人が中身に OK）／1. 骨子を作る — Claude、このあとすぐ／2. 数字と事例を入れて仕上げる — Claude、骨子に OK が出たら／3. 先方に送る — あなた」。
   聴き返すのは、ゴールが 2 通りに読めて分け方が大きく変わるときだけ（1 問まで）。
3. **本人の OK のあとで置く**：台帳があれば `secretary_goal`（action=start。持ち主は本人に固定）でゴールを立てる。台帳が無ければ、この会話にチェックリストで置く（Claude のアプリならプロジェクトへの保存を勧める）。OK の前に作らない。
4. **1 つ目をその場で進める**：下の表のスキルで、本人の材料（貼ってもらった議事録・Drive の資料・会社プロファイル）から作る。材料が無いときだけ `案件/122.サンプル株式会社/` を使ってよいか聞く。
   メールの送信・公開・支払い・契約はしない。下書き・試作まで。必要な道具がつながっていなければ「これをつなぐとここまでやれます」を 1 行で言い、つながっているものだけで進める。
5. **締める**：成果物を見せ、台帳があれば `secretary_goal`（action=finish_step、`first_card_id`）で済みにする（無ければチェックを入れる）。
   「次の作業と担当」を 1 行で伝える（例：「次は骨子への OK です。LINE で秘書に『提案書の続き』と送っても進められます」）。

| 片付けたい仕事（例） | 1 つ目で使うスキル | 材料 |
|---|---|---|
| 提案書の骨子・営業資料 | `osi-docs:storyline-gate` → `osi-sales:proposal-package` | 商談のメモ・相手先の公式サイト |
| 議事録から次にやること | `osi-sales:meeting-minutes`（1 段目。無理なら `osi-core:transcript-router` に文字起こしを貼る） | 議事録・文字起こし |
| 請求書・領収書から支払の一覧／今月の入金・支払の予定表 | 本体で表にする（写真・PDF を読み、相手・金額・期日を並べる。台帳への登録は経理の初期設定 `osi-finance:osi-finance-onboarding` のあとで） | 請求書・領収書の写真や PDF、入金・支払の予定 |
| 社内のお知らせ文・募集文 | 本体で下書き（社内向けの文の書き方は会社プロファイルの決まりに沿う） | 決まりの中身・条件 |
| 受付ページ・サイト | `osi-deploy:create-app`（2 段目。マネージドも Deploy も ✕ なら `osi-deploy:local-project-output`） | 何を受け付けるか |
| 動画 | `osi-creative:ai-video-production`（2 段目。Creative が ✕ なら見送り、ほかを選んでもらう。鍵の登録には誘わない） | — |

成果物は案件フォルダ（相手先があればその案件の `03_制作・成果物/`、無ければ本人が決めた場所）に置く。
「次に繋ぐと広がること」は `../../workflows/README.md` の型 5 本（商談録音→提案／契約→請求→月次／アイデア→アプリ公開／素材→動画／議事→ナレッジ）から、片付けた仕事に最も近い 1 本を 1 行で指す。

## 出力（最後に返すもの）

1. 作ったもの／飛ばしたもの（パス）
2. この環境の段の表（Step 4）
3. 最初の仕事：ゴールと作業、1 つ目の成果物の場所、次の作業と担当（Step 5）
4. 本人がやる残り（あれば）：機微値の記入、Connectors の接続、自社 MCP の接続（URL を貼るだけ）。**各 1 行・リンク付き**。鍵の登録は入れない
5. **（任意）ツールポータル** を 1 行だけ：「クレジットの残りを見る・作ったものを自社のアカウントで持つ・鍵が要る機能を使うときは、ツールポータルの『ツール設定』から（開かなくてもこのまま使えます）」。URL は `health_check` の出力にあるポータルのものを使う
6. **次にできること**（選択肢 3〜4 個。選ばれたらそのスキルに進む）

**途中で止まるとき（フォルダ待ち・機微値の記入待ちなど）は、返事の最後を「次にやること：〜」の 1 行で終える。** 相手が次に押すもの・送るものが 1 つだけ分かる状態にする。専門用語（連結・マネージド・role_arn など）は使わない。

所要の目安は 15 分（最初の仕事を除く）。Step 1〜4 で 15 分を超えたら、Step 5 に入る前に「続けて最初の仕事を 1 つ進めますか」と聞く。
