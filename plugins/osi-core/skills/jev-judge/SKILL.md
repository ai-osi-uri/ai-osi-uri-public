# 判定をまとめてかける（jev-judge）

## 原則

- **Claude が 1 件ずつ読む代わりに、Jev にまとめて判定させる。** 1 件の費用はほぼゼロ（議事録 1 本で 1 円未満）、何百件でも 1 回で返る。
- **自信の数字で分ける。** 確定（sure）はそのまま使い、`unsure` だけ Claude が読むか人に確認する。全件を Claude が読み直さない。
- **判断の骨組みはこちらが持つ。** 計算・件数・日付の比較・金額の一致はコードか Claude が行い、Jev には「意味の判断」だけを聞く。
- **送らないもの**: 医療情報（病院・患者・検査結果）、個人情報（氏名と連絡先の組・口座など）、契約書の全文。TypeSafe 側に残りうるため。

## 呼び方

本文をどこから取るかで道具を選ぶ（中身の判定は同じ。本体は共有ライブラリ `packages/deploy-tools` の 1 か所）。

| 判定したいもの | 道具 | Claude が渡すもの |
|---|---|---|
| 会話の中の文章（数十件まで） | `jev_judge`（リモートMCP・AI OSI URI Deploy 拡張の両方） | `items: [{id, text}]` |
| Web ページ（問い合わせページ・公開後の画面） | `jev_judge` | `urls: [...]`（道具がページを取りに行く） |
| 手元のファイル・フォルダ（議事録フォルダ・Drive 同期フォルダ） | `jev_judge_files`（AI OSI URI Deploy 拡張だけ） | `paths: [...]`（道具が自分で読む。本文を会話に通さない） |

件数が多いときは、本文を会話に通さない `urls` / `paths` を優先する（Claude が本文を運ぶ費用の方が Jev より高くつく）。

1. 共通の引数:
   - `items` は最大 300 件／回、1 件 3 万字まで。id は後で対応付けに使う（URL・ファイル名・行番号）。
   - `questions`: `{問いID: {type, instructions, criteria}}`。1 回に複数の問いを混ぜてよい（安くなる）。
   - `threshold`（既定 0.8）、`noul_margin`（既定 0.2）、件数が多いときは `only_unsure: true`。
2. 鍵: リモートMCP は共用の鍵（運営が設定済み）。AI OSI URI Deploy 拡張は設定の「TypeSafe API Key（任意）」。
   道具が「鍵が揃っていません」と返す／道具が無い → この工程は Claude が自分で読む（従来どおり）。止めない。

## 問いの書き方（Jev は書いた言葉どおりに読む）

- 条件と境目を具体的に書く。「〜ですか？」で終える。否定形や二重否定は避ける。
- 選択肢（choice）は `{ID: 説明}`。説明は「何に当たるか」を 1 行で。似た選択肢は違いを書き分ける。
- 段階（score）は低い順の配列 `["なし","やや","強い"]`。
- 間違えた答えを見て「本当はこういう意味だった」と説明したくなったら、その説明を問いに足す。

## 検証済みの問い（2026-09-22、日本語の実データで確認）

| 用途 | 問い | 結果 | 使い方 |
|---|---|---|---|
| 営業お断りページ | noul「このページは、営業・勧誘・売り込みを目的とした問い合わせを送らないよう求めている（または、送っても対応しないと明記している）ページですか？」 | 36 ページで全問正解（文字検索は 2 件見落とし）。該当は 0.94 以上、非該当は 0.27 以下 | `yes ≥ 0.8` → 送らない（除外）。`unsure` → 人が確認 |
| 議事録の案件特定 | choice「この議事録はどの案件の打ち合わせ記録ですか？案件名から最も当てはまるものを1つ選んでください。」criteria = 進行中の案件名の一覧 | 171 本・103 案件で 1 位正解 88%、上位 3 つに正解 96%。自信 0.9 以上（全体の 73%）は 98% 正解 | 自信 ≥ 0.9 → そのまま。未満 → 上位 3 候補を添えて確認 |

新しい用途は、まず 20〜50 件の正解付きデータで試し、ここに 1 行足してから本番に入れる。

## 用途別のひな形

- **LINE 秘書の受付**: choice「このメッセージの用件はどれですか？」（手順書の一覧）＋ noul「今日中の対応を求めていますか？」＋ score「相手の不満の強さ」`["不満なし","やや不満","強い不満"]`。
- **裏取りの一次チェック**（research-verifier）: item = 「出典の該当箇所＋主張」。choice「出典のこの箇所は、主張を支えていますか？」`{supports: 支えている, contradicts: 反している, silent: 触れていない}`。`supports` かつ自信 ≥ 0.9 以外は Claude が出典を読む。
- **経理の分類**（osi-finance）: 明細の摘要・メールの件名と本文を item に。金額・日付の突き合わせはコードで行い、Jev には「請求書か／領収書か／その他か」「出資・借入・保証金の戻りなど売上ではない入金か」だけを聞く。
- **案件アサインの難易度**（assignment-matcher）: 議事録を item に、score を 3 本（仮説構築力・AI スキル・共感力 × `["小","中","大"]`）。同じ議事録なら毎回同じ点が出るので、判定がぶれない。

## やらないこと

- 文章の生成・要約・翻訳を Jev に頼む（できない）。
- 数える・計算する・日付を比べることを Jev に頼む（苦手。コードで）。
- `unsure` を確定扱いにする／全件を Claude が読み直す（どちらも Jev を使う意味がなくなる）。
- 医療・個人情報を送る。
