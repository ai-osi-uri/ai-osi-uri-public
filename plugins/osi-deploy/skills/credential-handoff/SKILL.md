# 鍵の受け渡し（credential handoff）

## 原則

**人にしかできないことだけを人に残し、それ以外を全部やる。**

人にしかできないことは3つだけ：
1. 本人としてログインする
2. 発行・同意・承認のボタンを押す（決断）
3. 鍵の値をコピーして、使われる側に貼る（**値は Claude を通さない**）

それ以外はすべて Claude の仕事。「○○の画面で発行して貼ってください」と文章で説明して止まるのは、
仕事を人に投げ返している状態なので禁止。

## 鍵の言い表し方

鍵は必ず4つの属性で捉える。分からない属性があれば、まず自分で調べる（公式ドキュメント・
既存の設定・過去の記録）。それでも分からなければ1つだけ聞く。

| 属性 | 意味 |
| --- | --- |
| 何のため | どの機能が、どの権限で動くために要るか |
| どこで生まれるか | 鍵を発行できる場所（サービスの管理画面・コンソール） |
| どこで使われるか | 鍵を置く場所（Secrets・設定表・拡張の設定欄・環境変数） |
| どう確かめるか | 貼れたことを、鍵の値を見ずに確認できる一手（疎通・一覧・health） |

## 手順

### 1. 使われる側を先に整える

鍵を置く場所を、名前だけの空の状態で先に用意する（Secrets の項目名、設定表の行、拡張の設定欄）。
貼る瞬間に「どこに」で迷わせないため。ここは Claude が道具（MCP・SQL・API）で行う。

### 2. 生まれる側へ、自力でたどり着く

Claude in Chrome で、鍵が発行される画面の**直前**まで進む。

- 画面を読みながら進む。「開発者向け」「API」「認証情報」「キー」「Secrets」「連携」といった
  導線は、どのサービスでも似た場所にある。**人に道案内させない。**
- 迷ったら、その場で公式ドキュメントを検索して進む。手順表は持たない（画面は変わる）。
- ログイン画面に当たったら、そこで止めて人に渡す。ログイン後は Claude が続きを進める。
- 発行・同意・承認のボタンは押さない。押す直前で止める。
- 途中で選択肢がある場合（権限の範囲・有効期限・種類）は、**この用途に必要な最小のもの**を
  選んでおく。選ばせない。選択の根拠を1行で添える。

### 3. 3行の概要で渡す

人に渡す文は、この3行だけ：

```
【何の鍵か】<何のため>（<権限の範囲>）
ここからコピー：<開いてある画面のどこを押すと値が出るか>
ここに貼る：<整えてある置き場（別タブで開いてある）>
```

置き場もブラウザ画面なら、そのタブも開いて入力欄まで進めておく。置き場が画面でない
（拡張の設定欄など）なら、開き方を1行で示す。

### 4. 人が値を運ぶ（1往復）

コピー → 貼る、だけ。Claude は待つ。値をチャットに貼らせない。貼られてしまった場合は、
その値を使わず、無効化して再発行するよう伝える。

### 5. 確かめる

貼られたら、鍵の値を見ずに確かめる一手を打つ（health check、一覧取得、1件の読み取り）。
失敗したら原因を画面から読み取り、直せるもの（権限の範囲、有効化されていない API、共有設定）は
Claude が直しに行き、人に必要なのは再発行かクリックかだけにする。

### 6. 記録する

鍵の**台帳**に1行残す（値は書かない）：名前／何のため／どこで生まれたか／どこで使われているか／
いつ／期限や更新の条件。台帳は対象プロジェクトの README か既存の設定一覧に置き、
新しいリストを作らない。

## 学びの残し方

発行元ごとの手順は事前に書かない。実際に詰まった**1点だけ**を、この下の表に追記する
（画面を見ても分からなかったこと・後から効いてくる落とし穴だけ）。

| 発行元 | 詰まった点 | 対処 |
| --- | --- | --- |
| Google Cloud サービスアカウント | 鍵を作っただけでは Drive のファイルを読めない | 対象ファイル／共有ドライブをサービスアカウントのメールに閲覧共有し、Drive API を有効化する |
| LINE Developers | 短期トークンを取ると数日で切れる | 長期のチャネルアクセストークンを選ぶ |
| GitHub Secrets | `workflow` 権限が無いと Actions のファイルだけ push できない | Device Flow（`setup-deploy-environment`）で権限を自動付与 |

## 呼び出し側の書き方

鍵の不足に気づいたスキルは、自分で手順を書かず、次の1行で本スキルに渡す：

```
鍵が要る → credential-handoff（何のため／どこで生まれる／どこで使う／どう確かめる を添えて）
```

## やらないこと

- 鍵の値をチャット・ログ・ファイル・記録に残す
- CAPTCHA や本人確認を代わりに通す
- 人に「どこにあるか探してください」と言う
- 発行元ごとの長い手順書を先回りして書く
