# Cloud Run にアプリを移す・作るときの確かめ表

別のホスト（Railway / Render / VM など）から Cloud Run に移すとき、または新しく Cloud Run に載せるときに読む。
実際に起きた事故と、その防ぎ方。重い処理をするアプリは `cloud-run-long-running.md` もあわせて読む。

## 事故リスト

| # | 起きたこと | 原因 | 防ぎ方 |
| --- | --- | --- | --- |
| 1 | 移した直後、ある機能だけが使えない（ボタンが押せない等） | 前のホストにあった環境変数が、新しいサービスに入っていなかった | 移す前に、前のホストの環境変数の **名前の一覧** を控え、新しいサービスと 1 つずつ突き合わせる。反映のたびに CI でも突き合わせる（下の「設定の正本」） |
| 2 | 設定を直したら、外から開くと 403 になった | `gcp_api` で services を **丸ごと PATCH** したとき `invokerIamDisabled` を送らず、「誰でも開ける」が外れた | サービスの最上位の項目を変えるときは `updateMask` でその項目だけを送る（例 `?updateMask=invokerIamDisabled`、本文 `{"invokerIamDisabled": true}`）。template を変えるときは `updateMask=template`。直したあとは必ず外から開いて確かめる |
| 3 | 「誰でも開ける」にしようとして権限の付与が断られた | 会社の決まり（組織ポリシー）で `allUsers` に `run.invoker` を付けられない | `allUsers` は使わない。作るときに `--no-invoker-iam-check`（REST なら `invokerIamDisabled: true`）で公開し、ログインはアプリ側で持つ |
| 4 | 動いているのに、外からの確認が 404 で失敗した | `*.run.app` では `/healthz` のように **z で終わる道** は Google 側が先に 404 を返し、アプリに届かない | 外から確かめるときは `/healthz/`（末尾に `/`）や `/` など別の道を使う。アプリの確認用の道の名前を `z` で終わらせない |
| 5 | 移したあとに push したら、前のホストにも反映されていた | 前のホストの GitHub 自動反映がつながったままだった | 新しい置き場で動くのを確かめたら、前のホストは **リポジトリの接続を外してから** 止める。止めたら前の URL が開かないことを確かめる |
| 6 | 作り直したら、設定が本番と違っていた（監視が止まったまま・環境変数の抜け） | デプロイ用スクリプトの「作るとき」の設定が、本番を手で直した内容に追いついていなかった | 設定の正本を 1 か所（リポジトリのデプロイ用スクリプト）に置き、手で直したら必ずそこも直す。CI で正本と本番を突き合わせて、ずれたら失敗させる |

## 設定の正本と、反映のたびの確かめ（型）

リポジトリにデプロイ用スクリプトを 1 本置き、GitHub Actions（Workload Identity）から呼ぶ。

1. サービスが **無ければ**、スクリプトに書いた設定（環境変数・鍵・保存先のマウント・`--no-invoker-iam-check`・大きさ）で作る
2. **あれば** 画像だけを入れ替える（`gcloud run deploy --image`。他の設定には触らない）
3. そのあと毎回、次を確かめて 1 つでも違えば CI を失敗させる
   - スクリプトの環境変数と鍵の名前が、すべてサービスにあるか（値を決めているものは値も同じか）
   - 保存先がアプリの読む場所（`DATA_DIR` など）にマウントされているか
   - `run.googleapis.com/invoker-iam-disabled` が `true` のままか
   - 外から `/healthz/` が 200 を返すか

## 移すときの順番

1. 前のホストの環境変数の名前と、保存しているデータの件数を控える
2. 実行アカウント・保存先（バケット）・鍵（Secret Manager。AI の鍵は `gcp_secret_put`）を作る
3. データを写し、件数を比べる
4. CI で作って、上の確かめが通るのを見る。新しい URL で実際の機能を 1 つ動かす
5. 前のホストのリポジトリ接続を外し、止める。前の URL が開かないことを確かめる
6. 置き場の説明（ドライブのアプリ情報・README）を新しい URL と置き場に書き直す
