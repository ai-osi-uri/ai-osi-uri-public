# Phase N-1: Drive 記録

全パス（Web / Desktop）共通で適用される、成果物の Drive 記録手順。
アプリを作って終わりではなく、**再現可能な形で記録を残す**ところまでが納品。

---

## DoD ゲート

> **この Drive 記録を完了するまで、完了レポートを出してはならない。**

deploy-progress.md に「Drive 記録 ✅」が記載されていない状態で完了レポートを作成・送付することは禁止。
記録漏れは「納品したが場所がわからない」という最悪の状態を招く。

---

## Step 1: 保存先フォルダを決める

### 案件フォルダがある場合

Notion のリード一覧に案件が登録されていれば、対応する Drive 案件フォルダが存在する。

**配置ルール**:
```
03.PJT資料/
  └── {ID3桁}.{企業名}/
      └── 03_制作・成果物/
          └── app/                    ← ここに格納
              ├── _アプリ情報_README.md
              ├── deploy-progress.md  （作業中に使用したもの）
              └── （オフライン版があれば同梱）
```

### 案件フォルダがない場合（社内ツール・検証用等）

```
90_社内/
  └── apps/
      └── {アプリ名}/
          ├── _アプリ情報_README.md
          └── （関連ファイル）
```

### フォルダ命名規則
- アプリ名はケバブケース（例: `brand-shop`, `inventory-manager`）
- 日付プレフィックスは不要（Git / Vercel に履歴がある）

---

## Step 2: アプリ情報_README.md テンプレート

以下のテンプレートをコピーし、実際の値を埋めて保存する。

```markdown
# アプリ情報

## 概要

| 項目 | 内容 |
|------|------|
| アプリ名 | （例: ○○ブランドショップ） |
| 用途 | （例: ECサイト / 社内管理ツール / デモアプリ） |
| ステータス | （例: 🟡モック / 🟢本番稼働 / ⚪️停止中） |
| 作成日 | YYYY-MM-DD |
| 作成者 | （担当者名） |
| 案件 | （Notion リード ID / 案件名 / なし） |

## 接続先

| サービス | URL / 識別子 |
|----------|-------------|
| 公開 URL | https://example.vercel.app |
| GitHub | https://github.com/org/repo |
| Vercel / AWS / GitHub Releases | （該当するホスティング先のダッシュボード URL） |
| オフライン版 | （同梱パスまたは「なし」） |

## 構成

- **フレームワーク**: Next.js 14 (App Router)
- **ホスティング**: Vercel
- **DB**: Supabase (PostgreSQL)
- **決済**: Stripe
- **認証**: Supabase Auth
- （その他、使用したサービスを列挙）

## 更新・再デプロイ手順

### コードを修正してデプロイする場合

1. GitHub リポジトリをクローン
   ```bash
   git clone https://github.com/org/repo
   cd repo
   ```
2. 修正を加えてコミット・プッシュ
   ```bash
   git add .
   git commit -m "fix: 修正内容"
   git push origin main
   ```
3. Vercel が自動でビルド・デプロイ（約 1-2 分）
4. デプロイ完了を確認
   - Vercel ダッシュボードで `READY` を確認
   - 公開 URL にアクセスして動作確認

### 環境変数を変更する場合

1. Vercel ダッシュボード → Settings → Environment Variables
2. 対象の変数を編集
3. Redeploy（Settings → Deployments → 最新を Redeploy）

## 注意

- （プロジェクト固有の注意事項をここに記載）
- （例: Stripe テストモードのまま / 画像は仮素材 / 等）
```

## Step 3: _アプリ台帳.md テンプレート

全アプリを横断的に管理するための一覧ファイル。
**1 行追記形式** で、新しいアプリを作るたびに 1 行追加する。

保存先: `03.PJT資料/_アプリ台帳.md`（既にあれば追記、なければ新規作成）

```markdown
# アプリ台帳

作成したアプリの一覧。新規作成時に 1 行追記する。

## ステータス凡例

| アイコン | 意味 |
|----------|------|
| 🟡 | モック（デモ・検証用。本番決済なし） |
| 🟢 | 本番稼働中 |
| ⚪️ | 停止中（Vercel 削除 / Supabase pause 等） |

## 一覧

| # | ステータス | アプリ名 | 案件 | 公開 URL | GitHub | 作成日 | 備考 |
|---|-----------|---------|------|----------|--------|--------|------|
| 1 | 🟡 | ○○ショップ | ID:045 ○○社 | https://example.vercel.app | org/repo | 2026-07-25 | デモ版 |
| 2 | 🟢 | △△管理画面 | ID:052 △△社 | https://admin.example.com | org/repo2 | 2026-07-20 | 本番稼働 |
```

**追記ルール**:
- 番号は連番で振る
- ステータスは作成時点のものを入れ、変更があれば都度更新する
- 備考には「デモ版」「テストモードのまま」「独自ドメイン未設定」など、現状の制約を記載

## Step 4: オフライン版の同梱（あれば）

Desktop アプリ（Electron / Tauri）やオフライン対応版がある場合、ビルド済みバイナリを同梱する。

**同梱対象**:
- `.dmg` / `.exe` / `.AppImage` などのインストーラー
- ポータブル版の `.zip`

**配置場所**:
```
03_制作・成果物/
  └── app/
      └── offline/
          ├── MyApp-1.0.0-arm64.dmg      # macOS (Apple Silicon)
          ├── MyApp-1.0.0-x64.dmg        # macOS (Intel)
          ├── MyApp-Setup-1.0.0.exe      # Windows
          └── README-offline.md          # インストール手順
```

**README-offline.md に含める内容**:
- 対応 OS とバージョン
- インストール手順（スクリーンショット付きが望ましい）
- 初回起動時の設定
- アップデート方法

**オフライン版がない場合**: このステップはスキップする。

---

## Step 5: evidence を残す

すべての記録が完了したら、deploy-progress.md に Drive 記録の完了を記載する。

**追記する内容**:
```markdown
## Drive 記録 ✅

- 保存先: `03.PJT資料/{ID}.{企業名}/03_制作・成果物/app/`
- アプリ情報_README.md: ✅ 作成済み
- アプリ台帳: ✅ 追記済み（#XX）
- オフライン版: ✅ 同梱済み / ⬜ 該当なし
- 記録日: YYYY-MM-DD
```

**この記載があって初めて、完了レポートの作成に進むことができる。**
