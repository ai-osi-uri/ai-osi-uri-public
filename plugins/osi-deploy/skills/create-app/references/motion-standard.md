# 動きの標準 — 待ち・切り替え・知らせの動きは、番号の付いた見本の数値で作る

> create-app Phase 1-C で `screen-structure.md` と一緒に読む。画面の**構造**は screen-structure、
> ここは**動き方**（何秒で・どの曲線で・どれだけ動くか）を決める。配色・部品の見た目はデザインシステムの担当。
>
> 数値の出典：Motion Prompt（大滝昇平さん作・MIT License、https://showheyohtaki.github.io/motion-prompt/ ）。
> 各行の `#番号` は動く見本の番号で、`https://showheyohtaki.github.io/motion-prompt/#番号` で確認できる。

## 原則

**1. 待ち・切り替え・知らせの動きは、下の表の番号と数値で作る。アプリごとに秒数を考え直さない。**

**2. 動きは「何が起きたか」を伝えるためだけに使う。飾りの動きを足さない。**

**3. `prefers-reduced-motion: reduce` のときは、移動・拡大の動きを止め、表示の切り替えだけにする。**

## なぜか

- **秒数を毎回考えると、アプリごとにばらばらになる。** あるアプリはトーストが速く、別のアプリは遅い、ということが起き、
  会社として作ったものに見えない。番号で決めておけば、レビューでも「#056 の数値か」で見られる。
- **「いい感じに動かして」では AI も人も同じものを作れない。** 名前と番号と数値があれば、誰が作っても同じ動きになる。
- **業務アプリは毎日何十回も同じ画面を行き来する。** 見せ場の演出（ブランドサイトの幕など）を入れると、
  1回は気持ちよくても、毎回の待ちが足されて「遅いアプリ」になる。動きは状態を伝える分だけにする。

## 場面ごとの標準

曲線の CSS：`easeOutCubic` = `cubic-bezier(0.33, 1, 0.68, 1)`、`easeInOutCubic` = `cubic-bezier(0.65, 0, 0.35, 1)`

### 待ち（読み込み・処理中）

`screen-structure.md` の「ローディング表示の3点セット」（上端の進み具合バー・本文の読み込み中・ボタンの処理中）は必須のまま。その中身の動きを次で作る。

| 場面 | 番号 | 動きの標準 |
|---|---|---|
| 一覧・カードの読み込み中（`app/loading.tsx` の本文） | #069 スケルトン | 中身と**同じ位置・同じ大きさ**の灰色の角丸の枠を出す。光の帯（幅160px・両端透明・中央の不透明度0.75）を**0.9秒ごと**に左から右へ流す。中身への切り替えは0.15秒、戻りは0.3秒、どちらも直線。外側の要素には `page-loading` の class を残す（進み具合バーがこれを待つ） |
| 時間の読めない短い待ち（画面全体を止める必要があるとき） | #070 スピナー | 半径26・太さ6の薄い輪の上に、長さ243°の主色の弧（端は丸）。**1秒に1.3回転**（1回転 0.77秒・直線）。幕は白の不透明度0.78、出すのは0.15秒。済んだらチェックを0.25秒（easeOutCubic、拡大率0.7→1）で出してから消す。画面全体を止めない待ちには使わず、ボタンの処理中表示で済ませる |
| AI処理・送信・保存の主ボタン | #160 ローディングボタン | 押したら**0.3秒**（easeInOutCubic）で丸に縮め、文字は縮み始めの1/3で消す。丸の中で白い読み込み表示（線幅3・弧0.7π）を**0.7秒で1回転**。終わったら0.2秒で緑（#1E9E5A）に変えてチェックを描き、**0.35秒**（easeInOutCubic）で広げて「完了」を出す。処理中は `disabled`（二重押し防止は screen-structure のとおり） |
| 副ボタン・小さな操作 | — | 文言を「◯◯中…」に変え、左に小さなスピナー（上の #070 と同じ回転速度）。縮める動きは主ボタンだけにする |

### 切り替え

| 場面 | 番号 | 動きの標準 |
|---|---|---|
| 画面遷移（業務アプリの既定） | — | 上端の進み具合バー＋本文のスケルトン（#069）で足りる。**#092 ページ遷移アニメーション（色の幕）は業務アプリでは使わない**（毎回約0.95秒の待ちを足すため。LP・ブランドサイトでだけ使う） |
| 一覧の写真・カードから詳細へ（どれを開いたか見失わせたくないとき） | #161 ビュートランジション | 押した写真（カード）1枚の位置と大きさを、詳細の上部まで**0.6秒**（easeInOutCubic）で連続して変える。周りは進み0〜62%で消え、詳細の中身は60〜100%で現れる。一覧と詳細の同じ要素に同じ `view-transition-name` を付ける（View Transitions API）。**表の行には使わない**（写真・カードのある一覧だけ） |
| 詳細画面のタブ | #057 タブ | 下線の位置と幅を**0.25秒**（easeInOutCubic）で次のタブへ移す。中身は前のパネルを0.2秒（直線）で消し、0.1秒おいて次のパネルを0.2秒で出す（出るとき8px下から上がる）。タブの切り替えでデータを読み直さない（screen-structure のとおり） |
| 一覧のページ送り | #064 ページネーション | 今のページのしるしを**0.2秒**（easeInOutCubic）で移す。一覧の中身はクリックの前後0.2秒で不透明度を1→0→1にして入れ替える。読み込みが0.2秒を超えるときは、その間スケルトン（#069）にする |
| 開閉（FAQ・詳細な説明） | #052 アコーディオン | 開くのは**0.35秒**、閉じるのは0.32秒、どちらも easeInOutCubic。下の段は押し下げ、本文は枠の中に切り抜いて不透明度で出す。矢印は開く量に合わせて180°回す |

### 知らせ・重なり

| 場面 | 番号 | 動きの標準 |
|---|---|---|
| 保存・送信の結果（作業を止めない知らせ） | #056 トースト | 右下（右端から18px・下端から16px）に、右から240pxを**0.35秒**（easeOutCubic）で滑り込ませる。下端に残り時間の線（高さ3px）を直線で縮め、縮みきったら**0.35秒**（easeInOutCubic）で右へ滑り出す。表示しておく長さ（残り時間の線の長さ）は文の長さに合わせて3〜5秒に延ばしてよい（延ばすのは表示の時間だけで、出入りの0.35秒は変えない） |
| 確認・入力で作業を止める | #049 モーダル | 開くのは**0.32秒**（easeOutCubic）。幕は不透明度0→0.42、窓は拡大率0.9→1と不透明度0→1を同時に。閉じるのは0.28秒（easeInOutCubic）。**1件の詳細表示には使わない**（詳細は自分の URL を持つ画面。screen-structure のとおり） |
| 入力欄の正誤 | #159 インラインバリデーション | 間違いは**0.15秒**（easeOutCubic）で枠を赤・地を薄い赤にし、欄の下に理由を出す。正しくなったら**0.25秒**で枠を緑にし、欄の右端にチェックを出す。打ち始め（1文字目）では赤にしない |
| 押せるカード | #081 ホバーで浮き上がる | 乗ったら**0.3秒**（easeOutCubic）で上へ10px、影を広げる（ぼかし6→22px・下へ2→12px・濃さ0.08→0.22）。離れたら同じ0.3秒で戻す。**表の行は浮かせず、背景色を変えるだけ** |

## 入れ方

- 上の表の秒数・曲線・量は**そのまま使う**。変えてよいのは色（アプリの主色）・文言・大きさ（画面に合わせた拡大縮小）だけ。
- 場面が表に無いときは、Motion Prompt の一覧から近い番号を探し、その番号の数値を使う（`npx skills add` で入るスキル、またはサイトの見本）。
  探した番号は、要件定義書の「画面の動き」に `#番号 名前` で書いておく。
- Motion Prompt の**コードを写す**ときは、各ファイル先頭の `// Motion Prompt #ID · MIT License …` の1行を必ず残す（MIT の表示義務）。数値だけを使うときは、この文書の出典の記載で足りる。
- 共通の値は CSS 変数にまとめる：

```css
:root{
  --ease-out: cubic-bezier(0.33, 1, 0.68, 1);      /* easeOutCubic */
  --ease-in-out: cubic-bezier(0.65, 0, 0.35, 1);   /* easeInOutCubic */
  --dur-toast: .35s;   /* #056 */
  --dur-modal-in: .32s; --dur-modal-out: .28s;   /* #049 */
  --dur-tab: .25s;     /* #057 */
  --dur-page: .2s;     /* #064 */
  --dur-press: .3s;    /* #160 縮む・#081 浮く */
  --spin: .77s;        /* #070 1秒に1.3回転 */
  --shimmer: .9s;      /* #069 */
}
@keyframes spin{to{transform:rotate(360deg)}}
@keyframes shimmer{from{transform:translateX(-100%)}to{transform:translateX(100%)}}
.spinner{animation:spin var(--spin) linear infinite}
.skeleton{position:relative;overflow:hidden;background:var(--muted, #e9e7e5);border-radius:6px}
.skeleton::after{content:"";position:absolute;inset:0;width:160px;
  background:linear-gradient(90deg,transparent,rgba(255,255,255,.75),transparent);
  animation:shimmer var(--shimmer) linear infinite}
@media (prefers-reduced-motion: reduce){
  *,*::before,*::after{animation-duration:.01ms!important;animation-iteration-count:1!important;transition-duration:.01ms!important}
}
```

- shadcn/ui の部品（Dialog・Tabs・Toast/Sonner・Accordion）を使うときは、部品の既定の秒数をこの表の値に上書きする。

## チェック（Phase 3 のプラン提示と app-smoke-test で見る）

- [ ] 一覧の `loading.tsx` が、中身と同じ形のスケルトン（#069）になっているか（`page-loading` の class が残っているか）
- [ ] AI処理・送信の主ボタンが #160 の動き（縮む→回る→完了）になっているか。処理中に押せないか
- [ ] 保存・送信の結果がトースト（#056）で右下に出て、自動で消えるか
- [ ] 業務アプリに色の幕のページ遷移（#092）が入っていないか
- [ ] タブ・ページ送り・モーダルの秒数が表の値か（CSS 変数を使っているか）
- [ ] `prefers-reduced-motion: reduce` で移動・拡大の動きが止まるか
- [ ] 表の行がホバーで浮いていないか（背景色の変化だけか）

> 経緯（2026-10）：画面遷移のローディング表示の付け忘れを繰り返し指摘されていた。screen-structure で「付けること」は必須にしたが、
