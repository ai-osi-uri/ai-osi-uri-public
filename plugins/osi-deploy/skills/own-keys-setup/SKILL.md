# 自分の鍵に移る（own-keys-setup）

## §0 考え方

- **お試し（マネージド）は体験用。** 共用アカウントで、鍵なしでアプリを作って公開するためのもの。枠は アプリ 2 本・GitHub 2・Vercel 2・Supabase（データベース）1、画像・動画・音声は「生成枠」（会社ごとの通算。`health_check` の「お試しの枠」行に残り % が出る。使い切ると `[quota_exceeded:generation]`）。
  2 本目のアプリ、AI 秘書、本番運用は **自分の鍵** で作る。作ったものが本人のアカウントに残り、費用も各サービスから本人に請求される。
- **何が要るかはサーバが知っている。** 鍵の一覧と「やりたいこと別にそろっているか」は `health_check` の `uses` 行が正本。
  スキル本文に鍵の表を持たない（増えたらサーバ側だけ直せば済むように）。
- **鍵の値は Claude を通さない。** 本人がツールポータルの「自分の鍵」に貼る。チャットに貼られたら使わず、
  「チャットに残ったので、発行元で作り直してから画面に貼ってください」と伝える。
- **切り替えは本人が押す。** 「自分の鍵を使う」はポータルの画面のボタン。Claude からは切り替えない。

## §1 いまを見る

1. `health_check` を呼ぶ（URL で繋いだコネクタ。テキストで返る）。読むのは 3 か所：
   - `keys :` … いま「マネージド（お試し）」か「自分の鍵」か
   - `uses :` の下の行 … `○/✕ [id] やりたいこと  足りない鍵: …  ※注意  <ポータルの URL>#<id>`
   - `broken :` … 預けたのに効いていない鍵（期限切れなど）
2. `health_check` がテキストでなく JSON で返るなら、ダウンロード版の拡張を使っている。このスキルではなく
   `setup-deploy-environment` に渡して終わる。
3. やりたいことを 1 つに決める。呼び出し元から渡されていればそれ。無ければ聞く（選択肢は `uses` の行の題名をそのまま）。
   決済を付けるなら、親の「アプリを作って公開する」も対象に入る（子の扉は親がそろわないと動かない）。

## §2 地図を 1 行で出す

最初の返事で、これからやることを 1 行で見せる。例：

> ① 鍵を 2 つ登録（Vercel のトークン・Supabase の組織 ID）→ ② 「自分の鍵を使う」に切り替え → ③ そろったか確かめる → 秘書づくりに戻ります

足りない鍵が 0 で切り替えだけなら ② ③ だけ。全部そろっていれば「そろっています」と言って、すぐ元の作業に戻る。

## §3 鍵を 1 つずつ

足りない鍵ごとに、次の 3 行だけを出して待つ（まとめて全部の手順を書かない）：

1. **何のため**：その鍵で何が動くか 1 文（例：「Vercel のトークン … 管理画面を公開するのに使います」）
2. **どこで作る**：発行ページ。Claude in Chrome が使えるなら `credential-handoff` に渡し、発行ボタンの直前まで連れて行く。
   使えなければ、ポータルの画面の「取得ページを開く」を押してもらう
3. **どこに貼る**：`uses` 行の末尾の URL（`…/keys#<id>`）。開くと、そのやりたいことに要る鍵だけが並んだ画面になる。
   「確かめて登録」を押すと、サーバが鍵が効くかを確かめてから預かる

本人が「貼った」と言ったら `health_check` をもう一度呼び、その鍵が `credentials:` で OK になったことを確かめてから次へ。
`NG（無効・期限切れ）` なら作り直してもらう。権限不足（例：GitHub の repo と workflow）を疑うときは、その 1 点だけ伝える。

Supabase は「トークン」と「組織 ID」の 2 つで 1 組。片方だけでは足りない扱いになる。

## §4 切り替え

鍵がそろって、`keys :` がまだ「マネージド」なら：

> ポータルの「自分の鍵」の上にある「自分の鍵を使う」を押してください（確認が出たら OK）。押したら「押した」と送ってください。

切り替える前に一度だけ伝えること：お試しで作った公開中のアプリは、自分の鍵からは操作できなくなる（アプリは動き続ける。お試しに戻せば操作できる）。
お試しが選べない人（会社がマネージドを申し込んでいない）は、最初から自分の鍵で動いているので切り替えは要らない。

## §5 確かめて戻る

`health_check` を呼び、目的の行が `○` になったことを確かめる。

- `○` → 「そろいました。続きを始めます」と言って、呼び出し元のスキル（`create-app` / `secretary-create` など）の止まったところへ戻る
- `✕` のまま → 足りない鍵の名前と、画面の URL だけをもう一度示す

## 呼び出し元との約束

| 呼び出し元 | いつ呼ぶか | 渡すやりたいこと |
|---|---|---|
| `create-app` | `[quota_exceeded:projects]` / `[quota_exceeded:resources]`（お試しの枠）を受けた／本人がお試しの枠を超えて作りたいと言った | `app`（決済があれば `pay` も） |
| `create-app` | Stripe の道具が「Stripe の鍵が未登録」で止まった | `pay` |
| `secretary-create` | URL のコネクタで、`uses` の `[secretary]` が `✕` | `secretary` |
| LINE の道具 | 「チャネルアクセストークンを預けると使えます」と出た | `line` |

## 事故の型

- 手順を全部まとめて書き、本人がどこで止まったか分からなくなる → 1 回に鍵 1 つ
- 鍵がチャットに貼られ、そのまま使う → 使わない。作り直しを案内する
- 鍵を入れただけで自分の鍵に切り替わったと思い込む → 切り替えは別のボタン。`keys :` で確かめる
- 期限切れの鍵が「登録済み」に見えて、作る途中で 401 → `credentials:` の `NG` を見る
