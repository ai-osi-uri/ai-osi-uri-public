# secretary-create（秘書をつくる）

会社ごとに LINE 秘書を1つ作る。**1社に1つの置き場（Supabase プロジェクト）** を作り、そこへひな形（DB の形・関数・定時処理）を入れ、
その会社の **業務定義** を書き、LINE とつなぐ。秘書は業務定義に沿って動く（業務定義が正本。直すのは「業務定義を直す」スキル）。

## 守ること

- **鍵は本人が入れる。Claude は値を見ない。** LINE のチャネルシークレット／アクセストークン、Claude の API キーは、
  `secretary_install` が返す **設定用リンク（setup_url）** を本人に開いてもらい、そこに貼ってもらう。チャットに貼らせない。
  貼られてしまったら使わず、「チャットに鍵が残ったので、LINE Developers で再発行してから設定用リンクに貼ってください」と伝える。
- **費用が出る操作・外に見える操作の前は、完成形を見せて OK をもらう。** 置き場の作成（月額が発生）、LINE 公式アカウントの作成、業務定義の書き込み。
- 会社名・代表者名・住所は **公式サイトで一字ずつ確認** し、ウェブの表記を正とする。確認できない肩書は書かない。
- 普通の言葉で話す。カタカナ語・略語を避ける。1回の質問は多くて3つ。
- 報告は「何を頼まれたか → どう進めたか → 結果 → 決めてほしいこと」の順。

## 道具（どちらの経路でも名前は同じ）

| 段階 | 道具 |
|---|---|
| 置き場の作成 | `supabase_list_organizations`（自分の鍵のときだけ）→ `supabase_create_project` → `supabase_list_projects`（ACTIVE_HEALTHY を待つ） |
| ひな形を入れる | `secretary_install`（DB・初期設定・関数・定時処理。setup_url と webhook_url を返す）。ひな形は GitHub の ai-osi-uri/ai-osi-uri-line-secretary（本番の秘書と同じもの）から、その場で読む |
| 業務定義を書く | `secretary_write_flow`（版・変更の記録つき。同じ No は上書き） |
| 状態を見る | `secretary_status`（メンバー数・LINE の鍵が入ったか・業務定義の版・入っているひな形の版と最新・足りない関数） |
| 関数の入れ直し | `secretary_update`（DB の追加分もあるときは `with_sql: true`） |

**どちらの経路を使うか（会社の設定で決まる）**：本人が「自分の鍵で」「Deploy 拡張で」と言ったときは、会社の設定に関わらず Deploy 拡張（自分の鍵）で進める。それ以外は リモートMCP の `whoami` を呼び、`credential_mode` を見る。
- `managed`（提供元が用意した置き場で動かす）… リモートMCP の道具を使う。作成先の組織は自動で決まる（引数で変えない）。作ったものは案件台帳に載る。
- `byok`（会社自身の鍵で動かす）… Deploy 拡張（自分の Supabase の鍵）の道具を使う。組織は `supabase_list_organizations` で本人に選んでもらう。
- リモートMCP がつながっていなければ Deploy 拡張で進める（= 自分の鍵）。

## 流れ（5段階＋試運転）

最初にこの全体を1回だけ見せる（完成形の文面で）：

```
会社の秘書を作ります。全部で5段階、1時間ほどです。途中でやめても続きから再開できます。
【1/5 会社のこと】【2/5 業務定義】【3/5 秘書の置き場を作る】【4/5 LINE】【5/5 つなぐもの】→ 試運転
```

### 1/5 会社のこと
- 会社の正式名称（公式サイトで確認して、住所・代表者も拾う）、秘書を運営する人の呼び名と会社メール、秘書を使うメンバーの呼び名、秘書の呼び名（既定「秘書」）。
- `company_profile` は「社名／代表者の肩書と氏名／住所」の形にする（例：`〇〇株式会社／代表取締役 山田 太郎／〒…`）。

### 2/5 業務定義
1. 任せる業務を選んでもらう（複数可）：
   `1. 営業管理（リード〜受注）／2. 契約（NDA・契約書の作成・送付・締結の追跡）／3. 請求・支払／4. お客さまとの打ち合わせの振り返り／5. 社内の依頼・やること管理`
2. 選ばれた業務ごとに、`references/standard-flows.md` の標準の流れを見せ、「誰が・何を・どこに記録するか」を3〜5問で聞いて直す。
   - 人の名前は呼び名で。「記録先」は具体的なフォルダの場所ではなく、台帳・書類の名前で書く（置き場所の正本は台帳側）。
3. 最後に **業務定義の一覧（表）** を見せて OK をもらう。OK が出るまで書き込まない。
4. 5 は必ず入れる（秘書の基本の動き：頼む→担当に届く→進んだら報告→頼んだ人に届く）。

### 3/5 秘書の置き場を作る
1. 完成形を見せて OK をもらう：
   `置き場（Supabase）を「<会社の短い名前>-secretary」という名前で東京リージョンに作ります。月額はおよそ 1,500〜4,000 円です。▶ 作る ／ ▶ あとで`
2. `supabase_create_project`（db_pass は強い乱数を作って渡す。本人にも見せない）→ 数分待ち、`supabase_list_projects` で `ACTIVE_HEALTHY` を確認する。
3. `secretary_install` を呼ぶ。失敗したら `done`（済んだ手順）を見て、同じ道具をもう一度呼ぶ（既にあるものは作り直さない）。
4. 2/5 で OK をもらった業務定義を `secretary_write_flow` で書く（version は `v1.0`）。
5. 返ってきた `project_ref`・`setup_url` を控える（再開に使う）。

### 4/5 LINE
1. 聞く：`社内で使う LINE 公式アカウントを作りますか？ ▶ 作る（画面を開いて一緒に進めます） ▶ もうある ▶ LINE は使わない`
2. 作る場合は Claude in Chrome で開き、本人に操作してもらう（アカウントの作成・ログイン・利用規約への同意は本人が行う）：
   - LINE 公式アカウントの作成：`https://entry.line.biz/start/jp/`（アカウント名は「<会社名> 秘書」など）
   - 作ったら LINE Official Account Manager → 設定 → Messaging API → 「Messaging API を利用する」（プロバイダーは会社名で作る）
   - LINE Developers（`https://developers.line.biz/console/`）で、そのチャネルの「Messaging API 設定」→ 応答メッセージを OFF、Webhook の利用を ON
3. `setup_url` を本人に開いてもらい、**チャネルシークレット**（チャネル基本設定）と **チャネルアクセストークン（長期）**（Messaging API 設定の一番下で発行）を貼ってもらう。
   Claude の API キーを求められたら（`needs.anthropic_key_in_setup` が true）、Anthropic Console で作った鍵も同じ画面に貼ってもらう。
   貼ると Webhook の設定と疎通の確認まで自動で行い、「友だち追加」のボタンが出る。
4. 運営する人に友だち追加してもらう。友だち追加で呼び名が自動で当たる（当たらなければ、運営が LINE で「<表示名> は <呼び名>」と送る）。

### 5/5 つなぐもの
業務定義で「記録先」になったものだけ聞く。v1 で今すぐつなげるもの・後からのものを正直に分けて伝える：
- すぐ使える：秘書の中の台帳（営業管理表・チケット）、管理画面
- 後から（別途設定）：議事録の取り込み（Plaud など）、Google ドライブの台帳、電子署名（DocuSign）、会計ソフト

### 試運転
1. `secretary_status` で、`line_key: true`・メンバーが1人以上・`functions_missing: []`・業務定義の行数を確認する。
2. 本人に LINE で「残ってる？」と送ってもらい、返事が来たら完成。来なければ `secretary_status` の `last_event` を見る（Webhook が届いているか）。
3. 最後に報告：作った置き場（ref）、業務定義の版と行数、LINE アカウント名、これから2週間はずれを業務定義に直していくこと、後からつなぐもの。

## 再開するとき
`project_ref` が分かれば `secretary_status` で今どこまで済んでいるかを見て、続きの段階から始める。
設定用リンクの期限（24時間）が切れていたら `secretary_install` をもう一度呼ぶ（設定は上書きせず、リンクだけ作り直す… ただし既に LINE の鍵が入っていればリンクは不要）。
