# contract-docusign-send セットアップ

**既定の経路（2026-10-16〜）は、URL でつなぐコネクタ（リモート MCP）の `ds_*` です。**
連携アプリの鍵は会社で1回だけ預け、各自は「DocuSign とつなぐ」を1回押すだけです。

---

## 1. 会社で1回：連携アプリの鍵を預ける（owner / admin）

1. DocuSign の［アプリとキー］で連携アプリを1つ用意する。**本番アカウントでは新しく作れない**ので、
   開発者アカウントで作って Go-Live で本番へ移すか、すでに本番にあるアプリを使う。
2. そのアプリの認証は「認証コードの付与」・クライアントシークレットを保管できる「はい」。リダイレクト URI に
   `https://www.ai-osi-uri.info/keys/oauth/docusign/callback` を足して保存する（既存の URI は残してよい）。
3. 「秘密鍵の追加」で Secret Key を作る（一度だけ表示される）。
4. ポータルの「鍵設定」→「会社の鍵」に、Integration Key・Secret Key・環境（`prod` か `demo`）を預ける。

## 2. 各自1回：DocuSign とつなぐ

ポータルの「鍵設定」→「DocuSign」（`/keys/service/docusign`）で「DocuSign とつなぐ」を押し、
DocuSign の画面で許可する。チャットで `ds_status` が `connected: true` になれば完了です。
送信者は**許可を押した本人**になります。

## 3. つながっていない人の予備：公式 DocuSign コネクタ

Claude の設定 →［コネクタ］から公式の DocuSign を接続する。鍵は要らないが、**手元のファイルを渡せない**ので、
人が DocuSign の画面にドラッグして下書きを作り、Claude がそれを拾って整える（SKILL.md の経路 A）。

---

## 補足

### 別のアカウントでつなぎ直したい

ポータルの「鍵設定」→「DocuSign」で接続を外し、もう一度「DocuSign とつなぐ」を押す。

### 送信者は誰になるか

**許可を押した本人**です。DocuSign 上の送信履歴にもその人が残ります。
経理担当以外がつなぐ必要はありません。

## 変更の経緯

> **2026-10-16: 既定の経路を URL のコネクタの `ds_*` にしました。**手元の Finance 拡張の `ds_*` は外しました。
> 連携アプリは会社の鍵（鍵設定）として1回だけ預け、各自は「DocuSign とつなぐ」を押すだけです。
> 本番アカウントで新しく Integration Key を作れない点は変わらないので、既に本番にあるアプリを使うか Go-Live を通します。

> **2026-08-20: 既定の経路を「公式 DocuSign コネクタ＋人がアップロード」に戻しました。**
>
> 手元のファイルを自動で DocuSign に載せる道を、実地で全部当たって塞がっていることを確認しました。
> 公式コネクタは `remoteUrl` かテンプレートしか受けない（**公開URLでの封筒作成は成功を確認**、
> 非公開 Drive は `NO_DOCUMENT_RECEIVED`）。Claude in Chrome の代行アップロードは
> `file_upload` がこの環境で使えない。Drive コネクタは「リンクを知っている全員」を作れない。
> 本番 DocuSign アカウントでは Integration Key を発行できない。
>
> **一方で、ファイル以外は公式コネクタで全部できます**（受信者・署名欄・件名・下書き保持・
> 後からの修正・送信・リマインド・取り消し）。そして元々「送信は人が押す」原則なので、
> 人が DocuSign を開くことは変わりません。**増える手間はドラッグ1回**という結論です。
>
> 自前コネクタ（base64 直送）は消していません。開発者アカウントと Go-Live を通した組織は
> そちらが最短です。

> **2026-08-18: JWT 方式から認可コード方式（PKCE）に変えました。**
>
> 以前は利用者ごとに DocuSign でアプリを登録し、RSA キーペアを生成し、秘密鍵の PEM 全文を
> 設定欄に貼る必要がありました。「トークンが失効しない」ことを理由に選んだ方式でしたが、
> **重すぎて社内の誰も設定を終えられず、2026-08 時点で一度も使われていませんでした。**
> 失効しない代わりに誰も始められないのでは、失効するより悪いという判断です。
>
> 旧方式の設定が入っている環境では、引き続き JWT で動きます（手を止めないため）。
>
> **2026-08-17: AWS（S3 ステージング）が不要になりました。**契約書は自前コネクタが読んで
> base64 で DocuSign に直接送るため、一時ファイルも一時公開URLも作りません。
> 旧手順は `_旧版_S3方式_20260817/` にあります。
