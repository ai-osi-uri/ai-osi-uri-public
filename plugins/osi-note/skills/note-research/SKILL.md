# note-research（note の記事を調べる）

道具は PC の AI OSI URI note 拡張（非公式・既定は読むだけ）。呼べなければ note-setup へ。
読むだけの道具しか使わないので、本人の OK なしで呼んでよい。ただし**大量に呼ばない**（1 回の頼みで記事の本文は 10 本まで・検索は 5 回まで）。note 側に負担をかけないため。

## 1. 何を知りたいかを決める
本人の言葉から次を取る。足りなければ 1 回だけ聞く（全部は聞かない）。
- テーマ（キーワード。言いかえを 2〜3 個）
- 目的：自分が書く記事のネタ探し／競合の分析／特定のクリエイターの傾向／自分の記事の振り返り
- 有料記事を含めるか（既定は含める）

## 2. 集める
| 目的 | 呼ぶもの |
|---|---|
| テーマの全体像 | `search-notes`（`sort: "popular"` と `"hot"` を各 1 回・`size: 20`）、必要なら `"new"` |
| まとめて傾向を見る | `analyze-notes`（`query`・`size` は 20 程度） |
| 人・マガジン・タグを探す | `search-all` / `search-users` / `search-magazines` / `get-hashtag` |
| 特定のクリエイター | `get-user`（`username`）→ `get-user-notes`（`page: 1` から 2 ページまで） |
| 上位の記事の中身 | `get-note`（`noteId` は `n` で始まる記事 ID。URL の note.com/〇〇/n/ の後ろ） |
| 自分の記事（ログイン時） | `get-my-notes` / `get-stats`（`filter: "month"`, `sort: "pv"`） |

- `get-note` で読むのは、スキ数の上位から 5〜10 本。有料記事は無料で読める範囲だけ。**本文を長く写さない**（まとめに引くのは 1 本につき 1 文まで）。
- 検索がエラー・空のときは言葉を変えて 1 回だけやり直す。それでもだめなら「note の仕様が変わった可能性がある」と伝えて、取れた分でまとめる。

## 3. まとめる（返し方）
最初に結論を 3 行で書き、そのあとに次を順に並べる。
1. **よく読まれている記事**：タイトル・著者・スキ数・有料/無料（価格）・URL の表（上位 10 本まで）。
2. **読まれる型**：タイトルの言い回し、冒頭の書き方、見出しの数、文字数のめやす、画像の使い方、タグ、価格帯。数字は取れたものだけ（推測で埋めない）。
3. **空いている切り口**：上位に無いが、検索や新着で需要が見える角度を 3〜5 個。本人の立場（業種・経験）があればそれに寄せる。
4. **次の一歩**：「このうち 1 つで構成案を作りましょうか？」と 1 行だけ。構成案・本文・下書き保存は note-draft。

自分の記事の振り返りのときは、PV の上位・下位と、その差（タイトル・テーマ・公開日・タグ）を並べ、次に書くテーマを 3 つ挙げる。

## 守ること
- 他の人の記事を写して自分の記事にしない。型や切り口だけを学び、本文は本人の言葉で書く（note-draft）。
- スキ・コメント・フォローはこのスキルではしない。
- 取れなかった数字は「不明」と書く。
