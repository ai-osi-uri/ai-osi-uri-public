# 報告メッセージ テンプレート（成果物 D）

依頼主（事業主）・上長・共同創業者へ事業計画のたたき台を報告するときの雛形。財務数値は必ず財務モデル(A)に一致させる。
チャット（LINE / Slack）向けは見出し記号を減らして短く、メール向けは件名を付ける。

**順番は固定：①依頼の理解 → ②進め方の解釈 → ③その順で進めた結果 → ④意見をもらいたい点。**
「作ったもの」「必要資金の額」から書き始めない（下の「使わない書き出し」を参照）。

---

## 型1：依頼主（事業主）へ、依頼の理解から書く

{議事録の抽象度で言い直す。例：「このアプリをどう売るか」＝事業計画・戦略のたたきを作り、次回ディスカッションする}

**こう進めると解釈しました**
{決める順番。例：①誰に売るか → ②いくらで売るか → ③その場合の座組と、必要な資金}

**その順番で仮置きして進めた結果**
①{例：最初の相手は日本の受託開発・SES企業（仮説）}

③{例：座組は{決まった形}。この前提で5年の損益と必要資金を出すと、{A の正本値：売上 FY1→FY5、黒字化年、必要資金＝現金が一番減る時点の額}}

{別枠：目玉機能など。「こういう機能を考えています」の粒度で1〜3行}

・{財務モデルのリンク}
{グループ宛なら：○○さんには考え方へのご意見を、△△さんには内容のご確認をお願いします（メンションは付けない）}

## 使わない書き出し（禁止）

- 「事業計画一式をドラフトしました。作ったものは…」← 依頼した側は、頼んだことがどう解釈されたかを先に知りたい
- 「必要資金は約{額}です」← 前提（誰に・いくらで・どの座組で）を聞く前に額を見せると、額の議論になって考え方の議論に入れない
- 「席」「β」「Phase」「FY」「KPI」「トラフ」等の略語（business-plan-builder Step 1.5 の語彙に従う）

注意：
- 楽観に寄せない。良い数字も悪い数字（先行赤字・必要資金）も正直に書く。
- 希望（EXIT時期・調達額）とモデルがズレる点は、隠さず「意見をもらいたい点」に上げる。
- 数字は財務モデル(A)の値をそのまま使う（pptx・docxと食い違わせない）。
- 論点・決定事項リスト（E）のリンクは付けない。決めてほしいことは本文と B 最終ページで足りる。

> 観測（2026-09-18 / ある事業者の事業主への LINE 報告）：型2の書き出しで送った初稿は「届け方が間違っている」と差し戻され、型1に直したものが採用された。
