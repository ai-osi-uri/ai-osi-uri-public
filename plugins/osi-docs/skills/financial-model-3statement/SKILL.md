# 財務3表フル連動モデル作成スキル

事業計画の数値計画を、**月次60ヶ月・PL/BS/CF フル連動の Excel** として生成する atomic スキル。最大の目的は「コンサバに引いたうえで、キャッシュフロー上いくら資金が必要か（資金トラフ）」を、検算可能な形で示すこと。

成果物（1ファイル・5シート）：
1. **サマリー** … FY別 売上/利益/現金、資金需要KPI（必要資金・推奨調達額・調達後最低現金）、売上×営業利益グラフ
2. **前提・KPI** … 全入力値（青字）。ファネル単価・コスト単価・運転資本・税・月次CA人数/増資スケジュール・販管費FY内訳
3. **月次三表（FY1-5）** … PL→BS→CF（60ヶ月）。Balance Check と 連動Check 付き
4. **財務三表（年次・参照）** … 月次を集約（PL/CF=合計, BS=期末）
5. **パイプライン明細** … 受注/獲得の実データ入力欄

## ★ 大切にしている考え方（必ず守る）

`references/method.md` が中核。要点：

1. **CF プラグ禁止・参照モデル準拠**：BS の現金を「前月現金＋他の全BS勘定の増減」で算出して BS を自閉させ、CF は BS 差分から独立に組んで BS 現金に一致させる。**Balance Check（資産−負債−純資産）と 連動Check（CF期末−BS現金）の2本が全60ヶ月で0**であること。
2. **コンサバな立ち上がり**：採用→稼働の成熟ラグ×稼働率で売上を遅らせる。初月から売上を立てない。
3. **必要資金を出す**：増資ゼロ想定の現金推移の最小値＝資金トラフ＝必要資金。
4. **消費税・入金サイト・税**を実装（method.md 参照）。

## ワークフロー

```
1. 前提を集める（対話）→ 2. config.json 作成 → 3. generate_model.py で生成
→ 4. recalc（必須）→ 5. verify.py で2本のCheck=0と必要資金を確認 → 6. 必要なら増資を設定して再生成
```

### 1. 前提を集める
ユーザーから以下を引き出す（不明な点のみ AskUserQuestion、1度に4問まで）。既定値で進めてよいものは既定で進める。
- 事業のタイトル、売上ドライバー（本テンプレは人材紹介×スクール型：送客/成約率/紹介料/受講率/受講料）
- コスト単価（人件費・ロイヤリティ・スクール費・初期費用）
- 月次の人員（CA等）採用カーブ（コンサバに）、立ち上がりラグ・稼働率
- 運転資本（入金サイト）、法人税率・消費税率、創業資本
- 販管費の FY別内訳

### 2. config.json
`assets/example-config.json` を雛形にコピーして値を埋める。スキーマは generate_model.py の `DEFAULT_CONFIG` と同一。`headcount` と `raise` は60要素。**まず `raise` は全0**にして必要資金を見る。

### 3〜5. 生成・検算
```bash
python3 scripts/generate_model.py --config config.json --out <案件>_財務モデル.xlsx
# recalc（xlsx スキルの recalc.py。パスは環境に合わせる）
python3 <xlsx-skill>/scripts/recalc.py <案件>_財務モデル.xlsx 90
python3 scripts/verify.py <案件>_財務モデル.xlsx     # RESULT: OK を確認
```
`verify.py` が「必要資金（無調達トラフ）」を表示する。**RESULT: OK でなければ完了としない**（Check が0でない・数式エラーがある等）。

### 6. 増資の設定
表示された必要資金（＋20%バッファを目安）を config の `raise` の該当月（通常 M1）に入れて再生成・再検算。「調達後 最低現金 > 0」を確認する。

## 引数を変えずに試す
`python3 scripts/generate_model.py --out test.xlsx`（同梱 DEFAULT_CONFIG で「人材紹介×スクール」型の例を生成）。

## 他業種への転用
BS/CF の連動機構・運転資本・税・資金トラフは業種非依存。**PL のドライバー行ブロックだけ差し替える**（method.md §6）。`generate_model.py` の `# PL funnel` 周辺を編集する。

## 保存先
案件成果物なのでこのリポジトリには保存しない。outputs（スクラッチ）に生成し、ユーザー提示後、案件の Drive フォルダ（`21.PJT資料/...` 等）へ格納する。
