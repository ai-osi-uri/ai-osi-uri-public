# デッキ構成（Deck Composition）

骨子（何を/誰に/どの順で信じてもらうか）は決まった。次は**それをスライドの並びに割る**工程。ここを飛ばして描画に行くと、「綺麗だけど何が言いたいか分からないデッキ」になる。

このスキルの仕事は1つ：承認済みの `storyline.md` を受け取り、**スライド構造（`slide-plan.md`）**に翻訳する。各スライドが何を言い切り、どの順で並び、どこで章が変わるかを決める。色も図形もまだ描かない。

```
storyline-gate → ★deck-composition（ここ）→ pptx-custom
  考える            構成する                  刷る
```

---

## 入出力（スキル間の契約）

- **入力**：承認済み `storyline.md`（コアメッセージ＋論理の骨子3〜5段＋証拠設計＋落とし穴）。無ければ先に storyline-gate へ。
- **出力**：`slide-plan.md`。スライドの順序リスト。各スライドは「Action title・1メッセージ・前からの繋ぎ（subtitle）・載せる証拠/ビジュアルの指定・所属する章」を持つ。
- **次工程**：`slide-plan.md` を pptx-custom に渡して描画させる。本スキルは描画しない。

---

## 構成の8原則

### 1. 枚数は骨子から導く（先に決めない）

「17枚で」「14枚で」と先に枚数を決めない。骨子の各段（3〜5段）を起点に、**1段が1枚で足りるか／複数枚に割るべきか**を判断して積み上げる。足りなければ足し、冗長なら畳む。結果として枚数が決まる。

### 2. 1スライド1メッセージ

1枚に主張を詰め込まない。骨子の1段が2つの主張を含むなら2枚に割る。**枚数を増やしてでも呼吸させる**方が、詰め込んで読ませるより伝わる。

### 3. タイトルは Action title（言い切る）

各スライドのタイトルは、**結論を1文で言い切る**。論点ラベル（「市場規模について」「課題」）にしない。

- ❌「市場規模」→ ✅「狙う市場は、競合と違う場所にある」
- 日本語 24pt で1行に収まる目安 **≤21文字**。収まらなければメッセージが二つある＝割る合図。

### 4. Subtitle は「繋ぎ」であってラベルではない

サブタイトルは前のスライドから現在へ橋を架ける。聞き手の無言の問い「なぜ今これを見ているのか」に答える。

- ❌「コア事業の説明」→ ✅「では本丸の CAIO 事業を——仕組み・価格・現状を見ていく」

### 5. ピラミッドで積む（縦は why/so-what、横は MECE）

頂点＝コアメッセージ。2段目＝骨子の3〜5主張。各主張に紐づくスライド群は、その主張の下で**重複せず漏れなく**並ぶ。縦は「なぜ？／だから？」で繋がる。骨子のピラミッドをそのままスライドの階層に落とす。

### 6. 概念は使う前に定義する

複数スライドで使う用語・略語（CAIO, ARR, NPS 等）は、**初出のスライドで**定義する。5枚後に「Xとは」を置かない。定義はサブタイトルにインラインで入れるか、使い始める前に定義スライドを1枚置く。

### 7. 15枚超はナビゲーションを付ける

長いデッキは「いま全体のどこか」を常に示す。3点セット：先頭付近の**目次**、章の変わり目の**章扉**、各スライド上部の**パンくず**（例：`PART C · 実行方法`）。繰り返し参照する中心図があれば**アンカー**にして、各詳細スライドを「この図のこのセルを今ズームしている」と接続する。

### 8. 用語を統一し、本編を未解決で終えない

同じ概念を別の語で呼ばない（「中核資産」と「横断資産」を混在させない）。「未解決の論点／TBD」スライドはクロージング直前に置かない——本編の最後を「まだ決まってない19個」で締めると、それまでの説得が崩れる。付録に回す。

## 最重要QA：声に出して読む

`slide-plan.md` ができたら、**各スライドの Action title と subtitle を、上から順に声に出して読む**。プレゼンするつもりで。

接続詞を足さずに自然に流れるなら、構成は通っている。「えーと、次は…」「これはつまり…」と**橋渡しの言葉を自分で発明したくなったら、その繋ぎ目のスライドが欠けているか順序が違う**。これは見た目のQAより重要——見た目のバグは聞き手が我慢するが、流れのバグは話し手が準備不足に見える。

## ワークフロー

```
0. storyline.md（承認済み）を受け取る。無ければ storyline-gate へ戻す
1. 骨子の各段 → スライドに割る（原則1〜2）
2. 各スライドに Action title と繋ぎ subtitle を立てる（原則3〜4）
3. ピラミッド整合・用語・定義・ナビを点検（原則5〜8）
4. 声に出して読むQA → 繋ぎ目の欠けを直す
5. slide-plan.md を確定 → pptx-custom に引き渡す
```

---

## 出力フォーマット（slide-plan.md）

pptx-custom が機械的に読める1枚。これがスキル間の受け渡し物。

```markdown
# Slide Plan: {相手} / {目的}
（出典 storyline: コアメッセージを1行で再掲）

## 章構成
- PART A: {章タイトル}（S1–S4）
- PART B: ...

## スライド一覧
| # | 章 | Action title（言い切り） | 1メッセージ | 繋ぎ(subtitle) | 載せる証拠/ビジュアル |
|---|----|------------------------|------------|---------------|--------------------|
| 1 | – | {表紙} | – | – | – |
| 2 | A | {言い切りタイトル} | {一文} | {前からの橋} | {図/数値/実物/モック} |
| … |
| N | – | {クロージング＝コアメッセージに回帰} | | | |

## ナビ要否
- 目次: 要/不要 ／ 章扉: 要/不要 ／ パンくず: 要/不要 ／ アンカー図: {あれば}

## 声出し読みQA
- 通った / 直した繋ぎ目: {…}
```

---

## やってはいけないこと

- **骨子なしで構成し始める** — 入力は承認済み storyline.md。無ければ storyline-gate へ。
- **枚数を先に決める** — 「17枚で」から入らない。骨子から積み上げる。
- **ラベルタイトル** — 「課題」「市場」で止める。言い切るまで確定しない。
- **骨子に無いスライドを足す** — かっこいいからで1枚増やさない。各スライドは骨子のどの段に紐づくか言えること。
- **描画に踏み込む** — 色・フォント・座標・図形を決める。それは pptx-custom の仕事。
- **声出しQAを飛ばす** — 構成スキルで一番効くQA。
