# 型：企画書

**読み手が決めること**：作るもの・やることの芯を信じて、進めてよいか。

下敷きにしているのは、ゲームディレクターの桜井政博氏が公開している企画書の作り方
（1ページに1項目、図か写真が1枚と文章2行、カテゴリーの切れ目に目次のページ、企画意図や調査は載せない）。
ただし、読み手が日程や判断もする場（役員会など）に出すときは、最後の「進め方」「決めてほしいこと」は残す。

---

## 考える（storyline-gate へ）

- コアメッセージを「課題 → 答え」の2つに分け、それぞれ一文で言い切る。課題は問いの形にする（例：「◯◯がいなくても、△△まで進められるようにするには？」）。
- 課題の前に「なぜ今それが課題なのか」を置く。前回の議論や受けた指摘があれば、それを出発点にする。
- **「他にない一点」**を1つだけ決め、骨子の要素として書く。似た案と比べて、これが無ければ価値が無いというもの。
- 答えは「最初に使う人が迷わず最後まで行ける」形を優先する。慣れた人が深く使える余地は別に残す。

## 構成する（deck-composition へ）

- 章は今までどおり問いの木から作る。そのうえで、**1枚に1つの問いだけに答える**。3つの指摘なら3枚にする。
- 各ページは「見出し＋図か絵1枚＋本文2行まで」。2行を超える説明はスピーカーノートへ回す。
- 大カテゴリー（章）と小カテゴリーを持たせ、全ページで「いまどの章のどこか」と全体の進み具合が分かるようにする。章の区切りに目次を再掲する。
- 「他にない一点」は1枚まるごと使う。
- 中身の具体（使う場面・画面など）は1つずつ1枚にする。
- 読み手が日程や判断もする場なら、最後に「進め方」「できたかの判定」「決まったこと／決めてほしいこと」を置く。そうでなければ削る。

## 刷る（pptx-custom へ）

- 図は、言いたいことの形が一目で分かるものにする（流れ・集中・比較 など）。箇条書きで済ませない。
- 使う場面や画面の説明は、画面の見本を図形で描いて置く（日本語の UI は AI 画像にしない）。実物ができたら実際の画面の写真に差し替える。
- **要所だけ**（表紙・課題・他にない一点・比喩のページ）、イメージの絵を全面に置き、片側を暗くして言葉を載せる。全ページには入れない（リズムが消える）。
- イメージの絵は AI 画像生成で作ってよい（pptx-custom「AI-Generated Images」）。文字・ロゴ・実在の人物や製品が写らないようにし、言葉を載せる側を暗く空けるよう指示する。
- 絵を入れたら描画して画像で確かめ、言葉が絵の明るい部分に重なっていないかを見る。

## 載せないもの

- 企画意図の長い説明、市場調査、グラフ、代わりの案。狙いはスピーカーノートか社内用の資料へ。
- 相手に渡す場合、相手の内情の分析やこちらの勝ち筋。
- 確かめていない数字。仮に置いた日程・数字は「仮置き」と書き、画面見本の会社名などが架空であることはノートに書く。

## 仕上げの点検

- 表紙から最後まで、1ページ1項目になっているか。
- 課題と答えを、それぞれ一文で言えるか。
- 「他にない一点」が1枚まるごと使って見せられているか。
- 本文が2行を超えているページが残っていないか。
- 全ページで、進み具合と「いまの章・小項目」が分かるか。
- 全面の絵は要所だけか。言葉が絵に埋もれていないか。
