# Wiring Diagram Intake

画像から直接きれいな図を描かず、先に再利用可能な構造化正本を作る。

## 入力

- 元画像またはPDF。複数枚可
- 分かれば拠点名、階、部屋、図面の向き
- 必要な成果物と対象範囲

## ワークフロー

1. 元ファイルを保持し、回転、傾き、台形、明暗、解像度を確認する。
2. 必要なら補正画像と領域別クロップを作る。補正で文字や線を創作しない。
3. 部屋・ラック・機器・回線・電源・凡例を先に抽出する。
4. 接続線を端点から追い、機器、ポート、媒体、ラベルを記録する。
5. 読み取れない情報へ `unknown-*` ID、信頼度、画像座標、質問を付ける。
6. 矛盾を検出する。例: 存在しないポート、片端だけのケーブル、重複IP。
7. 重大な不確実点だけを優先してユーザー確認し、回答履歴を残す。
8. 確定版 `network-source.json` と確認レポートを出力する。

## 確認優先度

- `P0`: 接続先、機器種別、台数など図面・BOMを変える
- `P1`: 型番、ポート番号、媒体など調達・施工を変える
- `P2`: 表示名、色、注記など後で直せる

P0が未解決のままレンダリングへ進まない。

## 出力

```text
intake/
├── original/
├── normalized/
├── network-source.draft.json
├── clarification.md
├── decisions.jsonl
└── network-source.json
```

## ガードレール

- 線の交差と接続点を区別する。
- 型番の一部が読めても、完全一致として確定しない。
- ポート数や製品仕様を記憶で補完しない。
- IP、認証情報、顧客名など機微情報の公開範囲を確認する。
- 元画像、補正画像、抽出結果の対応を追跡可能にする。
