# exec-deck-patterns — 経営層デッキの設計原則（深掘り）

内部合意・経営層向けデッキで効く原則を1か所にまとめた深掘りリファレンス。**構成（どのスライドが何を言い、どう並ぶか）の判断そのものは `deck-composition` の責任**。本書はその判断を支える原則と、`pptx-custom` が刷るときに守る言語・体裁のルールを示す。`deck-composition` は要約参照として、`pptx-custom` は各スライドを刷るときの「言い切り・タイポ・パレット」の拠り所として読む。

---

## 1. Action title（言い切りの見出し）

各スライドのタイトルは**主張を述べる文**にする。「売上分析」ではなく「主力3商品が粗利の80%を生み、残り40SKUは赤字」。タイトルだけを上から順に読むと、デッキ全体の論理が一本のストーリーとして通る——これが Action title の合格条件。

- ✅「初期費用ゼロのCAIO契約なら、3ヶ月で投資回収できる」
- ❌「料金プラン」「コストについて」（トピックの提示で、主張がない）

判定法：**タイトルだけを順に音読**して、聞き手が「で、結論は？」と思わず頷ける流れになっているか。なっていなければタイトルが description（説明）に留まっている。

## 2. Message, not description（説明でなくメッセージ）

スライド本文も「何があるか」でなく「だから何か（So what）」を言う。データは主張の**証拠**として置く。グラフを貼って終わりにしない——そのグラフが言わせたい一文をタイトルかキャプションに必ず書く。

- 説明モード：「アンケート結果：満足度は72%」
- メッセージモード：「満足度72%——競合平均を18pt上回り、価格改定の余地がある」

## 3. WHY / HOW critique（1枚ごとの自己批判）

各スライドに2つ問う。**WHY**：この聞き手にとって、なぜこのスライドが要るのか（消せないか）。**HOW**：その主張をどう証明しているか（証拠は十分か）。WHY に答えられないスライドは削る。HOW が空のスライドは証拠を足すか、主張を落とす。経営層デッキが膨れる最大要因は「あると安心だが意思決定に効かない」スライドの放置。

## 4. One message per slide（1スライド1メッセージ）

1枚で言い切るのは1つだけ。2つ言いたくなったら2枚に割る。聞き手は1枚から1つしか持ち帰らない。箇条書きが5つ以上、または相互に無関係な要素が並ぶスライドは、メッセージが割れているサイン。

## 5. Pyramid principle（ピラミッド／Minto）

結論を先に置き、その下に「なぜそう言えるか」を MECE な3本前後の柱で支える。

```
        【結論：この提案でやるべき】
       /            |             \
  根拠A          根拠B           根拠C
 (データ)        (データ)         (データ)
```

- **トップダウン**：表紙の次（または冒頭サマリ）で結論を述べ、以降のスライドが根拠を1本ずつ展開する。経営層は結論から聞きたい。
- **MECE**：根拠の柱は漏れなくダブりなく。3本が基本、多くて4本。5本を超えたら粒度が細かすぎる＝1つ上の抽象でくくり直す。
- **各柱がサブピラミッド**：根拠Aのスライド群もまた「Aの結論→その証拠」で組む。入れ子で同じ形を保つ。

> 並び順・章立て・どの柱を立てるかは `deck-composition` が `slide-plan.md` で決める。本書は「結論ファースト＋MECEな3本柱」という形の根拠を与えるだけ。

## 6. タイポグラフィ規則

| 役割 | サイズ | ウェイト | 備考 |
|---|---|---|---|
| スライドタイトル（Action title） | 28–40pt | bold | 2行に収める。3行になるなら言葉を削る |
| セクション/章扉タイトル | 40–54pt | bold | 章扉は大きく、余白を贅沢に |
| 本文 | 14–18pt | regular | 左揃え。中央揃えは見出しのみ |
| キャプション/出典 | 9–11pt | regular, muted | グラフ下の出典・注記 |
| 数値の主役（KPI） | 44–80pt | bold | 「3ヶ月」「80%」など1枚の主張数値は特大に |

- ヘッダーは個性のあるフォント＋本文はクリーンなフォントの対。Arial 既定にしない。
- タイトルと本文の**サイズ差を十分に**（タイトル32pt以上／本文14–16pt）。差が無いと階層が消える。
- **タイトル下のアクセント線は引かない**（AI生成スライドの典型。余白か背景色で階層を作る）。

## 7. パレット（支配色の作り方）

1色を支配色（視覚的重みの60–70%）、支える1–2色、鋭いアクセント1色。全色を均等にしない。社内案件は `brand-design.md`（osi-sales / proposal-estimate 配下のブランド規約）を最優先。汎用の引き出しは `pptx-custom` の SKILL.md「Color Palettes」を参照。

- **サンドイッチ構造**：タイトル/結論スライドはダーク地（白文字）、中身はライト地、締めは再びダーク。リズムと「ここが要点」の合図になる。
- 色は名前付き定数でスクリプト冒頭に定義（`const NAVY='1E2761'`）。生 hex をインラインに書かない。
- コントラスト比は本文で4.5:1以上。明地に明文字／暗地に暗アイコンを避ける。
