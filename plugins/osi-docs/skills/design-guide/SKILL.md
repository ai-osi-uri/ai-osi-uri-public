# design-guide（デザインの作り方の共通ルール）

## これは何か

資料・文書・表・画面を作るときの「作り方の決まり」。色やロゴの決まりではない。
会社が違っても、媒体が違っても成り立つことだけを書いている。
**会社の色は持たない。** 使う会社の色は「6. 会社の色を差し込む」で入れる。

使い方：何かを作る前に「1. 共通」を読み、作る媒体の章を読む。作り終えたら「7. 出す前の確認」を通す。
細かい実例と測った数字は `references/` にある（参考。条件が変われば上書きしてよい）。

### 書き方の印
- **太字の言い切り** … 守る決まり。破ると読み手に伝わらなくなる
- 「→ 自問：」 … 迷ったときに自分に聞く問い。決まりに書いていない場面もこれで判断する
- 引用ブロック … 一度の実例。日付と条件つき。参考にとどめる

## 1. 共通（全部の媒体）

### 1-1. 作る前に「誰に・なぜ・何を」を決める
**作り始める前に、読み手・その人がこれを見て決めること・こちらが出すもの、の3つを1行ずつ書く。**
これが無いと、どれだけ見た目を整えても「で、何の話？」になる。
- 会議で使う資料は、最初に「この場で合意したいこと」を書き、そこから話す順番を組む
- 作ったもの（アプリ・試作）を見せるときも、〈誰に・なぜ・何を出す提案か〉を必ず添える

→ 自問：読み手はこれを見終わったあと、何を決めればいいか分かるか。

### 1-2. 読み手が主語
**「自分たちの業務」「弊社のサービス」を主語にしない。** 読み手が「うちとは違う」と感じた時点で読まれなくなる。
型（抽象）は型として示しつつ、読み手が自分の場面に置きかえられる具体的な場面で書く。

→ 自問：この1文の主語は誰か。読み手に置きかえられるか。

### 1-3. 普通の言葉で書く
**抽象語・カタカナ語・社内用語を使わない。** 読み手が意味を考えた時点で、内容が入らなくなる。

避ける言葉の例（具体的に禁止する）：
- 「説明可能性」「ソリューション」「シナジー」「エンパワー」「ケイパビリティ」「アジリティ」
- 「〜を最適化」「〜を推進」「〜の高度化」のように、何が変わるのかが書いていない動詞

言いかえ方：その言葉で「何が・どう変わるか」を書く。（例：「業務を最適化」→「毎月3日かかる集計が半日になる」）

### 1-4. 相手に決めてもらうことは、答えられる質問にする
**「ご検討ください」で終わらせない。** 選択肢・数字・名前で答えられる問いにする。はい／いいえで終わる問いも避ける。
数字を出すときは、**こちらの試算か、相手の計画か**を必ず書く。

→ 自問：相手はこの質問に、その場で一言で答えられるか。

### 1-5. 社外に渡すものと社内用を分ける
**相手に渡す文書に、相手の内情の分析やこちらの狙いを書かない。** 口で言うのと文書に残るのは別物。
背景の分析が要るときは、社内用の資料を別に作る。

### 1-6. 固有名詞は一字ずつ確かめる
**相手の会社名・人名・役職・住所は、書く前に公式の情報で一字ずつ確かめる。** 間違いは中身の良さを全部打ち消す。
確かめられない名前は、相手のメール署名どおりに書く。役職が確かめられなければ付けない。

### 1-7. 他社の例を出すときは時期を書く
**事例には「何年何月の話か」を添える。** 古い例を最新の話と誤解させないため。

### 1-8. 見やすさの最低線（全媒体）
- **薄い色の文字・小さい文字を使わない。** 「見にくい」は内容を読まれない理由として一番多い
- **強調は1か所に絞る。** 全部を太字にすると、どこも強調されない
- **強調は濃い色の太字で。** 色だけ・下線だけ・細字の色変えは弱い
- 背景と文字の明るさの差を十分にとる（目安は references/observations.md）

## 2. スライド

### 2-1. 構成
- **1枚に言いたいことは1つ。** そのスライドのタイトルは、言いたいことを言い切る文にする（「現状」ではなく「集計に毎月3日かかっている」）
- **章立ては読み手の問いの順に並べる。** 型（課題→解決→効果）に当てはめるのは、読み手の問いがその順のときだけ
- 相手に渡す版に「前回からの変更点」の章は入れない（社内の事情であって、読み手の関心ではない）

### 2-2. 目次
**目次は「番号つきの章＋小項目」の短い一覧にする。** 各章の始まりに同じ目次を出し直し、これから話す章だけ濃く、他は薄くする。
右側に「その章で話すこと」を一言添えてもよい。

### 2-3. 余白とレイアウト
**中身が数行しかない項目を、縦長のカードで横に並べない。** 下半分が空いて、手を抜いたように見える。
そういう内容は、上から下に並べる一覧にする。

**スライドに大きな空白を残さない。** 空いたら、文字を大きくするか、図や画像を入れる（画像は生成してよい）。

→ 自問：このスライドを縮小して見たとき、空白が目立たないか。
→ 自問：カードの中身の量は、カードの大きさに見合っているか。

### 2-4. カード・図
- カードは「同じ種類のものを並べて比べさせたい」ときに使う。単に区切るためだけに使わない
- 図は、文章では伝わりにくい「並び・つながり・大きさの違い」があるときだけ使う
- 表を入れたスライドは、**画像にして最後の行まで目で確かめる**（折り返しで行が伸び、はみ出すことがある）

## 3. Word の文書

- **最初の段落で「この文書は何のためのもので、読み終えたら何を決めるか」を書く**
- 見出しは3段階までにする。それより深くなるなら、章を分ける
- 表は「比べる」「一覧で引く」ためだけに使う。文章で書けることを表にしない
- **マニュアルは、相手に説明するためのものとして書く。** 社内の作業手順書と混ぜない
- 手順は番号つきの一覧にし、1つの番号に1つの操作だけを書く
- 画面の説明は、ボタンや項目の名前を画面の表記どおりに書く（言いかえない）

## 4. Excel

- **入力するセルと、計算で出るセルを見た目で分ける。** 触ってよい場所が分からないと、計算式が上書きされる
- **数字は計算式でつなぐ。** 計算した結果の数字を手で打ち込まない（元を直しても連動しなくなる）
- 単位（円・千円・%・人）を見出しか書式で必ず示す。同じ表の中で単位を混ぜない
- **数字の出どころを書く。** こちらの試算か、相手の計画か、公表資料か
- 1枚目に「この表の見方」（何の表か・どこに入力するか・どこが結果か）を置く
- 見出し行は固定し、印刷やPDFにするときは1ページの幅に収める

## 5. アプリ・画面

### 5-1. 作る前に
**画面を作る前に、要件（誰が・何のために・どの順で使うか）を文章で決める。** 要件なしで作った画面は「しょぼい」と言われる。
議事録や依頼の記録があれば、それを元に要件を書く。

### 5-2. 部品は shadcn/ui の標準を使う
**ボタン・入力欄・選択肢・カード・表・ダイアログ・タブ・通知などは、shadcn/ui の部品をそのまま使う。** 自前で作り直さない。
部品ごとの見た目・動き・押しやすさが既に作り込まれていて、作り直すと品質が下がる。
- 色は shadcn/ui の色の変数（`--primary` `--background` など）で決める。部品の中に色を直接書かない
- 会社の色を当てるときは、変数の値だけを差し替える（6章）
- 部品の選び方の早見表は references/app-screens.md

### 5-3. 画面の並べ方
- **1つの画面でやることは1つ。** そのために一番押してほしいボタンは1つだけ目立たせる
- 大事な情報を左上に置く。読む順に上から下へ並べる
- 空っぽの状態（まだデータが無いとき）に何をすればいいかを画面に書く
- エラーは「何が起きたか」と「どうすればいいか」を普通の言葉で書く
- スマートフォンの幅でも崩れないか確かめる

→ 自問：初めて開いた人が、説明なしで最初の一歩を押せるか。

## 6. 会社の色を差し込む

本スキルは色を持たない。使う会社ごとに、次の順で決める。

1. 会社の設定ファイル（例：`osi-profile.md` の `brand`）に色・フォントがあれば、それを使う
2. 依頼の中で色やロゴが指定されていれば、それを使う
3. どちらも無ければ、**中立の色（白・黒・灰）＋強調色1色**で作る。強調色は濃い青系を既定にする

決める項目は次の4つだけ：
| 項目 | 何に使うか |
|---|---|
| 主色 | 強調の太字、一番押してほしいボタン、見出しの線 |
| 文字色 | 本文（ほぼ黒） |
| 背景色 | ページ・スライドの地（ほぼ白） |
| 注意色 | 警告・削除など、気をつけてほしい操作だけ |

**色を増やさない。** 4色で足りないと感じたら、色ではなく配置や大きさで区別できないかを先に考える。

アプリでは、この4つを shadcn/ui の変数（`--primary` `--foreground` `--background` `--destructive`）に入れる。
スライド・Word・Excel では、同じ4色を各スキルのテーマ設定に渡す。

## 7. 出す前の確認

作り終えたら、出す前に次を全部確かめる。1つでも引っかかれば直してから出す。

- [ ] 読み手・決めてもらうこと・出すもの（1-1）が、成果物の最初で分かるか
- [ ] 主語が読み手側になっているか（1-2）
- [ ] 抽象語・カタカナ語が残っていないか（1-3 の禁止の例で探す）
- [ ] 相手への質問は、その場で答えられる形か。数字の出どころが書いてあるか（1-4）
- [ ] 社外に渡すものに、社内向けの分析が混ざっていないか（1-5）
- [ ] 固有名詞を公式の情報で確かめたか（1-6）
- [ ] 薄い色・小さい文字・大きな空白が無いか（1-8、2-3）
- [ ] 表・図がはみ出していないか、画像にして目で見たか（2-4）
- [ ] 確認をお願いするときは、素材ではなく**相手に出す完成形そのもの**を見せているか
