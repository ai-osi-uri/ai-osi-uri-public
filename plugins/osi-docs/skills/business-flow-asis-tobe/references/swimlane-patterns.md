# スイムレーンの典型パターン

業務フローには繰り返し現れる「型」がある。実装するときはこの型を意識すると、矢印が絡まずに済む。

## パターン1 — 線形（Linear）

A → B → C → D と流れる単純な業務。例：取込、登録など。

```
レーン1 [A] → 
レーン2          [B] →
レーン3                 [C] →
レーン4                        [D]
```

```json
"flows": [
  { "path": [[0,0],[1,1],[2,2],[3,3]], "color": "RED" }
]
```

## パターン2 — 往復（Round-trip）

依頼→処理→返却。例：与信、API コール、メール往復。

```
レーン1 [依頼] →                      [受領]
レーン2          [処理] → [返却] ↗
```

```json
"flows": [
  { "path": [[0,0],[1,1]] },
  { "path": [[1,1],[1,2]] },
  { "path": [[1,2],[0,3]] }
]
```

または `bidir: true` で1本の双方向矢印にまとめる：
```json
{ "path": [[0,0],[1,0]], "bidir": true }
```

ただし bidir は上下方向の隣接レーンに使う場合のみ推奨。横長になると矢印の意味が読みづらくなる。

## パターン3 — 分岐（Branch）

成功時 vs 失敗時で別ルート。例：RPA 成功率60%／失敗40%は手動。

```
レーン1                     [手動フォール]   <- 失敗ルート
レーン2 [起動] → 
レーン3          [画面操作60%] → 
```

ルートを分けるときは **2つの flows を並行で書く**：
```json
"flows": [
  { "path": [[1,0],[2,1]], "color": "GREEN" },          // 成功ルート
  { "path": [[2,1],[0,1]], "color": "RED", "labels": ["失敗40%"] }  // 失敗ルート
]
```

または、単一フローに `labels` で注釈をつける。

## パターン4 — 多者間ラリー（不備対応）

NEXT ONE ⇄ 代理店の往復が複数回発生する。実装上はループを書かず、**代表的な1往復＋「×2-5往復」タグ**で表現する。

```
NEXT ONE [起票]                      [確認] x2-5往復
代理店           [回答] →
```

```json
"actions": [
  { "lane": 0, "slot": 0, "label": "Backlogで\n起票する" },
  { "lane": 1, "slot": 1, "label": "Backlogで\n回答する" },
  { "lane": 0, "slot": 2, "label": "回答を\n確認する", "tag": "×2-5往復" }
],
"flows": [
  { "path": [[0,0],[1,1],[0,2]] }
]
```

## パターン5 — 集約（Fan-in）

複数レーンから1つに集約。例：複数システムから DB へ書き込み。

```
レーン1 [A1] ↘
レーン2 [A2] → [DB に保存]
レーン3 [A3] ↗
```

これは flows を3本書くのが素直：
```json
"flows": [
  { "path": [[0,0],[3,1]] },
  { "path": [[1,0],[3,1]] },
  { "path": [[2,0],[3,1]] }
]
```

## パターン6 — 並列（Parallel）

同時に複数のことが起きる。例：AI が並行で正規化・スコアリング。

スイムレーン上では「同じスロットに複数レーンのアクション」として描く：

```
レーン1                    [HITL選択]
レーン2 [正規化] → [スコアリング] →
レーン3        [API取得] ↗
```

時系列軸とレーン軸の交点が同じslotでも、複数のアクションが共存できる。スロット内で時間順序が必要なら、スロットを分ける。

---

## どのパターンを使うか迷ったとき

- **AS-IS のスイムレーンは複雑になりがち**。NEXT ONE 営業のような中央人物に矢印が集中する。これが「ボトルネック可視化」になるので、無理に整理しない
- **TO-BE のスイムレーンは AI Agent / システムレーンに矢印が集中する**ように設計する。これが「人間の解放」を視覚化する
- 1スライドあたりの flows は **6本まで**を目安に。これ以上は読めなくなる

迷ったら：パターン1（線形）に近づける。AS-IS で矢印が絡むのは「業務が絡んでいる」サインなので、それ自体が情報。
