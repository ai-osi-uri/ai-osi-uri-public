# 確かめて直す（knowledge-compare）

## §0 定義と不変条件

**確かめた** とは、①比べるやり方と相談が決まり、②やり方ごとに別々に答えが作られ、③伏せた資料で本人が順位を付け、④結果が数えられ、⑤決まりが書き換えられた（または、変えないと決まった）状態を指す。

不変条件（破ったら失敗）：

- **最初に決まりを読む。** 決まりの入口は `90_決まり/決まり.md`。無ければ `90_Meta/決まり.md`。そこに、置き場所の名前と、答え方・書き方・比べ方のノートの場所が書いてある。読むのは決まりの入口と、そこが指す「比べ方」のノート。やり方はそこに書いてあるものを正とする
- **答えは別々に作る。** やり方ごとに別の担い手に答えさせ、互いの答えも、他のやり方の存在も見せない。比べている本人（この会話）が答えを書かない
- **条件をそろえる。** 相談者の設定、長さ、書き方。どのやり方で作ったか分かる言葉（ノートの名前、決まりの言葉）を答えに書かせない
- **伏せる。** ラベルは相談ごとに入れ替える。対応表は、本人が順位を付け終わるまで見せない
- **物差しを都合よく足さない。** 足すなら、前の回の採点で見つかった弱点だけ。足したことは結果に書く
- **決めつけない。** 相談が十問に満たないうちは「そういう向きが見えた」と言う。道具の採点と本人の順位が食い違った所を、一番の手がかりとして報告する
- 負けた所を消さない。どの種類の相談で負けたかを、決まりのノートに残す

事故の型：比べている自分が答えを書いて、知っている結論に寄る／試したいやり方にだけ丁寧な指示を出す／採点の観点を、勝たせたいやり方の指示と同じ言葉にする／六問の結果で「証明された」と言う。

## 手順

1. **何を比べるか決める。** 二つ以上。いつも「ノートを読まない答え」を一つ入れる（ノートが効いているかの基準になる）
2. **相談を集める。** 五〜十問。半分は元の場面がノートにあるもの、半分はノートに無い分野のもの。本人が最近ほんとうに迷ったことを優先する。ノートの言葉を使わず、人が普通に相談する言い方にする
3. **答えさせる。** やり方ごと・相談ごとに別の担い手に頼み、答えの本文だけを `<作業フォルダ>/答え/<やり方の名前>/<相談の番号>.txt` に書かせる。ノートを読むやり方は、読むだけで書き込ませない
4. **伏せて組む。** `python3 scripts/blind.py assemble --answers <答え> --questions <問い.json> --out <比べる資料.md> --key <対応表.json>`
5. **順位を付ける。** 本人に資料を渡す。あわせて採点の担い手を二人立て、見立て・気づき・自分の側で決められること・外れたときの備え、の四点と順位を付けさせる（対応表は渡さない）
6. **数える。** 順位を `順位.json` にまとめ、`python3 scripts/blind.py tally --key <対応表.json> --ranks <順位.json>`。やり方ごとの順位の平均と一位の数、相談の種類ごとの勝ち負けを出す
7. **読む。** どの種類の相談でどのやり方が勝ったか／負けた答えに共通していた弱点／本人と採点の担い手が食い違った所
8. **直す。** 勝ったやり方に合わせて決まりのノートを書き換える案を出し、本人が決めたら書き換える。比べた日付・相談の数・結果・限界を、決まりの下に数行で残す。変えないと決めた場合も、その旨を残す
