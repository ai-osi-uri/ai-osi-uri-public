# 束ねる（knowledge-bundle）

## §0 定義と不変条件

**束ねた** とは、①全部の型の「なぜ」を読み、②束ねた案を根拠つきで出し、③本人が決め、④本質のノート・型の親・入口の一覧が書かれ、⑤説明できなかったものが未解決として残された状態を指す。

不変条件（破ったら失敗）：

- **最初に決まりを読む。** 決まりの入口は `90_決まり/決まり.md`。無ければ `90_Meta/決まり.md`。そこに、置き場所の名前と、答え方・書き方・比べ方のノートの場所が書いてある。読むのは決まりの入口と、そこが指す「書き方」のノートの、型から本質への部分。確かめ方はそこに書いてあるものを正とする
- **案を出すまでが道具の仕事。** 本質を足す・変える・題を決めるのは本人。案は受け箱に置き、決まるまで本質のフォルダに書かない
- **本質は性質の形で書く。** 「こうする」でなく「こうできている」。手の形のままなら、まだ本質ではない
- **束ねすぎない。** 一つの本質に入れた型の「なぜ」が二系統以上に割れたら分ける。一本の型が二つの本質に入ってよい
- **根拠の薄さを隠さない。** 「なぜ」が空の型は、結論だけから割り当てたと明記する。食い違う型を説明できない組は、未解決のまま書く。無理に片付けない
- **他人の本質を持ち込まない。** 本で読んだ性質や、別の人の一覧から始めない。本人の型から上げる
- 本質のノートの「自分の言葉で一行」は空ける

事故の型：きれいな数に合わせて束ねる／どの型にも当てはまる広すぎる一文にして、問いが立たなくなる／束ねた結果、一本の型に何でも入って読めない長さになる／案をそのまま書き込んで、本人が決めた感覚を持てない。

## 手順

1. 決まりを読む
2. **全部の型を読む。** `python3 scripts/list_types.py --dir <型のフォルダ>` で題・結論・なぜ・親を一覧にする。「なぜ」が空の本数を先に伝える。長すぎる型（一万字を超えるもの）があれば、束ねる前に分ける案を出す
3. **束ねる。** 同じ「なぜ」で束ね、束ごとに一文にする
4. **三つで確かめる。** 性質の形か／もう一度「なぜ」と聞いてまだ下があるか／食い違って見える型を両方説明できるか。下があるなら一段下げ、同じになったものは一つにする
5. **案を出す。** 受け箱に `本質の案_日付.md` を置く。本質ごとに、一文・問い・現れ方（型のリンク）・自分の側で決められること・境目とまだ言えないこと。どこにも入らなかった型、根拠の薄い割り当て、未解決の食い違いを最後に並べる
6. **本人が決める。** 言い方、束の切り方、数を直してもらう。見てもらうのは「まだ下があると感じるか」と「この粒で考え始められるか」
7. **書く。** 本質のノートをひな形で書く／型の題の下に親を書く／入口の一覧に本質と問いを並べる／説明できなかったものを入口の「まだ説明できていないもの」に書く
8. **確かめを勧める。** 入口ができたら、`knowledge-compare` で、束ねる前の読み方と比べてみることを一言勧める

やり直す目安：型が二十本ほど増えた／「まだ説明できていないもの」が五つを超えた／答えがしっくり来なくなった。
