# 透明性レポートのフォーマット

知識化完了後、必ずこのフォーマットでレポートする。これが「自律実行 + ユーザーが確認可能」を成立させる仕組み。

## なぜ透明性レポートが必須か

スキルが自律的にタイプ判定・保存先・命名・リンクまで決めてしまうと、ユーザーは「何が起きたか」が見えなくなる。Obsidian で目視確認しなくても、レポートを見るだけで現状が把握できる粒度で報告する。

これがあることで、ユーザーは：
- 安心してスキルに任せられる
- 「あ、その分類は違う」と即修正できる
- 後から振り返って「あの時何を保存したか」を再現できる

## 標準フォーマット

```
✅ 知識化完了

新規作成（N件）:
- [フルパス]
- [フルパス]

既存ノート更新（M件）:
- [フルパス]  ← [どこに何を追記したか1行で]

新規リンク（K本）:
- [新ノート] ⇔ [[既存ノート]]
- [新ノート] ⇔ [[既存ノート]]
```

`✅ 知識化完了` の絵文字は使う（このスキルでは例外的に許可。スキャン性が高いため）。それ以外の場所では vault の絵文字禁止ルールに従う。

## 例：複数ノート作成 + 既存更新

```
✅ 知識化完了

新規作成（2件）:
- 20_Concepts/AIで提案書を作るときの3原則.md
- 50_Resources/Anthropic_Claude公式ドキュメント.md

既存ノート更新（1件）:
- 60_Areas/営業・提案.md  ← 「関連 Concepts」セクションに新ノートのリンクを追加

新規リンク（4本）:
- AIで提案書を作るときの3原則 ⇔ [[提案書は人から施策の順序が正解]]
- AIで提案書を作るときの3原則 ⇔ [[最先端AIとして踏み込むモード]]
- AIで提案書を作るときの3原則 ⇔ [[Anthropic_Claude公式ドキュメント]]
- AIで提案書を作るときの3原則 ⇔ [[営業・提案]]
```

## 例：既存更新のみ（新規ノートなし）

```
✅ 知識化完了（既存ノート更新のみ）

既存ノート更新（1件）:
- 20_Concepts/提案書は人から施策の順序が正解.md  ← 「反例・限界」セクションに新しい反例を1件追記

新規リンク: なし（既存リンクで十分）
```

## レポートの後に書いてよいこと（任意・最小限）

レポート本体の後、以下のいずれかが該当する場合のみ、**1-2行**で補足する：

- 判断に迷った場面（「Conceptか Resourceか迷ったが Concept 重心とした、必要なら教えてください」）
- 検討したが採用しなかった代替案（「単一ノートで書く案も検討したが、3つに分割しました」）
- ユーザーが見落としそうな注意点（「リンク先の `[[既存Concept]]` は arichived ですが、内容的には関連していたためリンクしています」）

## レポートの後に書いてはいけないこと

以下は冗長・不要：

- ❌ 各ノートの全文要約（ユーザーは Obsidian で直接読める）
- ❌ 「ご確認ください」「ご質問あれば」のような社交辞令
- ❌ 「保存に成功しました！」のようなテンション高めの完了報告（レポート自体がそれ）
- ❌ frontmatter の中身を全部表示（必要なら Obsidian で見る）

レポート → 終わり。次の指示を待つ。

## 報告対象の優先順位

レポートには全てを書かなくてよい。重要度順：

1. **新規作成ノート全件**（必ず）
2. **既存ノート更新内容**（必ず、ただし「どこに何を」を1行で）
3. **主要リンク**（最大 5本程度、それ以上は「他N本」と省略可）
4. **ハッシュタグの追加**（重要なら言及、些細なら省略）
5. **削除した既存ノート**（必ず明示、削除は重大なため）

リンクが10本以上になる場合：

```
新規リンク（12本）:
- 主要リンク 5本を列挙
- ...他7本（うち4本が[[60_Areas/営業・提案]]への集約用）
```

## 削除を伴う場合の特別フォーマット

統合により既存ノートを削除する場合は、削除を最初に明示：

```
✅ 知識化完了（統合あり）

⚠️ 既存ノート削除（1件）:
- 20_Concepts/旧ノート名.md ← 新Concept[[新ノート名]]に統合済み

新規作成（1件）:
- 20_Concepts/新ノート名.md

新規リンク（3本）:
...
```

削除は重大な操作なので必ず ⚠️ マーカーで目立たせる。
