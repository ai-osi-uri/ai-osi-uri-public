# 出典表記のフォーマット

vault から引用する時は必ず出典を示す。これにより：
- ユーザーが Obsidian で原文に飛んで詳細を確認できる
- 「Claude の見解」と「ユーザー自身の蓄積」を分離できる
- 出典のないノート（=Claudeのハルシネーション）の混入を防げる

## 基本フォーマット：`[[ノート名]]`

Obsidian 互換のリンク記法をそのまま使う。

例：
> 提案書では「人→施策」の順序が重要です（[[提案書は人から施策の順序が正解]]）。

ユーザーがこの回答を Obsidian にコピペすれば、リンクが生きる。

## 文脈に応じた出典の置き方

### 1主張 = 1出典の場合

主張の直後に括弧で添える：

```
売上の絶対額推定は当てても外しても聞き手に不快感を与えます（[[売上推定の絶対額を出すリスク]]）。
```

### 1主張 = 複数出典の場合

カンマ区切り：

```
営業のトーンは相手の文化に合わせるべきで、これは
スピーチで違和感が顕在化します（[[提案書は人から施策の順序が正解]], 
[[スピーチ書き起こしレビュー法]]）。
```

### セクション全体が同じ出典の場合

最初に明示：

```
## サンプル提案書での教訓

以下は [[2026-04-29_提案書ディスカッション]] での議論から：

- 表紙コピーは相手のブランドトーンに合わせる
- 売上絶対額推定は越権リスク
- スピーチで読み上げると紙では見えない違和感が出る
```

### 引用と所感を区別する

vault の内容と、Claudeの解釈は明確に分ける：

```
[[最先端AIとして踏み込むモード]] によれば、AIに「踏み込め」と
明示的に許可することで出力の質が桁違いに変わります。

私（Claude）の解釈としては、これは AI の「保守バイアス」を
プロンプトで解除する手法と捉えられます。同種の効果は他の領域でも
報告されています。
```

## NGな出典表記

### ❌ 出典のない断言

```
売上の絶対額推定は当てても外しても聞き手に不快感を与えます。
```

→ vault の知識を使ったのか、Claudeの一般論なのかが分からない。

### ❌ ノート名を曖昧にする

```
あなたの過去のノートで...
あるノートで...
```

→ ユーザーが原文に辿り着けない。

### ❌ 出典のフォーマットを変える

```
（営業ノートより）
【出典: 提案書は人から施策の順序が正解】
```

→ Obsidian で生きるリンクにならない。`[[ノート名]]` を厳守。

## 引用の長さ

vault のノートから引用する時は、**短く・的確に**：

- ✅ キー主張だけを抜き出して引用
- ✅ 必要なら自分の言葉で要約 + 出典
- ❌ ノート全体を貼り付ける（読み手が処理できない）
- ❌ 関係ない部分まで引用する

## 「ない」も明示する

vault に該当情報が見つからなかった場合、それを必ず示す：

```
営業領域については [[提案書は人から施策の順序が正解]] 等の Concepts が
ありますが、「初回打ち合わせ後のフォローアップ」については vault に
直接のノートが見当たりませんでした。

このトピックは新規 Concept として書く価値がありそうです。
書きたければ「知識化して」と言っていただければ追加します。
```

これにより、vault の盲点が明らかになり、capture スキルへの橋渡しになる。

## ノートが archived の場合

`status: archived` のノートを引用する時は、その旨を添える：

```
過去には [[旧手法ノート (archived)]] のような考え方をしていましたが、
現在は更新されています。
```

これにより、古い情報を引用するリスクを減らす。

## まとめ：3つの鉄則

1. **必ず `[[ノート名]]` 形式**で出典を示す（Obsidian リンク互換）
2. **vault の内容と一般論を分離**する（出典の有無で区別）
3. **「ない」も明示**する（盲点の発見と capture への接続）
