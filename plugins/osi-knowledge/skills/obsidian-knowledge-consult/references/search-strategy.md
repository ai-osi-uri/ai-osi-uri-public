# 効果的な検索戦略

vault は意味的に組織化されているが、`obsidian_simple_search` はキーワード一致ベース。検索戦略次第で、見つかるノートの量と質が桁違いに変わる。

## 多角検索の基本

1回の検索で諦めない。以下の4軸で複数回検索する：

### 軸1: 概念名そのもの

ユーザーの問いに含まれる主要キーワードをそのまま検索。

例：「初回提案について教えて」
→ `初回提案` で検索

### 軸2: 同義語・関連語

同じ概念を別の言葉で表現したもの。vault のノートが必ずユーザーの問いと同じ語彙を使っているとは限らない。

例：
- 「営業」⇔ 「セールス」「販売」
- 「提案書」⇔ 「ピッチ」「資料」「デッキ」
- 「ペルソナ」⇔ 「顧客像」「ターゲット」
- 「リスク」⇔ 「危険」「懸念」「落とし穴」
- 「失敗」⇔ 「ミス」「教訓」「アンチパターン」

### 軸3: 固有名詞

クライアント名、人名、プロジェクト名、業界名は強力な検索キー。曖昧検索よりも精度が高い。

例：
- 「サンプル」「Sample」（カタカナ・英字両方試す）
- 「森川」「森川くみこ」（フルネームと姓のみ両方）
- 「2026-04」（特定期間の議事録を一気に拾う）

### 軸4: 抽象度を上下させた語

ユーザーの問いが抽象的なら具体例で検索、具体的なら抽象概念で検索する。

例：
- 抽象「マーケティング」→ 具体「集客」「広告」「LP」「Instagram」「TikTok」
- 具体「サンプル」→ 抽象「女性キャリア」「リスキリング」「ママビジネス」

## 検索結果の評価

`obsidian_simple_search` は関連箇所を含むノートのリストとスコアを返す。

優先順位の判定：
1. **タイトルにキーワードを含むノート** → 最優先
2. **frontmatter の `domain` や `tags` が一致** → 高優先
3. **本文中の出現頻度が高い** → 中優先
4. **断片的な言及のみ** → 低優先（深追いしない）

## type別の検索戦略

### Concepts を探す時

```
search keyword → type:concept でフィルタ可能なら絞る
```

Concepts は永続ノートなので、ヒットしたら必ず読む価値がある。5-10件読むのが目安。

### People を探す時

```
氏名 → 部分一致でも fullname でも試す
会社名 → 略称・正式名両方
```

### Resources を探す時

```
タイトル → 著者名 → 媒体名（PR TIMES, 日経新聞 等）
```

### Projects を探す時

```
クライアント名 → 案件名 → 業界 → 期間（YYYY-MM）
```

## 複合検索が必要な場合

`obsidian_complex_search` で frontmatter フィルタを使うと精度が上がる：

```
type: concept AND domain: 営業・提案
```

ただし複合検索は重いので、simple_search で見つからない時の最後の手段に。

## 検索が全く当たらない時

以下の順で試す：

1. キーワードを短くする（「営業・提案の方法論」→「営業・提案」→「提案」）
2. ひらがな・カタカナ・漢字の表記揺れを試す
3. 英語表記を試す（「ペルソナ」→「persona」）
4. `obsidian_list_files_in_dir` で `20_Concepts/` を全リストアップして目で探す
5. それでもなければ「vault には該当ノートが見当たりません」と素直に報告

## 過剰検索の罠

逆に、検索しすぎても意味がない。以下は避ける：

- 同じキーワードで何度も検索（結果は同じ）
- 関係ない領域まで網を広げすぎる（ノイズが増える）
- 5回以上検索しても薄い場合は、vault に情報がないと判断する

検索は**3-5回程度**で結論を出す。完璧主義より速度。
