# cinematic-hp — スクロールで一続きの映像が進むホームページ

ページ全体が **1台のカメラの旅** になっているホームページを作る。
仕組みは「AIで作った動画をコマ（静止画）に分け、画面に貼りついたキャンバスにスクロール位置に合わせて1コマずつ描く」。ブラウザで3Dを動かすのではない。

- 動画の連鎖生成の正本は `../vp-seamless-journey/`（最終フレーム連鎖・frame-diff 検証）。生成前のプロンプトは `vp-core` の承認ゲートに通す。
- 実測値・失敗の記録（日付と条件つき）は `references/observations.md`。ページの組み方の詳細は `references/page-engine.md`。

## 制約（守らないと壊れる）

- **全部つながっていること。** 場面ごとの動画をフェードで切り替えて並べない。前の動画の最終コマを次の動画の最初のコマにする。並べた時点で「つながって見えない」と言われる。
- **同じ空間の中を進むクリップでは、終わりの絵を指定しない。** 始めの絵＋「切らずに、ディゾルブせず、一続きのカメラの動きで◯◯まで前へ進む」で作る。終わりの絵を指定すると、モデルがカメラを動かすかわりに2枚を重ねてごまかし、二重写りになることがある。
- **実行時にコマ同士を重ねて表示しない。** なめらかにしようとクロスフェードすると残像になる。なめらかさはコマの密度とつなぎ目の作り込みで出す。
- **速さの緩急はゆるく。** スクロール量に対する映像の進み方の差は、最大でも2倍程度。急に速い区間を作ると、前後のコマがカクッと切り替わって見える。
- **全コマを読み終わるまで何も出さない作りにしない。** 最初の表示に要る分だけ先に読む。
- **コマを作り直したら、置き場の版を上げる**（`frames/j1` → `j2`…）。同じ名前に上書きすると、長期キャッシュで古いコマが混ざる。
- `html`/`body` に `overflow-x: hidden` を付けない（sticky が効かなくなり、スクロールしても止まった画面になる）。必要なら `clip`。
- リポジトリ・公開先は会社の GitHub の組織・会社の Vercel チームに作る（個人に作らない）。決まりは `create-app` の「作成先の決定ルール」。

## 判断の型

- **つなぎ方を先に決める。** 場面 A→B ごとに「同じ空間を進む（終わりの絵なし）」か「別の場所へ移る（終わりの絵あり＋画面を覆う理由：湯気・暗がり・扉・物の前を通る）」かを決める。覆う理由の無い場所移動は作らない。
  → 自問：「この2枚の間を、1台のカメラが実際に動いて行けるか？」行けないなら、間に場面を足すか、覆う理由を作る。
- **1本ずつ目で確かめてから次へ。** 次のクリップは前のクリップの最終コマから作るので、途中を作り直すとそれ以降を全部作り直すことになる（カスケード）。だから作るたびにコマを並べた一覧で、二重写り・形の急変・顔や手の崩れを見る。
- **費用は先に見せる。** 1クリップいくら × 本数、作り直しは1本ずつ追加、を見せて OK をもらってから作る（目安は `references/observations.md`）。720p を標準にする（画面いっぱいに表示しても、コマを WebP にした時点で差がほぼ消える）。

## 手順

1. **絵コンテ（無料）**：お店の情報（業態・売り・メニューと価格・場所・予約方法・雰囲気）から、カメラが通る順を決め、場面と場面の間に「つなぎ方」を書く。例：料理の寄り → こだわり → カウンター → 厨房 → 調理の手元 → 湯気 → メニュー → 外観 → 予約の欄。
2. **場面の絵**：各場面の最初の1枚を `generate_image`（16:9・2K）。光・色・時代感をそろえるため、毎回同じ言葉で雰囲気を書く。実在のお店の写真があれば元にし、無いものを使うときはページに「見本」と分かる表記を入れる。
3. **動画の連鎖生成**：`image_to_video`（Seedance 2.5 の画像→動画・720p・5秒）。つなぎ方の判断に従い、終わりの絵を付けるかを決める。次の始めの絵は前の最終コマ（`ffmpeg -sseof -0.05 -i A.mp4 -update 1 -frames:v 1 last.png`）。作るたびにコマ一覧で確かめる。
4. **コマに分ける**：大きさを1つにそろえ、つなぎ目を数コマかけて滑らかに混ぜ、動きの大きいところだけ密に残して間引く。パソコン用（横長）とスマホ用（中央を縦に切り出し）を WebP で書き出す。各画像が元の何コマ目かの配列（`SRC`）を残す。詳細は `references/page-engine.md`。
5. **ページを組む**：1枚の HTML。縦に長い区間の中に sticky のキャンバス、見出しは場面ごとに出る範囲を持たせ、最後に予約の欄。スクロール→コマの対応はなめらかな単調曲線、慣性あり（動きを減らす設定の人には無し）。詳細は `references/page-engine.md`。
6. **運営の仕組みにつなぐ**（あれば）：予約・問い合わせの送り先、アクセスを数える小さなスクリプト、お店の台帳への登録。運営の仕組みが無い会社では、送り先をメールやフォームにする。
7. **公開**：`/frames` に長期キャッシュ（immutable）。push はコマが多いので分ける（スマホ用 → パソコン用 → HTML）。途中で切れたら、入ったかを確かめてから次へ進む。公開 URL を curl で叩き、ページが新しい版のフォルダを参照しているか、先頭・中ほど・最後のコマが 200 かを見る。
8. **確かめる（作った瞬間に）**：ブラウザで公開ページを開き、少しずつスクロールして全場面を見る。見るのは、切れ目でカクッとしないか・二重写りが無いか・見出しが絵と重なって読めなくならないか・最後の予約欄まで行けるか。スマホの幅でも見る。予約欄から試しに1件送り、届くかを見る。
