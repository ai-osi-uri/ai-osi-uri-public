# 動画1本をスクロールでシークする作り（文字を止めて入れ替える）

3D ツールの連番が無いとき、**AI で作った実写の映像を 1 本のワンカットにつなぎ、スクロールで再生位置を動かす**型。
人が歩く・働く・暮らす場面で事業を見せたい会社のホームページ、提案用の「動くデモ」に使う。

## 守ること（相手から何度も直された点。最初から守る）

| 決まり | 中身 |
|---|---|
| 抽象より実写 | 粒子や図形ではなく、人が歩く・仕事をする・暮らす場面で見せる。 |
| 映像は 1 本だけ | 区画ごとに別の映像・別の写真を置かない。背景に `position:fixed` の映像を 1 本だけ置き、ページ全体がその上を進む。 |
| 継ぎ目を出さない | 場面と場面の境目（2 つの場面が上下に並んで見える・線が入る）を出さない。 |
| フェードを使わない | 場面のつなぎ（クロスフェード・ディゾルブ）も、文字・段落・オープニングの出入りもフェードにしない。動きは「カメラが移動してつながる」「文字が下からせり上がる／上へ抜ける（マスク）」「幕が開く（clip-path）」で作る。 |
| スクロールで進む | 映像は自動再生しない。スクロールした分だけ進み、戻せば巻き戻る。止まれば止まる。 |
| 文字は流さない | 文字はページと一緒にスクロールさせず、画面のよい位置に止める。場面が変わったら、その場で入れ替える。 |
| スクロール枠を作らない | ページの中に別のスクロール枠を作らない。止める文字は、表やニュースも含め必ず 1 画面に収める（スマホも）。 |

## 工程

### 1. 場面（キーフレーム）を決めて静止画を作る
- 事業ごとに「その仕事をしている人が映る場面」を 1 枚ずつ決め、最後に「街に戻る」場面で輪にする
  （例：朝の街 → オフィスで画面を見る人 → 電話する人 → 住宅街 → 部屋の中の人 → 夜景の人たち → 朝の街）。
- 場所と場所の間を空撮でつなぐ場合は、間に置く「つなぎの静止画」（例：夕方の住宅街）も作る。
- 生成：`generate_image`（16:9、2K）。プロンプトに「cinematic film still / 35mm film grain / 色味（例：navy and cyan grade）/ no text, no logos」を入れて、色調をそろえる。
- 1 枚ずつ目で確かめて直す（`edit_image`）。直す対象：
  - 実在のブランドのロゴ（ヘッドセット・PC など）
  - 読める看板・ビル名
  - 時代感のずれ（全員マスク姿など）
- 人物は AI 生成であることを、相手に渡すときに必ず伝える。

### 2. 静止画をつなぐ映像を作る（始めと終わりのコマを指定する）
- `image_to_video` に **`image_url`＝今の場面、`end_image_url`＝次の場面** を渡す。
  使えるモデル：`kling3-i2v` / `seedance25-i2v` など（終端フレーム可）。5 秒ずつ。
- 最後の 1 本は「最後の場面 → 最初の場面」にして、ループさせても継ぎ目が出ないようにする。
- プロンプトは「カメラの物理的な動き」を書く。
  - 例：`Single unbroken physical camera move, absolutely no dissolve or cross-fade, no double exposure: the drone flies up toward the lit window, passes through it into the room ...`
  - 窓・ドア・ガラスを「くぐる」動きにすると、場所が変わっても自然につながる。
- 全部を同時に投げ、終わったら `check_status` で回収する。1 本 2〜6 分かかる。
- **必ずコマを並べて確かめる**：`ffmpeg -vf "select='not(mod(n\,15))',scale=320:-2,tile=4x3"`。
  途中で 2 つの絵が重なって透けるコマ（＝ディゾルブ）があれば使わない。プロンプトを強めるか、別のモデルで作り直す。
  `kling3-i2v` は遠い場面どうしだとディゾルブに逃げやすい。そのときは `seedance25-i2v` で作り直すと、カメラが移動してくれることが多い。

### 3. 1 本につなぎ、継ぎ目を合わせる
- `scripts/build_film.sh a.mp4 b.mp4 ...`：解像度とフレーム数をそろえ、各映像の最後の 1 コマ（次の映像の最初と同じ絵）を落としてつなぐ。
- `scripts/align_film.py film_raw.mp4 film.mp4`：継ぎ目ごとに「前の映像の最後のコマ → 次の最初のコマ」のずれ（寄り・位置・色）を測る。
  そのうえで、前の映像の最後の約 1 秒でカメラの寄りと色を少しずつ合わせる。クロスフェードではない。
  - 結果の目安：継ぎ目の差が、普段の 1 コマの差と同じ程度（実測で 20〜40 → 1〜7）。
- 継ぎ目の前後 2 コマずつを並べて目で確認する。残っている差が、歩く人の手足などの自然な動きだけならよい。

### 4. スクロールで動かせる形に書き出す
- `-g 4 -keyint_min 4 -bf 0`（キーフレームを 4 コマごと、B フレーム無し）。こうしないと、スクロールで飛ばしたときにカクつく。
  - 例：`ffmpeg -i film.mp4 -an -vf scale=1280:-2 -c:v libx264 -crf 31 -g 4 -keyint_min 4 -bf 0 -pix_fmt yuv420p -movflags +faststart scrub.mp4`（30 秒で約 8MB）
- 1 ファイルで渡すデモなら base64 で埋め込む（10MB 前後）。公開するなら mp4 を別ファイルにして Vercel 等に置く（読み込みが速い）。

### 5. ページの組み方
**映像（スクロールで再生位置を動かす）**
```js
// 各区画 = 映像の [t0,t1] 秒を受け持つ空のスクロール区間（data-t0 / data-t1、高さ = その場面を見せたい長さ）
const mid = scrollY + innerHeight * 0.5;
let t = 0;
for (const s of secs) if (mid >= s.offsetTop)
  t = +s.dataset.t0 + (+s.dataset.t1 - +s.dataset.t0) * clamp((mid - s.offsetTop) / s.offsetHeight, 0, 1);
target = t;
// rAF ごとに滑らかに追いかける（物理的なカメラの重さが出る）
cur += (target - cur) * 0.14;
if (!movie.seeking && Math.abs(movie.currentTime - cur) > 0.008) movie.currentTime = cur;
```
- `<video muted playsinline preload="auto">` にして、`autoplay` と `loop` は付けない。
- iOS では、最初に 1 回だけ `play()` → `pause()` してから再生位置を動かす（`loadeddata` のとき）。
- 区画の t0/t1 は「その区画の文字の主役が映っている秒」に合わせる。主役の場面は区画を長く（150〜230vh）、移動の場面は短く（120vh）する。

**文字（止める・その場で入れ替える）**
- 区画は空のスクロール区間として残す。文字は `position:fixed` の舞台（stage）に移し、区画ごとに 1 枚のパネルにする。
- そのときの区画（画面の真ん中の線がどの区画にあるか）のパネルだけ表示する。
- 入れ替えの動き：
  - 消える文字：`clip-path:inset(0 0 100% 0)` と `translateY(-34px)` で上へ抜ける（0.5 秒）。
  - 出る文字：0.35 秒待ってから、`clip-path:inset(0)` と `translateY(0)` で下からせり上がる。
  - ブロックごとに 0.06 秒ずつ遅らせる。
  - `opacity` は使わない。
- 区画の装飾クラス（例：`.svc` `.contact`）はパネルに引き継ぐ（引き継がないと見出しのデザインが外れる）。
- 数字のカウントアップは、パネルが出たときに動かす。
- 文字の左側の読みやすさは、映像の上に左から右へ濃くなるグラデーションを敷いて確保する。スクロール量に応じた暗さ（dim）は連続値で掛ける（切り替えのフェードにしない）。

**その他**
- オープニングは、黒幕を上下に開く（`translateY(±100%)`）。
- 上端に読み進み具合の線、右に今いる章の目次（PC のみ）を置く。目次と文字が重ならないよう、PC では文字の右に 15vw の余白をとる。
- 横はみ出し対策は `overflow-x: clip`（`hidden` は sticky や fixed の動きを壊す）。

### 6. 確かめる（数字で）
Playwright（`/usr/bin/google-chrome`）で、PC（1440×900）とスマホ（390×844）の両方を確かめる。
- 何もしない間は `currentTime` が動かない。
- 各区画の中でスクロールすると、文字の位置は 1px も動かず（`getBoundingClientRect().top` が同じ）、`currentTime` だけが進む。
- 上に戻すと `currentTime` が戻る。
- 表示中のパネルの上端と下端が、画面の中に収まる。
- 中身がはみ出しているスクロール枠（`overflow:auto/scroll` かつ `scrollHeight > clientHeight`）が 0 件。
- `scrollWidth > innerWidth` が false（横はみ出しなし）。
- ページのエラーが 0 件。
- 各区画のスクリーンショットを撮って、文字と場面が合っているかを目で見る。

## 実在の会社のページを作るとき
- 社名・代表者名・数字・ニュースは、相手の公式サイトに載っている事実だけを使う。代表の言葉を作って「本人の言葉」として載せない。載せる場合は「趣旨から起こした文」と伝えて、確認をもらう。
- 画面の隅に「デザイン提案用デモ（制作：{{company.name}}）」と小さく出す。
- 公開 URL にはせず、まずファイルで渡す（実在の会社のブランドで作ったページなので、公開するかは本人が決める）。
