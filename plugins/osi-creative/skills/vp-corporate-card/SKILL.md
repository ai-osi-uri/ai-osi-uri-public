# vp-corporate-card — 企業の動画名刺（15秒／30秒）

このメソッドの仕事は **「6ビートの文言」「ビート別の画像起点プロンプト」「ナレ原稿」を書く**こと。
生成ループ（承認ゲート→生成→検証→連結）は `vp-core` に委譲し、本メソッドは**中身**を作る。

> **正本（必ず参照）**
> - 骨格・尺・原価・納品物：`../ai-video-production/references/30s-beat-structure.md`
> - ブランドキット：`../ai-video-production/references/brandkit.md`
> - 画風テンプレ：`../ai-video-production/templates/prompts-{anime-ghibli|corporate|documentary|lifestyle}.md`
> - ナレ：`../narration/SKILL.md` に委譲　／　BGM：`../music/SKILL.md` に委譲
> - モデル単価：`../ai-video-production/references/model-comparison.md`　／　落とし穴：`../ai-video-production/references/pitfalls.md`
> - テロップ実装：`../live-ugc-reel-edit/scripts/build_reel_template.py` を**流用**（作り直さない）

## 0. 判断（このメソッドを使うか）

- 尺が **15秒か30秒**、目的が「渡す・見せる・掴む」→ **本メソッド**。
- 2〜3分で「理解させる」（IR・採用・会社説明）→ `vp-corporate-narrated`。
- 個人の自己紹介 → `vp-personal-intro`。
- **中間の尺（45秒・60秒）は作らない。** 求められたら「30秒か、2〜3分か」に寄せる。

## 1. ブリーフを起票する（Phase 0・3分）

3経路のどれでも、最後は同じ `brief.yaml`（`templates/brief-corporate.yaml`）に落とす。

| 経路 | 入力 | 使う場面 |
|---|---|---|
| **A. 音声1本**（既定） | 社長・担当が60〜90秒喋った音声／Plaud文字起こし | 材料を集める時間がないとき。「1分喋ってください」で済む |
| **B. 既存素材** | 会社HP・LP・PR TIMES・会社案内pptx・名刺 | すでに材料があるとき（企業版はこれが多い） |
| **C. 対話** | `AskUserQuestion` 5問（下記） | 材料が何もないとき |

C の5問：①誰に見せる動画か　②相手が困っていることを一言で　③会社を一行で言うと　④誇れる数字・実績（無ければ「無し」）　⑤見た人にどうしてほしいか

**ブリーフが埋まらない項目は空のまま進める。**（proof が空ならB3を映像に置換する。§2の原則4）

## 2. 6ビートの文言を書く（Phase 1・ゲート①）

構成表・タイミング・15秒版の削り方は **`30s-beat-structure.md` が正本**。ここでは企業版の書き方だけ。

**先に3点セットを決める**（インサイト＝B1 ／ 情緒ベネフィット＝B5 ／ 信じる根拠＝B3・B4）。
**B1 の掘り方は `../ai-video-production/references/hook-insight.md` が正本**——WHY を2階層掘ってから書く。
`offer`（何ができるか）は現状の層なので、そのまま B1 にしてはいけない。

| ビート | 企業版で書くこと | 字数の目安（ナレ） |
|---|---|---|
| B1 フック | 顧客が言語化できていない **WHY を言い当てる**。自社の話をしない | 15〜20字 |
| B2 名乗り | 社名＋一行定義。「◯◯を、◯◯にする会社」 | 20〜25字 |
| B3 証明 | 数字を1〜3点。導入社数・年数・シェア | 30〜40字 |
| B4 提供 | **1つに絞る**。並べた瞬間に何も残らない | 30〜40字 |
| B5 動機 | なぜやっているか。創業のきっかけ・原体験 | 20〜25字 |
| B6 CTA | 社名＋URL／QR。ナレは無くてもよい | 0〜15字 |

### 書くときの原則

1. **B1で自社の話をしない。** さらに、現状の指摘で止まらない。「AIを入れたのに、誰も使っていない。」は
   まだ現状。その下の WHY まで降りて「道具は来た。決める人が、まだ来ていない。」まで持っていく。
2. **B4は B1 の答えにする。** サービスが3つあっても1つに絞る。**B1 と B4 がつながっていない台本は作り直し。**
   残り2つは別の動画にする（量産できるのだから分ければいい）。
3. **B3の数字を捏造しない。** 無ければB3を「現場・人・製品の映像＋テロップなし」に置換し、尺はB4に寄せる。
4. **B5を削らない。** ここが無いと会社案内になり、フックとして機能しない。
5. 全ビート合計のナレは **30秒版で115〜135字**（日本語ナレは約4.5字/秒）。超えたらB3から削る。

→ **★ゲート①**：6ビートの文言とナレ原稿だけをテキストで見せて承認をもらう。絵はまだ作らない。

## 3. ビート別の画像プロンプトを書く（Phase 2・ゲート②）

**既定はアニメ基調**（抽象化されていて感情移入しやすく、破綻が絵柄に吸収され、`veo31-fast` 統一で安い）。
実写は金融・医療・重厚BtoBなどで**明示指定されたときだけ**。

プロンプトの組み立て：

```
{brandkit/style_anchor.txt の内容}         ← ブランドキットがあれば必ず先頭に
[SUBJECT]   そのビートで映すもの（B1は課題の情景、B2はロゴ/社屋、B3は現場、B4は使われている場面、B5は原点、B6はロゴカード）
[LIGHTING]  warm natural light / golden hour / soft morning
[CAMERA]    slow push in / static / slow dolly（1ビート1動きだけ）
[MOOD]      problem-statement / confident / warm
4K, no text overlays
```

- 生成は `generate_image`（model: `nano-banana-2`、$0.08/枚）。**6枚まとめて作る。**
- 社屋・製品・人物など**同じものが複数ビートに出る**なら、参照画像を `extra.image_urls` に渡す（nano-banana-2 は人物参照 最大4枚・オブジェクト参照 最大10枚）。
- **B1だけは2案作る。** 最初の1秒で離脱が決まるので、ここだけは選ばせる。
- B6は毎回作らず、**ブランドキットの `outro/` を使い回す**（全動画で終わり方を揃える＝シリーズに見える）。

→ **★ゲート②**：6枚（B1は2案なので7枚）を並べて一括で採否をもらう。ここが通れば以降は自動で流す。

## 4. 生成〜納品（Phase 3–7・`vp-core` に渡す）

`vp-core` に以下を渡してループを回す。

```
plan:
  model: veo31-fast        # アニメ基調はこれで統一（$0.10/s）
  clips: 6                 # 15秒版は4
  duration_per_clip: 5s
  aspect: 16:9（→書き出しで 9:16 / 1:1 も出す）
  mode: image_to_video     # 起点は Phase 3 の採用画像
```

- **6本は並列投入する**（順に投げると8分かかるところが2〜3分になる）。
- ナレ：`../narration/SKILL.md` に委譲。声はブランドキットの `voice`（既定 Konoha）。固有名詞の誤読は発音辞書で潰す。
- テロップ：音声オフ前提。**各ビート1行だけ**焼く。B2の名乗りとB6のCTAは必ず焼く。
- BGM：`../music/SKILL.md` に委譲。**毎回生成しない。** ブランドキットの `signature_a`（企業の標準）を使い、B6にスティングを重ねる。
- 書き出し：30秒×3アスペクト＋15秒版。納品物一式は `30s-beat-structure.md` の「納品物」節のとおり。

## 5. 1社目でブランドキットを確定させる

**1社の1本目だけは全ゲートを通す。** その過程で `brandkit/<company>/` を作る（`brandkit.md` 参照）。
2本目以降は人が触るのは Phase 0 と Phase 1 だけになり、実質10分弱／本で回る。

## やらないこと

- 45秒・60秒の中間尺を作る（→ 30秒か2〜3分に寄せる）
- BGMを1本ごとに生成し直す（→ シリーズに見えなくなる）
- 実績の数字を推測で埋める
- テロップ実装を自作する（→ `live-ugc-reel-edit` のスクリプトを流用）
