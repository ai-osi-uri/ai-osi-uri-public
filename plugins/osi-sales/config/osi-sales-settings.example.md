## 案件マスタ（営業管理表）

案件情報の**正本**。Notion のリード一覧は 2026-07 に、Google スプレッドシート版は
2026-09-10 に廃止し、このファイルへ一本化した。

| 項目 | 値 |
| --- | --- |
| ファイル | `{{ledgers.sales}}`（osi-profile.md の値。例: `営業管理/営業管理表.xlsx`） |
| タブ名 | `取引先管理` |
| ヘッダ行 | **5行目**（4行目はグループ見出しの結合セル。データは6行目以降） |
| アクセス | **ディレクトリ経由（openpyxl）**。Google Sheets API・GCPサービスアカウントは使わない |
| 運用ルール | `{{ledgers.sales_rules}}` |

**なぜディレクトリ経由か**: 渡し先である契約マスタ・請求管理台帳（`{{paths.finance}}/*.xlsx`）が
すべてディレクトリベースで、OSI Finance も同じ設計だから。案件IDで突き合わせる相手と
経路を揃えている。

### 列

`案件ID / 取引先名 / URL / 事業区分 / 紹介元 / 獲得日 / ステータス / 確度 / 営業担当 /
CAIO担当 / サポート / アサイン状態 / 次アクション / 次アクション期日 / 最終接触日 /
想定額(税込) / 課金形態 / 想定開始月 / 想定期間(ヶ月) / 窓口氏名 / 窓口メール /
議事録 / 提案書 / 失注-保留日 / 失注-保留理由 / 再アプローチ月 / 顧客課題メモ`
（＋移行チェック2列・稼働期間2列）

列レターは使わない。列名で指定する（実際の列名は `ledger.py columns` で確認できる）。

**セクション見出しは無い。** 1案件1行・行は動かさない設計で、段階はステータス列が表す。

### ステータス値

`リード` / `商談中` / `提案中` / `金額提示済み` / `受注` / `契約済み` / `デリバリー中` /
`保留` / `失注` / `終了` の10値。選択肢の正本は同じブックの `マスタ` タブ。
KPI集計が壊れるので**値を勝手に増やさない**。

確度は `A`(90% ほぼ確実) / `B`(60% 前向きだが決裁待ち) / `C`(30% 検討初期)。
事業区分は `AIコンシェルジュ事業` / `受託開発` / `新規事業創出支援`。

## 案件フォルダ

| 項目 | 値 |
| --- | --- |
| 案件ルート | `{{paths.projects}}/`（osi-profile.md の値。旧称のフォルダ名を決め打ちしない） |
| 命名規則 | `{案件ID3桁}.{企業名}` （例: `139.キャンピングカー`） |
| サブフォルダ | `01_提案・見積` / `02_契約` / `03_制作・成果物` / `04_請求` / `05_受領資料` |

> 一部の案件フォルダは `01_契約書`〜`07_議事録` という別テンプレートで作られている。
> 既存フォルダがある場合は**その構造に合わせる**こと。

### 採番

**採番の正本は Drive のフォルダ名**（営業管理表の `案件ID` 列ではない）。
`ledger.py next-id` が案件ルートを走査して次番号を返す。

1. 欠番があってもよい。番号の再利用はしない
2. 採番したらフォルダを作り、**同時に営業管理表へ行を追加して `案件ID` 列に同じ値を入れる**
3. 台帳に載せない社内検討・調査・失注済みの資料には番号を振らない

> Drive のフォルダが bash から丸ごと見えないことがある（クラウド同期のキャッシュ外れ）。
> `next-id` が0件で止まったら **「無い」と報告せず**、Drive コネクタで一覧を取るか
> Finder で開いてもらう。

## 関連するマスタとの関係

案件は「リード → 商談 → 提案 → 契約 → 請求 → 納品」と進む。
マスタはこのライフサイクルを**分担**しており、統合しない。

| マスタ | 担当区間 | 正本にする情報 |
| --- | --- | --- |
| **営業管理表**（`{{ledgers.sales}}`） | リード〜契約締結 | ステータス・営業担当・獲得日・次アクションと期日・想定額 |
| **契約マスタ**（`{{paths.finance}}/`） | 契約締結〜請求 | 正式名称・請求先担当・メール・契約金額・契約期間 |
| **請求管理台帳**（`{{paths.finance}}/請求管理台帳.xlsx`） | 請求〜入金 | 請求額・請求月・入金・確定売上 |
| **案件フォルダ（`{{paths.projects}}`）** | 全期間 | 案件IDと成果物の実体 |

**引き継ぎ点は「契約締結」の1箇所だけ。** 営業管理表のステータスが `契約済み` に
なったら契約マスタへ起票する。請求先メールは**契約締結後は契約マスタが正本**
（営業管理表の窓口列は商談中のメモとして扱う）。

結合キーは**3桁の案件ID**。

### 既知の注意点

- 旧NotionのIDと現在のフォルダ番号は途中から乖離している。
  例: 旧ツールの ID とフォルダ番号が食い違う案件がある（`{{旧ID}}` / フォルダ `{{番号}}.{{企業名}}`）
- 1社で複数案件が走る場合、フォルダは分かれるが営業管理表は1行のことがある
  （例: サンプル株式会社 `053`/`064`）
- 案件IDが重複している行がある（`009` `030` `092`）。`update --case-id` は一意に引けないと
  止まるので `--row` で行番号を指定する
- 案件IDが未採番の行が21件ある

## 触り方

コネクタは使わない。`skills/new-lead-registration/scripts/ledger.py` が唯一の入口。
作法と不変条件は `skills/new-lead-registration/references/ledger-access.md` が正本。

```bash
L=plugins/osi-sales/skills/new-lead-registration/scripts/ledger.py
python3 $L columns
python3 $L find --company "セーフティ&ベル"
python3 $L read --status 商談中 --owner {{members.owner}}
python3 $L next-id
python3 $L append --data '{"案件ID":"141","取引先名":"...","ステータス":"リード"}'
python3 $L update --case-id 139 --data '{"ステータス":"提案中"}' --append-memo "9/15 初回商談"
```

場所は **osi-profile.md**（連結フォルダ直下・`config/osi-profile.example.md` が雛形）の `paths` / `ledgers` から読む。
一時的に差し替えたいときは環境変数で上書きする。

| 環境変数 | 既定値 |
| --- | --- |
| `OSI_PROFILE` | 探索で見つかった `osi-profile.md`（cwd の祖先 → `~/mnt/*/` → Google Drive 同期フォルダ） |
| `OSI_DRIVE_ROOT` | `osi-profile.md` があるフォルダ（`paths.root`） |
| `OSI_SALES_LEDGER` | `$OSI_DRIVE_ROOT/{{ledgers.sales}}` |
| `OSI_CASE_ROOT` | `$OSI_DRIVE_ROOT/{{paths.projects}}` |
| `OSI_SALES_TAB` / `OSI_SALES_HEADER_ROW` | `{{ledgers.sales_tab}}` / `{{ledgers.sales_header_row}}` |
