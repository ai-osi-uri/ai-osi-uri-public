# 提案の素材 × 相手の今の取り組みでつくる共同事業提案

> **組織固有値はプロファイルから読む。** 本文の `{{company.*}}` などは、連結フォルダ直下の `osi-profile.md` の値に置き換えて解釈する。値をここに直書きしない。

## いつ使うか
- 手元に「提案の素材」（人物・ブランド・教材・サービス・技術など）があり、それを相手企業の事業と組み合わせて共同事業を提案したいとき。
- 相手から頼まれた話ではなく、こちらから持ち込む提案のとき。
- 「○○社に何か提案できない？」と聞かれ、切り口から考えるとき。

## 0. 提案の素材を揃える（置き場は会社によって違う）
素材は次の項目で揃える。置き場が違っても項目は同じにする。

| 項目 | 中身 |
|---|---|
| 種類 | 人／ブランド／サービス／コンテンツ／その他 |
| 一言の説明 | 何者か・何か |
| 価値の分解 | 何が価値か（例：実体験を語れる／知名度がある／教育・商品として届けられる） |
| 一言のテーマ | その素材をまとめる言葉。提案全体をつなぐ言葉になる |
| 届く相手 | 誰に響くか |
| 使うときの制約 | 本人の稼働の上限、名前を出せる範囲、関係者の名前の扱い など |
| 本人の了承 | 了承済み／未確認 |
| 実績・裏づけ | 公表されている実績 |
| 窓口 | 誰を通すか |

- **社内の秘書（osi-secretary）がある会社**：秘書に「提案の素材を見せて」と聞くか、秘書の道具 `proposal_assets`（`all=true` で全件の中身）で取る。新しい素材は秘書に「提案の素材に○○を足して」と頼む（`save_proposal_asset`）。
- **秘書が無い会社**：手元の資料・公式サイトで上の項目を埋め、埋まらない項目は本人に聞く。埋めた結果は {{paths.projects}} の案件フォルダなど、会社が決めた置き場に残す。
- **了承が「未確認」の人物は、相手向けの資料に名前を出す前に確認する。** 家族・関係者など本人以外の名前は、本人の了承前は出さない。
- 人物の名前・肩書・経歴は、公式サイト等で一字ずつ確認してから書く。

## 1. 骨子の型（この順で考える）
1. **素材の価値を分解する**
   - 何が価値なのかを要素に分け、全体を一言のテーマにまとめる。
2. **相手の「今」を一次情報で拾う**
   - 相手の公式ニュースリリース・IR・議事録から、直近に始めた事業・ブランド・提携を探す。日付と、相手自身の表現（「提携」か「業務委託」か等）をそのまま使う。
   - 提案は「新しいことを始めましょう」ではなく「いま始めた取り組みを、この素材で加速しませんか」にする。
3. **相手のお客さまが動かない理由を分解する**
   - 気持ちの問題だけで終わらせない。費用・時間・安全・周囲の理解なども並べる。
   - 素材で解ける部分と、相手の商品設計で解く部分を分ける。
4. **役割を分ける**
   - 素材が担うもの（きっかけ・動機・学び）と、相手が担うもの（商品・販売網・手配・運営）を一文ずつで言えるようにする。つなぐ側（自分たち）の役割も書く。
5. **同じ素材を、対象者ごとに向け直して展開する**
   - 対象者別に複数の企画にする。どれも「同じ素材の向け直し」であることが分かるようにする。
   - 優先は「相手がいま成功させたい取り組みに直接効くもの」。準備期間が長いもの（予算サイクルがある相手など）は「担当部署と具体化」に回す。
   - 素材が複数あるときは、組み合わせを2〜3案、なぜ合うかと一緒に仮説として出し、本人に選んでもらってから進める。
6. **企画素案はすべて同じ型で書く**
   - 概要：対象／内容／相手の取り組み（出所付き：公表されている取り組み or 私たちの理解）／期待する価値（想定）／試験で確かめたいこと
   - 流れ：前・中・後（または手順）を上から下のリストで
7. **分担・収益・進め方は素案として出す**
   - 「〜と考えています」「一緒に決めたい」で書く。決まったことのように書かない。
   - 素材の本人が毎回稼働しなくても回る形（講座・教材中心）を基本にし、素材の「使うときの制約」を守る。
   - 進め方は「1つの企画を小さく試す」から。
8. **会議の到達点を決める**
   - 「賛同」ではなく「1つの企画について、担当者と次回の打ち合わせを決める」。
   - 最後の相談事項は、相手が名前・選択肢・時期で答えられる質問にする。

## 2. 書き方のチェック
- 主語をこちらにしない。相手が頼んだ話として書かず、「私たちからのご提案」として書く。
- 相手がすでに知っている背景は「現状の理解」と呼ぶ。
- 相手の事業についての記述は、公表情報か推測かを書き分ける。
- 社内向けのメモ（効果は断定できない、知名度がどこまで効くか不明、等）は相手向けの資料に入れず、「試験で確かめたいこと」として前向きに書く。
- 素材の人物の紹介を冒頭に短く入れる（読み手が「誰？」とならないように）。
- 表紙は「何の提案書か」を名乗る。章タイトルはラベルでよい。本文スライドのタイトルは言い切る。

## 3. 構成の目安
1. 本日のご提案（素材の紹介＋ひとこと＋本日ご相談したいこと）
2. 素材の価値とテーマ（価値の分解／相手のお客さまが動かない理由）
3. 共同事業の全体像（三者の役割／対象者別の企画一覧／共通の組み立て）
4. 企画素案（各企画：概要＋流れ）
5. 分担・収益・進め方（素案）
6. 本日ご相談したいこと

## 4. 他スキルとの関係
- 骨子が固まったら `deck-composition`（osi-docs）で構成、描画後は `proposal-self-review` を通してから見せる。
- 作った提案で新しく分かった素材の価値・制約は、秘書の「提案の素材」（または会社の置き場）に直して返す。次の提案で使えるようにするため。
