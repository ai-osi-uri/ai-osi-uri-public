# 営業管理表へのアクセス（osi-sales 共通・正本）

営業管理表を触るスキルは、**すべてこのファイルの作法に従う**。
`new-lead-registration` / `meeting-minutes` / `shodan-prep` / `proposal-package` /
`pr-times-article` / `session-review` から参照される。

---

## 0. 前提

| | |
| --- | --- |
| 台帳 | `{{ledgers.sales}}`（Google Drive デスクトップ同期のローカルファイル） |
| タブ | `取引先管理` |
| ヘッダ | **5行目**（4行目はグループ見出しの結合セル）。データは6行目以降 |
| アクセス | **ディレクトリ経由（openpyxl）**。Google Sheets API・GCPサービスアカウントは使わない |
| 運用ルール | `{{ledgers.sales_rules}}`（列の持ち主・ステータス遷移の必須列） |

**なぜディレクトリ経由か**: 渡し先である契約マスタ・請求管理台帳（`{{paths.finance}}/*.xlsx`）が
すべてディレクトリベースで、OSI Finance も同じ設計だから。案件IDで突き合わせる相手と
経路を揃えている。GCPサービスアカウントは使わない方針（2026-09-10 確定）。

---

## 1. 不変条件（破ると台帳が壊れる）

1. **行は消さない・動かさない。** 1案件1行。リードから失注・終了まで同じ行に残す。
2. **ヘッダは5行目。** 凡例ブロック（`凡例：` で始まる行）より下に案件行を置かない。
3. **ステータスは10値のみ** — `リード` `商談中` `提案中` `金額提示済み` `受注` `契約済み` `デリバリー中` `保留` `失注` `終了`。値を増やすとKPI集計が壊れる。
4. **顧客課題メモは追記であって上書きではない。** 日付を付けて足す。
5. **案件IDの正本は Drive のフォルダ名**であって台帳の列ではない。フォルダと台帳で必ず一致させる。

---

## 2. 触り方

openpyxl を直接書かない。`scripts/ledger.py` を経由する
（他スキルからは `../new-lead-registration/scripts/ledger.py`）。
上の不変条件をスクリプト側が守るので、各スキルが個別に実装すると必ずズレる。

```bash
L=../new-lead-registration/scripts/ledger.py     # 自スキル内なら scripts/ledger.py

python3 $L columns                                # 列名・ステータス値・パスを確認
python3 $L find --company "セーフティ&ベル"        # 表記ゆれを吸収して行を引く
python3 $L find --case-id 139
python3 $L read --status 商談中 --owner {{members.owner}}         # 一覧
python3 $L next-id                                # Driveフォルダから次の案件IDを採番
python3 $L append --data '{"案件ID":"141","取引先名":"...","ステータス":"リード", ...}'
python3 $L update --case-id 139 --data '{"ステータス":"提案中"}' --append-memo "9/15 初回商談"
```

- `append` は同名の行があると止まる（1社複数案件なら `--allow-duplicate`）。
- `append` / `update` は書く前に `{{paths.sales_admin}}/_backup/` へ自動でバックアップを取る。
- Excel のロック残骸 `~$<台帳ファイル名>.xlsx` があると止まる。**bash では消せないので
  Finder で削除してもらう。**
- 環境変数 `OSI_DRIVE_ROOT` / `OSI_SALES_LEDGER` / `OSI_CASE_ROOT` で場所を差し替えられる。

## 3. 列

`案件ID / 取引先名 / URL / 事業区分 / 紹介元 / 獲得日 / ステータス / 確度 / 営業担当 /
CAIO担当 / サポート / アサイン状態 / 次アクション / 次アクション期日 / 最終接触日 /
想定額(税込) / 課金形態 / 想定開始月 / 想定期間(ヶ月) / 窓口氏名 / 窓口メール /
議事録 / 提案書 / 失注-保留日 / 失注-保留理由 / 再アプローチ月 / 顧客課題メモ`
（＋移行チェック2列・稼働期間2列）

選択肢の正本は同じブックの `マスタ` タブ。確度は `A`(90%) / `B`(60%) / `C`(30%)。
事業区分は `AIコンシェルジュ事業` / `受託開発` / `新規事業創出支援`。

**列には持ち主がいる。他人の列は触らない。**

| 人 | 持つ列 |
| --- | --- |
| リードを取った人 | 案件ID・取引先名・紹介元・獲得日・営業担当 |
| 営業担当 | ステータス・確度・次アクション・期日・想定額まわり・窓口・失注/保留の3列 |
| 秘書 | ステータス（受注→契約済み）・アサイン状態 |
| 西 | CAIO担当・アサイン状態・事業区分 |

金額の正本はここではない。受注した瞬間、契約マスタと請求管理台帳へ移る。

## 4. 案件フォルダ

| | |
| --- | --- |
| 案件ルート | `{{paths.projects}}/`（プロファイルの値。旧称のフォルダ名を決め打ちしない） |
| 命名 | `{案件ID3桁}.{企業名}` 例 `139.キャンピングカー` |
| サブフォルダ | `01_提案・見積` / `02_契約` / `03_制作・成果物` / `04_請求` / `05_受領資料` |

一部の古い案件は `01_契約書`〜`07_議事録` の別テンプレートで作られている。
既存フォルダがあるときは**その構造に合わせる**。

**フォルダ作成と台帳への行追加はセットで行う。** 片方だけ作ると、以降のスキルが案件を引けない。

> Drive のフォルダが bash から丸ごと見えないことがある（クラウド同期のキャッシュ外れ）。
> **「無い」と報告しない。** `next-id` が0件で止まったら、Drive コネクタで一覧を取るか
> Finder で開いてもらう。

## 5. まだ直っていないこと（触る前に知っておく）

- **Google Sheet 版が別に存在する**（`{{paths.sales_admin}}/!old/（旧 Google スプレッドシート版）`）。
  2026-09-10 に xlsx を正本と決め、gsheet の案件は取り込み済み。**gsheet には書かない。**
- 案件ID が重複している行がある（`009` `030` `092`）。`update --case-id` は一意に
  引けないと止まるので、その場合は `--row` で行番号を指定する。
- 案件ID が未採番の行が21件ある（例: `サンプル株式会社` ほか）。
- 表記ゆれの疑いが残る行がある（似た社名で ID が違うもの）。
