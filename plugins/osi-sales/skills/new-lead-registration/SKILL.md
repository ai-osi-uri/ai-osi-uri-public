# 新規リード登録スキル（atomic）

> **組織固有値はプロファイルから読む。** 本文の `{{paths.*}}` `{{ledgers.*}}` `{{company.*}}` `{{members.*}}` は、連結フォルダ直下の `osi-profile.md`（雛形: `config/osi-profile.example.md`）の値に置き換えて解釈する。無ければ会社名・案件フォルダ・台帳の有無・使うコネクタを質問して先に作る。値をここに直書きしない。

自社の営業管理ワークフローにおいて、新しい見込み案件（リード）が発生した際に、営業管理表への行追加とプロジェクトフォルダの作成を一括で行う **atomic スキル**。提案書生成や Drive 格納などの後続処理は行わず、台帳への起票＋フォルダ作成までで完結します。

## なぜこのスキルが必要か

新規リードが入るたびに、営業管理表への行追加、案件IDの採番、フォルダ構造のテンプレ複製といった定型作業が発生します。手作業だと記入漏れやフォルダ名のズレ、採番の重複が起きやすいので、この一連の流れを自動化しています。

## 前提：案件マスタは営業管理表

案件情報の正本は **`{{ledgers.sales}}`**（タブ `取引先管理`、ヘッダは5行目）。
**ディレクトリ経由（openpyxl）で読み書きする。Google Sheets API・GCPサービスアカウントは使わない。**
台帳の触り方・不変条件・列の一覧は
**`references/ledger-access.md` を必ず読むこと**（osi-sales 共通の正本）。

```bash
L=scripts/ledger.py
python3 $L columns                       # 列名・ステータス値・パス
python3 $L find --company "{企業名}"      # 表記ゆれを吸収して行を引く
python3 $L find --case-id {案件ID3桁}
```
場所などの組織固有値は `config/osi-sales-settings.md` を参照してください。

列は**ヘッダ行の文字列**で指定します（列レターは使わない）。実際の列名は
`ledger.py columns` で確認できるので、書き込み前に一度見ておくこと
（存在しない列を指定するとエラーで止まります）。

`案件ID / 取引先名 / URL / 事業区分 / 紹介元 / 獲得日 / ステータス / 確度 / 営業担当 /
CAIO担当 / サポート / アサイン状態 / 次アクション / 次アクション期日 / 最終接触日 /
想定額(税込) / 課金形態 / 想定開始月 / 想定期間(ヶ月) / 窓口氏名 / 窓口メール /
議事録 / 提案書 / 失注-保留日 / 失注-保留理由 / 再アプローチ月 / 顧客課題メモ`

**セクション見出しはありません。** 1案件1行・行は動かさない設計で、段階はステータス列が表します。
ステータス値は `リード` / `商談中` / `提案中` / `金額提示済み` / `受注` / `契約済み` /
`デリバリー中` / `保留` / `失注` / `終了` の10値だけ。選択肢の正本は同じブックの `マスタ` タブで、
**値を勝手に増やさない**こと（KPI集計が壊れます）。

## ワークフロー

### ステップ1: 情報を収集する

ユーザーの発言（チャットログ、メール転送、口頭指示など）から以下の情報を抽出してください。不足があれば確認してください。

| 項目 | 必須 | 説明 |
|------|------|------|
| 企業名 | はい | 会社名。`取引先名` 列になる |
| 営業担当 | はい | 社内で誰がこの案件を持つか。`営業担当` 列になる |
| 紹介元 | はい | 誰から来たか（`紹介者名` / `パートナー企業名` / `コミュニティ名` 等）。`紹介元` 列になる |
| 代表者・担当者名 | いいえ | 先方のキーパーソン。`窓口氏名` 列になる |
| 企業HP | いいえ | `URL` 列になる |
| 顧客課題・アクション | いいえ | `顧客課題メモ` 列になる。紹介元・面談場所・入館番号などの背景情報もここにまとめる |
| 想定額 | いいえ | `想定額(税込)` 列。**月額なら月額を税込で**入れる |
| 初回面談日時 | いいえ | 決まっていれば `商談中`＋`次アクション期日` に使う。未定なら `リード` |
| その他メモ | いいえ | 背景情報など |

### ステップ2: 既に台帳に載っていないか確認する

同じ会社が二重起票されないよう、先に `python3 scripts/ledger.py find --company "{企業名}"` で確認してください。
表記ゆれ（株式会社の有無・促音・記号など）はスクリプト側で吸収されます。
`append` も同名行があると自動で止まります。

- ヒット0件 → 新規として続行
- ヒットあり → 既存案件の可能性。`AskUserQuestion` で「既存行を使う／別案件として新規登録する」を確認する
  （1社で複数案件が走ることはあるため、機械的に中断しない）

全体像を見たいときは `python3 scripts/ledger.py read` を使うと、各行に `__row`（行番号）が付いた形で取得できます。
`--status` / `--owner` で絞り込めます。

### ステップ3: 案件IDを採番する

**採番の正本は Drive のフォルダ名であって、営業管理表の `案件ID` 列ではありません。**
`python3 scripts/ledger.py next-id` が `{{paths.projects}}/` を走査して次番号を返します。

1. `{{paths.projects}}/` の直下フォルダを**名前の降順**で並べる
2. 先頭のフォルダ名の3桁番号 +1 を新しい案件IDとする（`ledger.py next-id` が返す `next`）
3. 欠番があってもよい。番号の再利用はしない
4. 台帳に載せない社内検討・調査用の資料には番号を振らない

採番した案件IDは、**このあとのフォルダ作成（ステップ5）と営業管理表への行追加（ステップ4）で必ず同じ値を使う**こと。

### ステップ4: 営業管理表に行を追加する

`ledger.py append` を使い、案件行の末尾に1行挿入して書き込みます。
**セクション見出しはありません**（1案件1行・行は動かさない設計）。ステータス列がそのまま段階を表します。

初回商談の日程がまだ決まっていなければ `リード`、既に決まっていれば `商談中` を入れる。

```bash
L=scripts/ledger.py
python3 $L append --data '{
  "案件ID": "{案件ID3桁}",
  "取引先名": "{企業名}",
  "URL": "{企業HP}",
  "紹介元": "{紹介元}",
  "獲得日": "{YYYY-MM-DD}",
  "ステータス": "リード",
  "営業担当": "{営業担当}",
  "窓口氏名": "{代表者・担当者名}",
  "次アクション": "{次に自分が何をするか}",
  "次アクション期日": "{YYYY-MM-DD}",
  "顧客課題メモ": "{聞いた話をそのまま}"
}'
```

- **次アクションと期日を必ず入れる。** 期日のない次アクションは朝の通知に乗らず、存在しないのと同じになる。
- ステータスは10値以外を入れない（`ledger.py columns` で確認できる）。範囲外なら append が止まる。
- 同名の行が既にあると append は止まる。1社で複数案件が走るなら `--allow-duplicate`。
- **まだ書かないもの**: 確度・想定額・窓口メール・事業区分。分からないものを埋めようとしない。
- 書き込み前に自動でバックアップが `{{paths.sales_admin}}/_backup/` に取られる。

### ステップ5: プロジェクトフォルダを作成する

Drive の `{{paths.projects}}/` に、テンプレートと同じサブフォルダ構造でディレクトリを作成してください。

フォルダ名の形式: `{案件ID3桁ゼロ埋め}.{企業名}`

例: 案件IDが 122 なら `122.サンプル`

テンプレートのサブフォルダ構造（`{{paths.project_template}}/` を参照）:
```
01_提案・見積
02_契約
03_制作・成果物
04_請求
05_受領資料
```

> 一部の既存案件は `01_契約書`〜`07_議事録` という別テンプレートで作られている。
> 既存フォルダがある場合は**その構造に合わせる**こと。

**フォルダ作成と営業管理表への行追加はセットで行う。** 案件IDが Drive と `案件ID` 列で食い違うと、
以降のスキル（proposal-package / meeting-minutes 等）が案件を引けなくなります。

### ステップ6: Slack 通知（任意・slack-notify が利用可能な場合）

`slack-notify` スキルが利用可能であれば、サブスキルとして呼び出して
リード起票完了を `#sales` チャンネルに通知する。

```
slack-notify(
  event_type="lead_created",
  payload={
    "company": "{企業名}",
    "id": "{案件ID3桁}",
    "drive_folder_url": "{案件フォルダURL}",
    "channel": "{主担当}",
    "introducer": "{紹介元（あれば）}",
    "first_meeting": "{初回面談日時（あれば）}"
  }
)
```

slack-notify が未整備、または Slack MCP に投稿系ツールが無い場合は
スキップして次へ。フォーマット・宛先・フォールバックは slack-notify
側で一元管理されるため、本スキルでは event_type と payload のみ指定する。

### ステップ7: 結果を報告する

以下を簡潔にユーザーに報告してください:
- 採番した案件ID（3桁）
- 営業管理表に追加した行番号（`ledger.py append` の戻り値 `inserted_row`）
- 作成したフォルダのパス（`{{paths.projects}}/{{paths.project_naming}}/`）
- 設定したステータス
- Slack 通知の有無（投稿先と件数。slack-notify が未稼働ならその旨）

## 注意事項

- **案件IDの正本は Drive のフォルダ名**。`案件ID` 列は結合キーとして同じ値を入れるだけで、採番の根拠にはしない
- フォルダ番号と営業管理表の `案件ID` 列は必ず一致させる。片方だけ作って終わらせない
- ステータスは `リード` / `商談中` / `提案中` / `金額提示済み` / `受注` / `契約済み` / `デリバリー中` / `保留` / `失注` / `終了` の10値のみ。KPIダッシュボードが集計しているので新しい値を作らない
- 行の追加は必ず `ledger.py append` を使う。openpyxl を直書きすると挿入位置とバックアップの作法が抜けて台帳を壊す
- **行は消さない・動かさない。** 1案件1行、リードから失注・終了まで同じ行に残す
- Drive パスは `{{paths.projects}}/`（プロファイルの値を読む。旧称のフォルダ名を決め打ちしない）
