# 目標設定シートの作り方

> **組織固有値はプロファイルから読む。** 本文の `{{company.*}}` などは、連結フォルダ直下の `osi-profile.md` の値に置き換えて解釈する。値をここに直書きしない。

初回商談のあと、お客さまに送る「目標設定シート」（Word）を作る。目的は記録ではなく、
**お客さまに「これをやる」を具体的に見せ、次回の認識合わせ → お申込みにつなげること**。

## 作る順番

1. **議事録を読む**（文字起こし全文）。次を抜き出す。
   - お客さまが自分の言葉で話した課題（例：担当者や部署によって進み方が違う）
   - すでにやっていること（ツール導入・研修・試したこと）
   - これから進みたい方針（人の置き方・順番・育て方）
   - 売上・コストについての関心、具体的な拠点・部署の名前、時期の話
2. **相手先を公式サイトで確かめる。** 社名・代表者名は一字ずつウェブの表記に合わせる。
   規模（拠点数など）と、相手が公表している強み（プレスリリース等）を確認し、出典を控える。
3. **4章で下書きを作る**（下の「構成」）。データを `sheet.json` にまとめ、
   `assets/build-sheet.js` で Word にする（形は `references/sheet-json.md`）。
4. **「先方はどう思うか」を自分で見直す**（下の「出す前の見直し」）。直すべき点は直してから渡す。
5. **送付用の LINE 文面を作る**（下の「送付メッセージ」）。

## 構成（この4章だけ）

表紙は「◯◯株式会社 御中／AIコンシェルジュ／目標設定シート」と、1行の断り書き
「◯月◯日に伺った内容をもとに、弊社の仮説で書いています。一緒に直し、確定版にします。」のみ。
概要表や副題は付けない。

1. **今の課題**：お客さまの言葉に沿って、太字の一文＋箇条書き2〜3行。
2. **現状の対応**：すでにやっていることを箇条書きで。
3. **進みたい方針**：お客さまが話した方針を箇条書きで。
4. **弊社のご提案**：冒頭に軸を一文（例：どの部署でも最後まで進められる人＝担い手を社内に置く）。続けてご提案を3つ程度。
   - ご提案は**どれかを選ばせるものではなく、順につながっていて全部進めるもの**として書く。「案A/B/C」と呼ばず「ご提案1・2・3」。
   - 典型的なつながり：①1部署の業務を最後の実行まで回す → ②担い手を育て、同じやり方で他部署に広げる → ③売上を上げる取り組みを1拠点で回し、他拠点に広げる形を作る。
   - 各ご提案は表にし、行は「目指す姿／できたと言える状態／進め方」を基本とする（必要なら「担い手」「1拠点で試すこと」）。
   - 進め方は、お客さまの実際の業務とツール名で具体に書く（例：ツールを入れる → 経費を渡すと台帳が更新される → 会計ソフトと同期して仕訳まで → 日々の業務で口頭で頼めば進む）。
   - 部署を広げる進め方は「ヒアリングで課題を洗い出す → 議事録から担い手が提案資料を作る → 現場に見せてフィードバック → どう作るかを AI に考えさせ、業務プロセスを書き、システムを作る → 使っていただく → フィードバックを受けて改善し続ける」。
   - 売上のご提案は、題材の拠点を名指しし、毎日の業務（価格調査・掲載・レビューやお問い合わせへの対応・週次の振り返り等）を AI で回す形で書く。
   - 最後に**「ご提案するプラン」を1つだけ**置く（標準プランは `references/plan-catalog.md`。無ければ金額の行を空けて、骨子だけ書く）。行は「金額／毎週やること／この形で進められること／御社にご用意いただくこと／期間と終わり方」。
     - 「この形で進められること」で、プランとご提案1〜3のつながりを書く。
     - 「御社にご用意いただくこと」：担い手を1名以上（インターン可・開始時期は次回伺う）、担い手の時間は週1日程度が目安、使う管理画面へのアクセス。
   - 自社から人を出す形はプランに入れない。プランの後に短く「今回は御社の中に担い手を育てることが中心のため含めていない。必要な場面があればお話を伺ったうえでご検討させてください」と書く。

## 書き方の決まり

- 普通の日本語で書く。カタカナ語・抽象語を避ける。
- **「◯か月目」「◯週目」のような時期の書き方をしない。** 進め方は順番の文で書く（期間はプランの「期間と終わり方」だけ）。
- **箇条書きの頭に「見出し：本文」の太字見出しを付けない。** 主語から始まる普通の文にする。
- 書かないもの：「向いている場合」「残る課題」、根拠のない「確かめる数字」、確かめたい質問の一覧、確認欄。
- 相手の内情の分析・こちらの勝ち筋は書かない。打ち合わせで出た率直な言い方（「◯◯ができていない」等）は、前向きな言い方に直す。
- 相手が公表している得意分野に触れるときは、口出しに見えないよう「**御社がやっているやり方を、AIで毎日・全拠点で回せるようにする**」と書く。
- 相手が使っているツール（会計ソフト等）が確かでないときは「◯◯など」と書き、「お使いのツールに応じて調整します」と添える。
- 約束の大きさを、プランの時間で6か月に届く範囲に合わせる。全拠点への展開などは「6か月の後に担い手が進めること」とする。

## 出す前の見直し

「この資料を出したら先方はどう思うか」を、相手の立場で考えてから渡す。特に次を確かめる。

- 課題の書き方が、相手の言葉と合っているか
- 量と時間が合っているか（盛りすぎに見えないか）
- 相手が用意するもの（人・時間・アクセス）が書いてあるか
- 相手の得意分野に口出ししているように見えないか
- ツール名・社名・拠点名に誤りがないか

## Word の見た目

- `assets/build-sheet.js`（docx-js）で作る。A4・余白20mm・フォント Yu Gothic。
- 章見出しは濃紺（1F3A6E）の太字＋下線。強調は濃紺の太字。薄い色・小さい文字は使わない。
- ご提案とプランは「左に項目・右に中身」の2列の表。見出し行は濃紺地に白字、左の項目列は薄い青（EEF2F8）地に濃紺太字。行は途中で切れない。
- 1〜3章は1ページ目、4章は改ページして各ご提案を1ページずつ。
- 作ったら PDF に変換して画像で全ページを確認してから渡す。

## 送付メッセージ（LINE）

- 「カウンセリング」という言葉は使わない。
- 流れ：お礼と名乗り → シートを作ったので送る（課題・方針を整理し、3つのご提案と進め方のプラン）→「あくまで弊社の仮説ですので、次回、内容へのご意見を伺いつつ、進め方の詳細のご認識合わせをさせていただければと考えています」→「ご認識が合いましたら、◯月からのスタートに向けて、お申込みの手続きまで進められればと考えています」→ 日程候補を伺う（まずその日程で大丈夫かを伺う）→「もしよろしければ」担い手候補の方の同席のお願い → 結び。
- シートのファイルを添付するよう伝える。
