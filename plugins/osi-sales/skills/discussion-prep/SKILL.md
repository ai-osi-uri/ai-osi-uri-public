# 方向性ディスカッション準備スキル（discussion-prep）

自社の提案ループの**入口**は、営業管理表の検索ではなく「経営メンバーとの壁打ち」。
本スキルは、その壁打ちに丸腰で入らないための準備だけを担当する atomic スキル。
**議論そのものは人間がやる。** 本スキルは "弾込め" に徹し、結論は出さない。

ゴール: 壁打ち開始時に、主担当の手元に「過去の自分の判断 ＋ 相手と競合の事実 ＋ 論点3点 ＋ 証拠レベルの叩き台」が揃っている状態。

---

## 設計原則

1. **結論を出さない。** 方向性を決めるのは人間（経営メンバーを含む）。本スキルは選択肢と材料を並べるだけ。
2. **過去の自分を再利用する。** vault に蓄積された判断パターンを毎回引く。ゼロから考えない。
3. **3点に絞る。** 論点は最大3つ。多いと壁打ちが発散する。
4. **速い。** 壁打ちは突発的に始まる。重い分析より、5分で出る要点を優先。

---

## ワークフロー

### ステップ1: 対象と狙いの特定

ユーザー発話から「対象企業」と、分かれば「相談したい論点の種」を拾う。
不足時は1問だけ確認（`AskUserQuestion`）：
- 対象企業（社名 / URL）
- この壁打ちで決めたいこと（例：攻め筋 / 価格感 / どこまで作るか）

### ステップ2: vault から過去の自分を引く（obsidian-knowledge-consult 連携）

`mcp__obsidian__obsidian_simple_search` で vault を検索し、再利用できる思考を引く：

- 同業種・類似構造の過去案件（例：セコム型の「名前で取る」座組み、店舗ドック型のカメラ活用 等）
- 20_Concepts/ にある自分の判断パターン（例：「AIの強みはパクリ放題」「他社比較で差を可視化」）
- 40_People/ に相手や紹介者の情報があれば添える

出典は必ず `[[ノート名]]` 形式。見つからなければ「該当なし」と明示する。

### ステップ3: 相手と競合を Web 調査（軽量）

`WebSearch` / `web_fetch` で要点だけ取る（深掘りは proposal 側の役割）：

- 対象企業の事業・規模・最近の動き
- 直接競合の上位2-3社が「今やっていること」（提案で"パクる"対象）
- 業界の旬・季節性・規制など、攻め筋に効く外部要因

### ステップ4: 論点を3点に絞って出す

壁打ちで話すべきことを、最大3つの問いに整理する。各論点に：
- なぜ今これが論点か（1行）
- 取り得る選択肢（A/B/C を簡潔に）
- vault / 調査から引いた示唆

例（かっぱ寿司の場合）:
1. 攻め筋は「在庫・発注の予測」か「競合(スシロー)の販促パクリ可視化」か、両輪か
2. デモで見せるのは1機能に絞るか、ダッシュボード全体か
3. 入口の課金を月額いくらに置くか（フィクサー連携の座組み前提）

### ステップ5: 証拠レベルの叩き台を添える

proposal-package のゲート①に渡す初期推定。確定ではなく "壁打ちの叩き台"：

| レベル | 見せ方 | この案件での当てはまり |
|---|---|---|
| 1 | 未来像pptxのみ | （該当度を1行で） |
| 2 | pptx＋画面モック | （該当度を1行で） |
| 3 | 実アプリをデプロイ | （該当度を1行で） |

「現時点ではレベルX寄り（理由）」と仮置きし、壁打ちで覆ってよい前提で出す。

### ステップ6: 1枚にまとめて返す

以下の構成で簡潔に提示（資料化は任意、まずはチャットで）：

```
【{企業名} 壁打ち準備メモ】
■ 過去の自分から（vault）: [[…]] …
■ 相手と競合の事実: …
■ 論点3点: 1) … 2) … 3) …
■ 証拠レベルの叩き台: レベルX寄り（理由）
■ 壁打ち後にやること: 方向が決まったら proposal-package へ（proof_levelを引き継ぐ）
```

---

## やらないこと

- 方向性を決める（＝人間の仕事）
- 提案書(pptx)・見積もりの生成（→ initial-proposal / proposal-estimate）
- 客先商談の準備（→ shodan-prep）
- 議事録（→ meeting-minutes）
- 論点を4つ以上出す（発散させない）

---

## 連携

- **前**: 単体起動、または proposal-package ステップ0 から呼ばれる
- **知識源**: obsidian-knowledge-consult（vault）
- **後**: 壁打ちで方向が決まったら proposal-package のゲート①へ、proof_level の叩き台を引き継ぐ
