# meeting-ready-check — 商談準備の確定チェック

> **組織固有値はプロファイルから読む。** 本文の `{{members.*}}` `{{paths.*}}` は、連結フォルダ直下の
> `osi-profile.md`（雛形: `config/osi-profile.example.md`）の値に置き換えて解釈する。

## 目的

営業の責任者（`{{members.owner}}`）が当日その場に出て、**pptx とノートを見ればそのまま喋れる状態**（＝確定）を、
前日の夜までに作る。「作業はしたが、確定したかどうか分からない」状態をなくす。

失敗の型（これを防ぐためにある）：
- 資料もデモもあるのに、誰がどこを話すかが決まっていない
- 成果物がチャットの中にだけあり、あとから探せない
- 責任者が「これでいく」と言う場面がなく、確定の印がどこにもない

## 準備物の形（必ずこの形）

| 準備物 | 中身 | 相手に渡すか |
|---|---|---|
| 相手に見せる pptx | 提案書そのもの。ノートは空 | 渡してよい |
| 話す内容入りの社内用 pptx | 同じスライドの各ノートに、話す内容を入れたもの。ファイル名に「話す内容入り（社内用）」 | **渡さない**（ノートに社内の注意も書くため） |

- **Word や Google ドキュメントの進行メモは作らない。** 話す内容は pptx のノートに入れる。
- 確認完了の基準は **「責任者がその pptx とノートで、そのまま喋れるか」**。
- 当日開くもの（デモアプリの URL など）は、ノートではなく**スライド本体**に入れる（相手にも見せる・押して開ける）。

### ノートの書き方（スライドごと）

```
【経過時間〜 担当者】
（話し言葉の文。責任者がそのまま口に出せる文にする）
――（その場で相手に聞く質問。選択肢・数字・名前で答えられる形）
〔画面操作の合図や、担当の切り替え〕
〔社内メモ：相手に言わないが気をつけること〕
```

- 先頭のスライドで「本日の目的（その場で合意したいこと）」を言い切る。進め方は目的から決める。
- 相手に決めてもらうことは、最後のスライドで質問の形にして、その場で答えを埋められるようにする。
- 相手に見せる版に、こちらの勝ち筋や相手の内情の分析は書かない（ノートの社内メモにだけ書く）。

## 対象

- 責任者が主催していて、相手が社外の予定だけを対象にする（予定名に「様」「さん」、または社外の参加者がいる）。
- 他の担当者が主催する定例は対象外。
- 判定に迷う予定は勝手に入れない。一覧に「対象にしますか？」と添えて聞く。

## 4段階（状態はこの4つだけ）

1. **草案**：AIが資料・デモ・論点の草案を用意した
2. **話す内容**：本日の目的を決め、各スライドのノートに誰が何を話すかを入れた
3. **確認待ち**：責任者の確認・補足を待っている
4. **確定**：責任者が「これでいく」と明示的に了承した

④にしてよいのは、責任者が了承したときだけ。AIが自分で確定にはしない。

## 状態と置き場所

新しい表は作らない。**カレンダーの予定の説明欄の先頭**に、次の形で書く（既存の説明・会議 URL は消さない）。

```
【準備】③確認待ち（M/D 更新）
確認の基準：「pptx＋ノート（話す内容）」で、そのまま喋れるか
置き場：<案件フォルダの日付フォルダへのリンク>
・<相手に見せる版のファイル名>
・<話す内容入り（社内用）のファイル名>
アプリ：<デモの URL（あれば）>
```

- 成果物は必ず `{{paths.projects}}` の案件フォルダの `01_提案・見積/YYYYMMDD/` に置く。チャットの中だけに置かない。
- Drive のコネクタで送れない大きさのファイルは、手元の同期フォルダ（device の道具）に書き込む。書き込めないときは、そのことを報告に書く。
- 社外の参加者が招待されている予定は、説明欄を変えると相手に通知が飛ぶ。変えずに報告だけする。
  社内の人だけの予定でも、更新するときは通知を出さない設定にする。

## 手順

1. 翌日（指定があればその日）のカレンダーを読み、「対象」に当てはまる予定を拾う。
2. 予定ごとに今の段階を調べる（説明欄の【準備】行、過去のチャット、案件フォルダの日付フォルダ）。
3. 足りない段階を進める。
   - 草案が無い → 議事録・前回のやりとりから、自社の営業スキル（proposal-package 等）の手順で pptx の草案を作る。
   - ノートが無い → 本日の目的を決め、上の「ノートの書き方」で各スライドのノートを書き、社内用 pptx を作る。
   - 確認待ち → 責任者に見せるのは**相手に出す完成物そのもの**（2つの pptx）。項目に分けた素材にしない。
     補足・修正をもらったら反映し、両方の pptx を作り直して置き直す。
4. 説明欄の【準備】行を更新する。
5. 一覧を返す。④確定以外を目立たせる。

```
明日の商談準備
・15:00 ○○様　③確認待ち — 見てほしいもの：話す内容入り（社内用）pptx
・11:00 ○○さん　①草案のみ — 話す内容が未定
・判定に迷った予定：○○（対象にしますか？）
```

## 毎晩の点検

- 予定タスク（日曜〜木曜の夜）で、翌日分に上の手順を実行する。
- 予定タスクの指示文には「このスキルを読み込んで従う」とだけ書き、決まりはこのスキル側に持つ（決まりを二か所に書かない）。
- メールや LINE は送らない。

## やってはいけないこと

- 責任者の了承なしに④確定にする
- 話す内容を Word・Google ドキュメントの別ファイルにする（pptx のノートに入れる）
- 社内用 pptx（ノート入り）を相手に送る・共有する
- 成果物をチャットの中だけに置く
- 社外の参加者がいる予定の説明欄を書き換えて、相手に通知を飛ばす
