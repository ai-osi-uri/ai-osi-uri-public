# minutes.json スキーマ仕様

`scripts/build_minutes.py` が読む minutes.json の完全な仕様。
`assets/example-minutes.json` がそのまま動くので、まずは複製して書き換えるのが速い。

## トップレベル

| キー | 型 | 必須 | 説明 |
|---|---|---|---|
| `meta` | object | yes | 議事録のメタ情報 |
| `summary` | array | yes | サマリ（3-5 項目） |
| `next_actions` | array | yes | 次アクション（TODO + 期限 + 担当） |
| `quotes` | array | yes | 相手の重要発言（原文引用） |
| `status_hint` | array/string | no | 案件ステータスへの示唆 |
| `notes` | array/string | no | 補足メモ |

## meta

```json
"meta": {
  "company_name": "サンプル株式会社",
  "date": "2026-05-06",
  "attendees": ["先方：山田部長・佐藤課長", "弊社：自社担当"],
  "location": "オンライン (Google Meet)",
  "topic": "AI 活用による営業 DX 提案・初回ヒアリング"
}
```

| キー | 必須 | 用途 |
|---|---|---|
| `company_name` | yes | 議事録タイトルの一部 + フッター |
| `date` | yes | 副題に表示 (YYYY-MM-DD) |
| `attendees` | no | 出席者の配列 |
| `location` | no | 場所（オンライン/オンサイト等） |
| `topic` | no | 議題（タイトル直下に表示） |

## summary（必須）

```json
"summary": [
  "先方の最大の課題は『営業ノウハウの属人化』",
  "yourrecord 導入には強い興味",
  "次回は 2 週間後、見積もりを持参して再訪問"
]
```

文字列の配列。3-5 件推奨。
時系列ではなく **重要度順**で書く。

## next_actions（必須）

```json
"next_actions": [
  {"todo": "見積もり提案書を作成", "due": "2026-05-13", "owner": "自社担当"},
  {"todo": "次回打ち合わせ日程の確定", "due": "2026-05-08", "owner": "山田部長"}
]
```

| キー | 必須 | 用途 |
|---|---|---|
| `todo` | yes | やること（具体的に） |
| `due` | no | 期限（YYYY-MM-DD or 自由文字列） |
| `owner` | no | 担当（人名 or 会社名） |

省略時は表セルに「—」が入る。

## quotes（必須）

```json
"quotes": [
  {"text": "うちは 30 年の営業ノウハウが定年退職で消えていく", "source": "山田部長"},
  {"text": "金額は妥当。問題は社内をどう説得するか", "source": "山田部長"}
]
```

または単純な文字列の配列でも可：

```json
"quotes": [
  "うちは 30 年の営業ノウハウが定年退職で消えていく",
  "金額は妥当"
]
```

| キー | 必須 | 用途 |
|---|---|---|
| `text` | yes | 発言内容（原文引用） |
| `source` | no | 発言者（"── ○○" として右寄せで表示） |

3-5 件推奨。多すぎると埋もれる。

## status_hint（任意）

```json
"status_hint": [
  "`ステータス` 列を「商談中」→「金額提示済み」へ進める提案"
]
```

文字列の配列、または単純な文字列。
SKILL.md の Step 8（営業管理表のステータス更新提案）の判断材料になる。
ステータスは `リード` / `商談中` / `提案中` / `金額提示済み` / `受注` / `契約済み` / `デリバリー中` / `保留` / `失注` / `終了` の10値のみ。

## notes（任意）

```json
"notes": [
  "セキュリティ懸念は競合 A 社も同じく直面している",
  "山田部長は意思決定権者。次回も両者参加が必須"
]
```

文字列の配列、または単純な文字列。
サマリに入れるほど重要ではないが、後で参照したい補足情報を入れる。

---

## 出力 docx の構造

スクリプトが生成する docx は以下の順で組み立てられる：

1. タイトル: `{company_name} 商談議事録`
2. 副題: 日付 | 出席 | 場所
3. 議題（meta.topic がある場合）
4. **サマリ** セクション（箇条書き）
5. **次アクション** セクション（3 列の表）
6. **相手の重要発言** セクション（引用ブロック）
7. **案件ステータスへの示唆** セクション（任意）
8. **補足メモ** セクション（任意）
9. フッター

セクションヘッダは赤色（CAIO アクセントレッド）。
本文は游ゴシックで日本語が綺麗に出る。
