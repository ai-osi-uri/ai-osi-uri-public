# 議事録から営業状況を判断して書く（meeting-minutes Step 3・Step 8 の正本）

議事録を読んだ AI が、その商談で「営業状況がどう動いたか」を判断し、営業管理表の行に書く内容を作る。
人は**書く内容を見て OK を出すだけ**にする（見せずに書かない・人に一から書かせない）。

会社ごとの具体（列名・ステータス値・失注理由の選択肢・正本の置き場）は、この文書には書かない。
`{{ledgers.sales_rules}}`（営業管理表の運用ルール）と `ledger.py columns` の戻り値が正。
運用ルールに段階ごとの「書く列」があれば、下の表よりそちらを優先する。

---

## 1. 正本を確かめる（最初に1回）

- 運用ルールに「正本は○○（DB など）。xlsx は書き出し」とあれば、**正本に書く**。書き出しの xlsx は触らない（直しても反映されず、次の書き出しで消える）
- 正本への書き方は運用ルールに従う（専用の道具・SQL・秘書への依頼文など）。分からなければ書かずに、作った内容を報告して人に聞く
- 書いた人・経路を残せる正本なら残す（例：書いた人＝依頼した本人、経路＝`議事録（Claude）`）。変更の履歴・通知は正本側の仕組みに任せる

## 2. 段階を判断する

議事録の**明確な発言・合意**だけを根拠にする。雰囲気・推測では動かさない。

| 議事録で起きたこと | ステータス（既定値の場合） | 一緒に埋める列 |
|---|---|---|
| 商談の日程が決まった | `リード` → `商談中` | 次アクション（商談）・期日（商談日）・窓口氏名 |
| 商談をした（進展はまだ） | 変えない | 最終接触日・確度・次アクション・期日・顧客課題メモ |
| 提案書を出した・説明した | → `提案中` | 提案書のリンク・次アクション・期日 |
| 金額を出した | → `金額提示済み` | 想定額（運用ルールの形：月額か総額か、税込か税別か）・課金形態・想定開始月・想定期間・確度 |
| 「お願いします」「進めてください」と言われた | → `受注` | 窓口氏名・窓口メール（契約書の送り先）・最終的に合意した金額と期間・次アクション（契約手続きへの引き渡し）・期日（翌営業日） |
| 返事待ちで止まった・先方都合で時期がずれた | → `保留` | 保留日・保留理由（選択肢から）・再アプローチ月。次アクションと期日は空にする |
| 断られた・他社に決まった | → `失注` | 失注日・失注理由（選択肢から）・再アプローチ月（望みがあれば）・顧客課題メモに負けた理由1行 |

- **進んだ方向にだけ動かす。** 巻き戻すのは、議事録にはっきりした発言があるときだけ
- `受注` のように**後ろの工程（契約書づくり・通知）が動き出す値**は、確認の画面で必ずそのことを一言添える
- 値は台帳の選択肢（ステータス・確度・理由）だけ。増やさない
- 金額・日付は議事録に出た数字をそのまま使う。計算が要るもの（税込にする等）は計算した旨を確認画面に書く

## 3. 次アクションと期日を作る

- 次アクションは「**誰が・何をするか**」を一文で。これを読んだ他人が代われる書き方にする
  - ✗ `先方確認待ち` → ○ `11/5までに返事がなければ電話する`
- 長文の経緯を次アクションに書かない（経緯は議事録 docx。台帳は状態だけ）
- 期日は必ず入れる。議事録に無ければ「次の打ち合わせ日」か「1週間後」
- 自社の次アクションが複数あれば、案件が前に進むものを1つ選ぶ（残りは議事録 docx の次アクションに残る）

## 4. 見せ方（Step 8 の確認）

変わる列だけを「列｜いま｜こう書く」の表で見せ、根拠になった発言を1行ずつ添える。

```
営業管理表（案件ID 123）にこう書きます：
| 列 | いま | こう書く |
|---|---|---|
| ステータス | 商談中 | 受注 ← 「この内容で進めてください」 |
| 想定額 | （空） | 月額 ○○円（税込）← 月○○円（税別）で合意。税込に計算 |
| 次アクション | （長文） | 契約書を窓口の方へ送る |
| 次アクション期日 | 10/26 | 10/27 |
※ 受注にすると、契約書づくりの担当に知らせが届きます
```

- 選択肢は「この内容で書く／直して書く／ステータスは変えず他だけ書く／書かない」
- 直しが来たら直した表をもう一度見せてから書く
- 最終接触日・議事録リンク・顧客課題メモの1行（Step 7・7.5）は確認なしでよい。それ以外はこの確認を通す
