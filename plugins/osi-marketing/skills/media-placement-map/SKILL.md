# 掲載先マップ／陣取り調査（洗い出し → 陣取り採取 → 空白ポジション）

「誰に送るか」を作るのが `outreach-list-build`。**「どこに載るか」を作るのがこのスキル。**

このスキルの価値は掲載先リストそのものではない。**「その枠で今、何が売られているか」を採ること**にある。
リストだけなら検索で出る。勝ち筋が見えるのは、上位5枠の訴求軸を原文で採り、占有マップに落としたときだけ。

## 全体の型

```
Stage0 製品理解 → Stage1 掲載先の洗い出し(3類型) → Stage2 掲載条件の一次確認
      → Stage3 陣取り採取(現1〜5位＋訴求軸) → Stage4 占有マップ／空白ポジション → Stage5 納品
```

Stage1〜3 は独立に並列化できる。サブエージェントを類型ごとに分けて同時に走らせること（1エージェント＝1類型が最も安定する）。

---

## Stage 0 — 製品理解（訴求資産の棚卸し）

受け付ける入力：製品/サービスの **URL**／紹介 **pptx・pdf**／1枚もの **docx・md・txt**／**チャットの数行**。
URLは WebFetch、資料は各抽出で読み、1つの製品理解に統合する。

抜き出すのは **訴求資産**（＝掲載先で並べられたときに戦える材料）。最低限これだけ確定させる：

| 項目 | 例（注文住宅ビルダーの場合） |
|---|---|
| 商品ライン | 平屋／2階建て |
| 定量スペック | 耐震等級3、HEAT20 G2、UA値、C値、保証60年 |
| 事業形態 | 全国FC（本部＋加盟店）／直営／地域限定 |
| 価格帯 | 坪単価・総額レンジ |
| ターゲット | 子育て世代のファミリー層 |

**事業形態は必ず採る。** 多店舗・FC・代理店・支店を持つ場合、後段で「本部名義」と「拠点名義」の**二重露出**が可能かを見るため。

不明な項目は「不明」のまま進める。ここで質問攻めにしない（最大1問）。

## Stage 1 — 掲載先の洗い出し（3類型で切る）

**業種を問わず、掲載先はこの3類型に分かれる。** 混ぜて一覧にすると、攻め方が違うものが同じ表に並んで判断を誤る。
類型ごとの見分け方・探し方は `references/media-taxonomy.md` を読むこと。

| 類型 | 実態 | 攻め方 |
|---|---|---|
| **A. 一括資料請求ポータル** | 加盟して反響を買う。反響課金＝初期費用ゼロが多い | 商談して加盟 |
| **B. 特化型比較メディア** | テーマを絞った枠を買う。運営が数社に集約されていることが多い | 枠を買う |
| **C. 記事型ランキング** | 多くはアフィリエイト送客型。**直接は買えない** | Aに加盟して間接露出を取る |

さらに、業界固有の第4類型がある場合は足す（例：FC本部なら「加盟店募集メディア」、BtoBなら「業界団体の会員一覧」「媒体資料DBのメディアレーダー等」）。

**必ず生死を確認する。** 比較記事に載っている媒体が、実際には閉鎖・ドメイン失効していることが頻繁にある。
WebFetch で実際に開き、閉鎖告知・売却ページ・404 を確認したものは「閉鎖」「ドメイン失効」と明記して候補から外す。
二次情報（キュレーション記事）だけを根拠に一覧へ載せない。

## Stage 2 — 掲載条件の一次確認

各サイトについて、**公式の法人向けページ・掲載案内ページ**（＝一次情報）で以下を確認する。

- 運営会社（社名変更・運営移管が起きているので必ず現在の社名を採る）
- 規模感（月間PV/UU、提携社数、継続率）
- 掲載対象（全国／エリア限定、本部として掲載可か）
- **料金体系**：掲載課金（月額固定）／反響課金／成約課金／完全無料 — と、分かる範囲の金額
- 審査の有無と基準
- 掲載申込／法人向けページの **URL**

**料金は公式非公開のことが多い。** その場合「非公開」と書き、推測で金額を埋めない。
実額を比較したいなら、同類型の複数社に**同条件（対象エリア・想定反響数）で同時に見積依頼**をかけるのが最短だと提案する。

## Stage 3 — 陣取り採取（このスキルの中核）

各サイトを **実際に WebFetch で取得して**、現在の1〜5位を採る。検索スニペットや記憶で書かない。

### 採る列（1行1レコードの縦持ちで統一する）

```
分類 / サイト / ランキング名 / 順位 / 会社名 / 事業形態区分 /
その枠で売られているもの（訴求軸・原文に近い形） / 価格 / スコア・保証等 /
集計根拠 / PR表記 / 出典URL
```

サイトごとに表を分けてはいけない。**縦持ちにしないと横断集計ができない**（Stage4 で効く）。

### 「集計根拠」は必須列

**同じ「1位」でも意味がまったく違う。** これを採らないと表が誤読を生む。実際に観測される根拠：

アクセス数／受注棟数／年間着工数／カタログ請求数／資料請求数／実利用者アンケート／
編集部の独自採点／月間検索数（＝広告出稿量の写像）／五十音順（＝そもそも順位ではない）／掲載プラン依存

集計根拠が **記載なし** のメディアは、そう明記する。それ自体が「信用できない」という情報になる。

### 「その枠で売られているもの」は原文に近い形で採る

会社名だけ採っても意味がない。**その会社に付いているキャッチコピー・推し文句を原文で採る**。
これが後段の占有マップの素材になる。定量スペック（坪単価・UA値・C値・保証年数・実績数）が併記されていれば必ず拾う。

### 攻略可能性の判定

採取しながら、各ランキングに **「順位が動かせるか」** の判定を付ける。分岐は1つだけ：

- **集計式が公開されているか。** 公開されていて、かつ自分で増やせる変数（掲載事例数・更新頻度・反響数）が式に入っていれば **攻略可能**。
- 知名度・棟数・売上規模だけで決まるなら **攻略不能**（＝金を積んでも順位は動かない。買えるのは枠だけ）。

これが打ち手の優先順位を決める。攻略可能なランキングが1つでもあれば、そこが最優先になる。

### 取得できないもの

WAF・robots・403 でブロックされるサイトが必ず出る。**「取得不可」と明記して未収録扱い**にする。
古い第三者記事から拾った数字を現在値として載せない（載せる場合は「未確認・◯年◯月時点」と必ず併記）。

## Stage 4 — 占有マップと空白ポジション

### 占有マップ

訴求軸ごとに「誰が押さえているか・占有度・こちらの勝機」を並べる。軸は採取した原文キャッチから帰納する（先に軸を決めない）。
占有度は3段階で十分：**完全占有／2社で分割／空洞**。

### 空白ポジションの見つけ方

空白は「誰も言っていないこと」を想像するのではなく、**クロスの穴**として機械的に見つかる。

1. **軸 × メディアのクロス表を作る**。行＝訴求軸、列＝メディア。
2. **片方しか語っていない交差点**を探す。
   例：「平屋を語るメディアは性能数値を持たず、性能数値を持つメディアは平屋を語らない」
   → **平屋 × 性能数値** が空白。両方を持つ製品なら、そこが一人勝ちできる文脈。
3. **カテゴリはあるのに中身が空**を探す。
   例：「『保証が充実した工務店』カテゴリがあるのに、掲載社の誰も保証年数を掲げていない」
   → メディア側が枠を用意しているのに埋まっていない＝最も入りやすい空白。
4. **運営が空きを自認しているか**を見る。「掲載エリアを順次追加していく」「◯◯を募集中」は明示的な空き宣言。

### 逆に「取りに行っても勝てない軸」も必ず出す

空白だけ出すのは片手落ち。**正面から取りに行っても負ける軸**を同じ重さで書く。判定基準：

- **完全占有軸**：全ソースで例外なく同じ社が押さえている → 正面突破しない
- **コモディティ化した認証・等級**：上位が全員持っている → それだけ掲げるのは何も言っていないのと同じ。
  一段深い固有名詞（計算手法・独自工法名・実測値）まで踏み込めるかが分岐
- **数値の絶対値勝負**：自社の値が上位相場の中位以下なら回避。別の切り口（実測平均・全棟悉皆性・効用への翻訳）に逃がす

### 単一の差別化ワード

**ポータルの枠は「一言のキャッチコピー＋価格帯」しか売れない。**
これが決まっていないと、どこに出しても埋もれる。占有マップから、既存プレイヤーとぶつからない
**単一の物理的差別化ワード**（モノ・数値・仕組みで言えるもの）の候補を3つ出し、決めるのは人に委ねる。

## Stage 5 — 納品

**2形態で出す。**

1. **Excel（一覧性・二次利用）** — `xlsx` スキルを読んでから作る。8シート構成と列定義は `references/output-schema.md`。
   集計シートは **COUNTIFS の数式で書く**（Pythonで計算した値を貼らない）。縦持ちの陣取りシートを直せば集計が自動追随する。
2. **HTML アーティファクト（読ませる・共有する）** — 結論と根拠を1枚で。再訪する種類の成果物なので永続アーティファクト化する。

Excel だけだと読まれず、HTML だけだと二次利用できない。両方出す。

納品時に必ず添える3点：
- **取得日**（ランキングは月次・週次で動く。SUUMO型は月次、アクセス型は週次）
- **取得できなかったサイト**の明示
- **前回資料からの訂正**（閉鎖・ドメイン失効・運営会社の変更を見つけたら必ず先頭で言う）

## 安全原則（必ず守る）

**景表法ステマ規制。規制対象になるのはメディアではなく広告主側。**
消費者庁の運用基準はアフィリエイト・比較サイトを名指しで例示しており、
「金は払ったが順位には口出ししていない」は免責にならない。制裁は措置命令（企業名公表）、
優良誤認を伴えば課徴金。詳細と条文の当たり方は `references/stealth-marketing-guard.md`。

- **PR表記なしでの有償上位掲載は提案しない。** 先方から持ちかけられても断るよう明記する。
- 「一般社団法人」など中立を装う名義のサイトへの有償掲載は、判別困難性が強い分だけ悪質と評価されやすい。特に警告する。
- 買ってよいのは **PR表記の運用が明文化されている枠** だけ。

**事実の扱い。**
- 一次情報（公式の法人向けページ）を根拠にする。二次情報しかない項目は「二次情報」と明記する。
- 不明な項目は「不明」と書く。推測で埋めない。
- 全レコードに出典URLを付ける。

## やらないこと（境界）

- 掲載の申込・契約の代行（窓口URLと条件までを出す。申込は人）
- ターゲット企業リストの作成（`outreach-list-build` の役割）
- フォーム営業の送信（`form-outreach-autopilot` の役割）
- 提案書への清書（`osi-sales:proposal-package` / `osi-docs:deck-composition` へ渡す）

## 連携

- 前工程：製品理解の材料が薄い場合は LP・紹介資料を先に用意してもらう
- 事実の裏取り：`osi-core:research-verifier`（納品前に主張単位で再検証したいとき）
- 後工程：クライアント提示なら `osi-sales:proposal-self-review` を必ず通す
- 出力：`xlsx`（Excel）／永続HTMLアーティファクト
