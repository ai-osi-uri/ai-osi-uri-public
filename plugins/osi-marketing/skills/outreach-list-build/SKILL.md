# アウトバウンド・リストビルド（収集 → レビュー → 台帳化）

自社製品の情報を起点に、送る相手のリストを作る。osi-marketing の入口。
「収集(名前を集める)」はこのスキル、「送信」は form-outreach、「URL到達/修復」は probe とURL自動修復ループを流用する。

## 全体の型
```
Stage0 投げる → Stage1 収集ブリーフ確認 → Stage2 収集 → Stage3 1回レビュー → Stage4 補完→台帳
```

## Stage 0 — 起動（まず「資料/情報」を受け取る）
**最初にターゲット業種を聞かない。** まず自社を説明できるものを受け取り、それを読んでから ICP を提案する。
- まず促すのは**製品/サービスの情報**: **URL** ／ 紹介 **pptx・pdf** ／ 1枚もの **docx・md・txt** ／ **チャットの数行**（複数可・順不同）。
  - URLは web_fetch、pptx/pdf/docx は各抽出で読み、**1つの製品理解（価値＝何を売るか）に統合**する。
- 資料が来る前に「誰に送る？」と聞かない。資料から**ICP（誰に効くか）を推定**し、Stage 1 で提案して確認を取る。
- ユーザーが最初から狙い（業種・件数）を書いてきたら、それを優先して取り込む（無理に聞き直さない）。
- 資料が本当に何も無い場合に限り、製品を1〜3行で説明してもらう（それでも業種の当てはこちらが提案する）。

## Stage 1 — ICP/収集ブリーフの提案 → 確認
**投入物から ICP を推定して、こちらから提案する**（ユーザーに業種を考えさせない）:
対象業種（＝資料の価値が刺さる相手）／地域／規模／含めるキーワード／除外／件数、そして「**なぜこの業種か（製品価値との紐付け）**」を根拠付きで提示。
- 商材とズレる候補業種があれば、相性(高/中/低)を添えて正直に示す。
- ユーザーは自然文で微調整（「その業種でOK」「地方も入れて」「50社でいい」「別業種も見たい」）。
- 件数・地域など運用条件だけ不明なら、そこだけ確認（業種はこちらの提案ベース）。確定したら campaign.json の `target` に落とす。

## Stage 2 — 収集
業種ごとに効く**種ソース**を当て、WebSearch と併用して候補を列挙する。各社に**一致理由・出典URL**を必ず付ける。
- 例（広報/PR会社）: 業界団体の会員一覧（例: 日本パブリックリレーションズ協会）／PR会社の比較・ランキング記事／会社データベース。
- 例（広告代理店）: 運用型広告代理店の比較記事／各社の実績・支援領域ページ。
- 同名別会社に注意（出典で**業態一致**を確認）。企業の公開情報のみ（個人情報は集めない）。
- 名寄せ・重複排除（株式会社/(株)/全半角/英表記ゆれ、ドメイン一致）。
- 出力: `campaigns/<campaign>/candidates.csv`（ヘッダ `会社名,公式URL`。公式URLは分かる範囲で、不明は空でよい）。

## Stage 3 — 1回レビュー（ユーザーの直し方は3通り用意）
「会社名／業態一言／一致理由／出典/確信度」を**表またはライブ・アーティファクト**で提示し、次の3通りで直せるようにする:
1. **自然文の一括操作**: 「上場企業は除く」「BtoC寄りは外して」「IT系PRに絞って」「あと30社足して」
2. **名指し／番号**: 「3・7・12は違うので削除」
3. **直接編集**: ドラフトCSV/シートを触って再アップ
差分を反映して再提示 → 「これで確定」でロック。確信度が低い/出典が弱いものは残さず要確認に。

## Stage 4 — 補完 → 台帳ドラフト
確定した `candidates.csv` を `campaigns/<campaign>/` に置き、ツールで補完する:
```bash
cd form-outreach-runner
npm run list-build -- --forms --limit 50   # 公式URL到達＋問い合わせフォームURL解決（送信なし）
```
→ `campaigns/<campaign>/list-build-draft.csv`（No・会社名・公式URL・実フォームURL・到達・メモ）。
公式URLが「到達不可」の社は **URL自動修復ループ**（probe→WebSearchで正URL特定→到達確認→承認）で直す。
人が最終レビュー（誤ヒット・重複・除外）してから、送信台帳（企業リスト）に取り込む → 以降は form-outreach へ。

## やらないこと（境界）
- 送信そのもの（form-outreach の役割）、台帳の無断確定（人の承認）、個人情報の収集。
- 憶測でのURL/社名の埋め（確信が持てないものは「要確認」にする）。

## 連携
- 設定づくり: `campaign-setup`（campaign.json の sender/target/message を対話で作る）
- 送信: `form-outreach`（autopilot・AI完了判定・要メール送付・二重送信防止）
- URL到達/修復: ツールの `probe` ＋ URL自動修復ループ
