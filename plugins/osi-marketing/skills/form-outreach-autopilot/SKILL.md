# フォーム営業オートパイロット

Webフォームへの営業送信を、`form-outreach-runner` を軸に自走させる。
これまで人が手でやっていた「実行→ターミナルを読む→ブラウザ調査→原因診断→修正→再実行」のループを、
このスキルが代行する。

## 場所・前提

**このスキルは案件固有の値を持たない。すべてキャンペーン設定から読む。**

- ツール: 案件の作業ディレクトリにある `form-outreach-runner/`（bashで `cd` して `npm run …`）
- キャンペーン設定: `campaigns/<campaign>/campaign.json`
  - 送信者情報・件名テンプレ・ターゲット条件・**台帳のパス／シート名／列マッピング**はここにある
  - 本文テンプレは `campaigns/<campaign>/message.txt`
  - 切り替えは `--campaign <name>` フラグ、または `CAMPAIGN` 環境変数
- AI判定を使うため `.env` に `ANTHROPIC_API_KEY` が必要（`.env` はリポジトリに含めない）

**最初にやること**: どのキャンペーンを回すかを確認し、`campaigns/<campaign>/campaign.json` を読んで
台帳のパスと列マッピングを把握する。ここを推測で埋めない。

## 絶対に守る安全原則（自動化しても不変）

1. **二重送信しない**: `run`/`autopilot` は「未処理」だけ送る。`成功`・`不確定`・`除外`・`ブロック`・`要メール送付` は触らない。
   `不確定`（送信済/未確認）は**絶対に自動再送しない**。
2. **CAPTCHAは突破しない**。`ブロック`は確定させ、メール送付側へ。
3. **営業お断りは尊重**して `除外`。
4. **台帳（マスタ）の書き換えは承認制**。URL修正・除外化は、対応表を提示して人の承認を得てから反映する
   （承認済み分だけ書き込む。誤って別会社に送らないため）。

## 手順

### Step 1. 送信ループを回す（自走の本体）
```bash
cd <案件ディレクトリ>/form-outreach-runner && npm run autopilot -- --campaign <name>
```
`autopilot` = reset（要手動/エラーのみ未処理へ）→ run（未処理を送信・AI完了判定込み）→ report → emaillist →
「残り要対応」内訳、を1コマンドで実行する。まずこれを回す。

### Step 2. 公式URLの棚卸し（死/誤りの確定）
```bash
npm run probe -- --campaign <name>
```
2回連続で到達不可のものが `url-audit.csv` に出る。これが「URL調査が要る会社」。

### Step 3. URL自動修復（Web検索→検証→承認→反映）
`url-audit.csv` の各社について、**1社ずつ**次を行う:

1. **WebSearch** で会社名を検索し、現行の公式HPを特定する。
   **同名の別業種・別会社に注意**（業種が違えば別法人であることが多い）。
2. 候補URLの**到達確認**: Claude in Chrome で `navigate` して `chrome-error` でないこと、
   または読み込み済みページから `fetch(url,{mode:'no-cors'})` が例外を投げないことを確認。
3. **会社同一性**を、所在地・事業内容で確認。確信が持てなければ「不明/確信度低」にする。
4. 結果を**対応表**（No・会社名・旧URL・正URL・到達・確信度・備考）にまとめて人に提示。
5. **承認された分だけ**台帳に反映。反映後は未処理に戻して次回送信対象にする。
   廃業・サイト消失は `除外`＋メモ。到達不可のままなら台帳は変えず保留。

台帳反映（exceljs, runnerディレクトリで実行）:
```js
// node -e で実行。台帳パス・列番号は campaign.json の ledger から取る（ハードコードしない）。
// ROW = No + 1（ヘッダ1行）。書き込み前に No 一致を必ず確認。
const ExcelJS = require('exceljs');
const camp = require('./campaigns/<name>/campaign.json');
const path = camp.ledger.path;
const col  = camp.ledger.columns;   // { no, company, officialUrl, result, sentAt, formUrl, memo }
```

対応表は案件側のドキュメントに追記していく（＝学習知識として蓄積）。

### Step 4. 修復分を送信
URL修正で未処理に戻した会社を送る:
```bash
npm run autopilot -- --campaign <name>
```

### Step 5. 「人が要る残り」を提示して終了
最終 `report` と、次の内訳を短く返す:

- `要手動`（フォーム難）: 実サイトを見て個別対応が要る少数
- `ブロック`（CAPTCHA）: メール送付側へ
- `要メール送付`: `email-queue.csv`（別プロセスでメール）
- `除外`: 対象外
- `不確定`: 送信済/未確認（**再送しない**。減らしたい場合は次回送信分から AI完了判定で減る）

## スケジュール運用（任意）

毎晩 Step1（＋余力で Step2-4）を回すよう scheduled-task を登録すると、日を跨いで失敗を自動で削り込める。
朝に「昨夜の成果＋人が要る残り」を報告する形にする。URL修正の台帳反映だけは承認制のため、
夜間は「対応表を作るところまで」にして、朝に人が承認→反映、が安全。

## 学習知識の蓄積（コード改修を減らす）

新しく解けたパターンは、コードでなくデータに残す:

- 社名→正URL の対応: 案件側の対応表ドキュメントに追記
- 新しい完了文言・項目ラベル・埋め込みサービスの癖に**繰り返し**当たる場合のみ、
  ツールの辞書（`config.ts` の FIELD_DICT / `interact.ts` の完了文言）に追記を提案する
  （エンジン本体の改修は頻度を最小に）

## やらないこと

- CAPTCHA突破、営業お断りへの送信、`不確定`の自動再送、台帳の無断書き換え。
- 送信そのものの新規実装（それは form-outreach-runner の役割）。本スキルは「回す・直す・切り分ける」オーケストレーション。
- **案件固有値のスキル内へのハードコード**（台帳の実ファイル名・クライアント名・送信者情報は campaign.json 側）。
