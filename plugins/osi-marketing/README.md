# osi-marketing

顧客理解と商品設計から、獲得ファネル、教育施策、ターゲット企業リスト作成、フォームアウトリーチまでを一気通貫で扱う。

## スキル一覧

- `persona-design` — 根拠付きペルソナとカスタマージャーニーを設計
- `product-concept` — 顧客課題から商品コンセプトと検証計画を設計
- `funnel-design` — 認知から継続・推奨までの導線とKPIを設計
- `webinar-plan` — ウェビナーの企画、台本、集客、フォローを設計
- `course-outline` — 学習成果から講座・研修カリキュラムを設計
- `outreach-list-build` — 自社製品の情報を起点にターゲット企業リストを作る（収集フロント）
- `form-outreach-autopilot` — フォーム営業を自走させるオーケストレータ（実行 → 失敗分類 → URL修復 → 再実行 → 残り提示）
- `media-placement-map` — 掲載先メディアの棚卸しと陣取り調査（3類型で洗い出し → 各ランキングの現1〜5位と訴求軸を実取得 → 占有マップ・空白ポジション → Excel＋HTML）

## 設計思想：キャンペーン設定駆動（client-agnostic）

案件固有の値（クライアント・商材・送信者・文面・ターゲット条件・台帳の場所）は、すべて**キャンペーン設定に外出し**する。
スキルもコードも「設定を読んで動く」だけにし、**次の案件は設定を差し替えるだけ**で回る。

```
form-outreach-runner/
└─ campaigns/
   ├─ <campaign-a>/
   │   ├─ campaign.json     # 送信者・件名・ターゲット条件・台帳の列マッピング
   │   ├─ message.txt       # 本文テンプレ（{{company}} 等を差し込み）
   │   └─ candidates.csv    # リストビルドの出力
   └─ <campaign-b>/
```

切り替えは `--campaign <name>` フラグ、または `CAMPAIGN` 環境変数。

> **この設計により、実行エンジン（form-outreach-runner）およびスキルには、特定クライアントの情報を持たせない。**
> 顧客名・台帳の実ファイル名・送信者の個人情報は、リポジトリではなく各案件の作業ディレクトリ側の `campaigns/` に置くこと。

## パイプライン

```
① リスト生成 ──→ ② 送信 ──────→ ③ 追跡・レポート
 (list-build)   (form-outreach)    (report)
      └────── 共通の台帳スキーマで受け渡し ──────┘
```

## 安全原則（全キャンペーン共通・変更不可）

1. **二重送信しない** — 送信対象は「未処理」のみ。`成功` / `不確定` / `除外` / `ブロック` は触らない。
   とくに `不確定`（送信済・未確認）は**絶対に自動再送しない**。
2. **CAPTCHA は突破しない** — 検出したら `ブロック` として確定し、メール送付側へ回す。
3. **営業お断りは尊重する** — 明記されているフォームは自動検出して `除外`。
4. **台帳（マスタ）の書き換えは承認制** — URL修正・除外化は対応表を提示し、人の承認を得てから反映する。
5. **送信元は正直に明記し、オプトアウト文を必ず入れる。**
6. **実行主体は人** — 無人で回し続けず、承認ゲート＋監督付きで運用する。

## 状態機械

送信結果は6状態で管理する。この分類が改善の羅針盤になる。

| 状態 | 定義 |
|---|---|
| 成功 | 完了UIを検知（完了文言／thanksページ遷移／多段完了ステップ） |
| 不確定 | 送信後に応答なし・タイムアウト。**自動再送しない** |
| エラー | バリデーション差し戻し。多くは入力実装の問題で解消可能 |
| 要手動 | iframe/埋め込みでDOM操作不可、送信元要件未達 |
| ブロック | CAPTCHA・ログイン要求。**突破しない** |
| 除外 | 営業お断り明記／除外リスト該当 |

到達率は「**確実成功**」と「**実質到達（成功＋不確定）**」の2本立てで管理する。

## 実行エンジン

送信の実体は `form-outreach-runner`（Playwright + AI フォーム判定）。
エンジンは各案件の作業ディレクトリに配置し、本プラグインのスキルがそれをオーケストレーションする。

## 関連
